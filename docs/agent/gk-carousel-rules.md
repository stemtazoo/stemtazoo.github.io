# GK Instagram Carousel Rules

このファイルは、G検定対策ブログの記事内容からInstagram用カルーセルを制作するときに使用する。

更新日: 2026-08-14

## 目的

G検定対策ブログの記事内容を、Instagramで短時間に理解・復習できる5枚カルーセルへ展開する。

カルーセル単体でも学習価値を持たせつつ、Instagramをブログへの入口として使う。

- Instagram：全体像・直感・判断基準を短く伝える
- ブログ：定義、仕組み、比較、ひっかけまで詳しく学ぶ
- 1つのテーマから「ブログ記事 → Instagramカルーセル」へ再利用できる制作フローを優先する

## 共通方針

すべてのカルーセルは、次の流れを意識する。

**全体像 → 直感 → 役割・仕組み → ひっかけ → 判断基準**

- 5枚構成を固定する
- 生成は必ず1枚ずつ行う
- 1回の依頼で1画像のみ生成する
- 分割画像・5枚まとめ画像は禁止する
- 落ち着いた、知的、教材風のデザインにする
- 余白を多めにする
- 原色や過度に派手な装飾は避ける
- 文字量は最小限にする
- 数式は必要な場合のみ使う
- 「暗記」よりも「選択肢を切る判断基準」を優先する
- 類似用語との混同を防ぐ視点を必ず含める

## 主要参考資料の扱い

生成内容の根拠は、ユーザーが指定する主要参考資料（MarkdownまたはGitHub Pages URL）を最優先する。

- 主要参考資料の定義・切り口・粒度を正とする
- 一般知識は補助としてのみ使う
- 参考資料にない説明を勝手に中心テーマへ広げない
- ブログ記事とInstagramで説明が食い違わないようにする

## 5枚の役割

### 1枚目｜全体像＋用語定義インフォグラフィック

目的は、**全体像と用語定義を示し、その用語の「つまり何？」を1枚で理解できるようにすること**。

必須要素：

1. 用語名
2. 一文定義
3. 中心概念を示す図
4. 重要要素は最大3つ
5. G検定での判断軸を短く1つ

構成の目安：

```text
用語名
↓
一文定義
↓
中心概念
↙ ↓ ↘
重要要素1 / 重要要素2 / 重要要素3
↓
試験での一言判断
```

ルール：

- 1枚目だけ見ても学習になるようにする
- 「タイトルだけ」の表紙にはしない
- 教科書のように情報を詰め込まない
- 最大3要素を基本とする
- 詳細説明は2〜4枚目へ送る
- 5枚目の「試験直前まとめ」と同じ内容を繰り返さない
- 「保存したくなる小さな学習ポスター」として成立させる

役割の違い：

- 1枚目 = **What is it?（全体像＋用語定義）**
- 5枚目 = **How do I identify it?（試験でどう見抜く？）**

### 2枚目｜直感的理解

目的は、**見た瞬間にイメージできるようにすること**。

次のような、その用語に合う表現を使う。

- たとえ
- 対応関係
- Before / After
- 入力 → 処理 → 出力
- 抽象図

文章で説明しすぎず、図を主役にする。

### 3枚目｜役割・立ち位置

目的は、**その用語が何の役割を担うのかを整理すること**。

用語の種類に応じて分類し、適切な構成を選ぶ。

主な分類：

- 学習手法
- モデル／構造
- 評価指標
- 問題・現象
- 概念・構成要素

スライド3は、次の手順を必須とする。

1. 用語を先に分類する
2. 正しい分類を選ぶ
3. 分類別の構成を使う
4. すべての用語に一律のレイアウトを適用しない

分類・レイアウトの正本は `project_rules/スライド3｜分類別プロンプト集.md` とする。このファイルがリポジトリ内に存在する場合、スライド3制作時に必ず参照する。存在しない場合も、上記の分類手順を省略してはならない。

### 4枚目｜ひっかけ防止

目的は、**似た用語や誤った説明を選択肢から切れるようにすること**。

基本構成：

- ❌ よくある誤解
- ⭕ 正しい理解

短い対比を優先する。必要に応じて、最も混同しやすい用語を1〜2個だけ扱う。

### 5枚目｜試験直前まとめ

目的は、**試験中に思い出す判断基準を残すこと**。

- 判断基準は最大3点に絞る
- 箇条書きにする
- 一文を短くする
- 「覚える項目」ではなく「見分ける基準」にする

例：

- 「離散・量子化・コードブック」→ VQ-VAE
- 「画像 × 局所特徴」→ CNN
- 「生成器 vs 識別器」→ GAN

## 1枚目と5枚目の切り分け

重複を避けるため、役割を明確に分ける。

### 1枚目：全体像と用語定義を理解するための地図

- 何の用語か
- どういう構造か
- 何が重要か

### 5枚目：問題を解くためのチェックリスト

- どのキーワードで判断するか
- 何と混同しないか
- どの選択肢を切るか

## Instagramとブログの相互導線

### ブログからInstagramカルーセルを作る

カルーセルはブログ記事の要約版として設計する。

基本フロー：

```text
ブログ記事
↓
1枚目に全体像と用語定義を圧縮
↓
2〜5枚目で理解と判断基準を補強
↓
Instagram投稿
↓
詳しい説明はブログへ誘導
```

画像内にURLを大量に入れず、ブログへの誘導は投稿キャプションやプロフィールリンクを基本とする。

必要に応じて5枚目の下部に、「詳しい解説はブログへ」程度の短いCTAを入れてよい。

### Instagram公開後にブログからリンクする

カルーセルをInstagramへ公開し、投稿URLが確定したら、対応するGKブログ記事にInstagram復習リンクを追加する。

```text
GKブログ記事
↓
Instagramカルーセルを制作
↓
カルーセルを公開
↓
Instagram投稿URLが確定
↓
対応するブログ記事に復習リンクを追加
```

リンクは `pages/gk/dendrogram.md` を基準実装とし、通常記事の `## まず結論` の末尾、次の区切り線または `## 直感的な説明` の前に置く。

```md
📌 **Instagramでも5枚のカルーセルで復習できます。**
[用語名｜G検定対策カルーセルを見る](https://www.instagram.com/p/POST_ID/)
```

追加時のルール：

- リンク先には、対応するカルーセル投稿の直接URLを使う
- InstagramのプロフィールURLや、別テーマの投稿URLで代用しない
- 投稿URLが確定する前に、仮URLやプレースホルダーを記事へ追加しない
- リンクテキストの `用語名` は、記事とカルーセルに対応する名称へ置き換える
- 同じカルーセルへの案内を記事内の複数箇所へ重複して置かない
- URLを追加した記事の `last_modified_at` を更新する
- 単純なMarkdownリンクを使い、埋め込みHTMLや複雑なLiquidは使わない
- 公開後に、リンクが対応するInstagram投稿へ遷移することを確認する

Instagram投稿URLをGK記事へ保存する前に、共有用・追跡用のクエリパラメータを取り除いて正規化する。

- `utm_source`、`igsh`、その他同様の追跡パラメータはGKのMarkdownファイルへ保存しない
- Instagramの投稿IDは一切変更しない
- 投稿種別や投稿IDなど、意味のあるパス情報は削除しない
- 通常のカルーセル投稿では、`https://www.instagram.com/p/POST_ID/` 形式を優先する

## 日本語テキスト事故防止

- 短文を優先する
- 漢字を詰め込みすぎない
- 1ブロック2〜3行までにする
- 長い説明文は禁止する
- 重要語だけ太字相当で強調する
- 文字崩れが出る場合はCanva等で差し替える前提とする

## デザイン方針

- 落ち着いたデザインにする
- 知的な印象にする
- 教材風にする
- 余白を多めにする
- 情報階層が一目で分かるようにする
- 装飾より理解を優先する
- 1枚につき主メッセージは1つにする

特に1枚目は、**「保存したくなる小さな学習ポスター」**として成立することを目標にする。

## 制作時の入力

次の情報がそろっていれば作業可能とする。

- 作成する用語
- 主要参考資料（MarkdownパスまたはURL）
- 作成するスライド番号（1〜5）
- 追加で強調したい点（あれば1つ）

## 運用ルール

カルーセル制作時は、次の優先順位で参照する。

1. `AGENTS.md`
2. `docs/agent/gk-content-rules.md`
3. `docs/agent/gk-carousel-rules.md`
4. `project_rules/スライド3｜分類別プロンプト集.md`（存在する場合）
5. 「G検定カルーセル｜最終マスタープロンプト」（指定または提供された場合）
6. 分解・実験用プロンプト（`prompt_gkentei_xx.md`、指定または提供された場合）

- リポジトリのルールファイルは、安定した制作方針を定める
- マスタープロンプトは、ルールに従う詳細な実行手順として使う
- 分解・実験用プロンプトは、調整・検証用途に限定する
- プロンプトが上位のリポジトリルールと矛盾する場合は、上位のリポジトリルールを優先する
- 特に、5枚構成、1回の依頼で1画像のみ生成、1枚目＝全体像＋用語定義、3枚目＝分類別構成、4枚目＝ひっかけ防止、5枚目＝試験の判断基準という役割を維持する
