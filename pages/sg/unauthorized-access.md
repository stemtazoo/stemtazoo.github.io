## まず結論

不正アクセス行為を判断するときは、**ネットワーク経由か、アクセス制御があるか、制限された利用を不正に可能にしたか**を確認します。内部者か外部者か、パスワードが正しいかだけでは決まりません。

取得・提供・保管・入力要求など法律全体の類型は[不正アクセス禁止法](/sg/unauthorized-access-law/)で確認できます。

## 直感的な説明

鍵が合ったことと、その鍵を使う正当な理由があることは違います。反対に、不適切な操作であっても、不正アクセス行為そのものの要件に当たるかは別に確認します。

## 定義・仕組み

| 確認する条件 | 事例で見ること |
|---|---|
| 電気通信回線を通じた利用か | インターネットや社内LAN経由か |
| アクセス制御機能があるか | 識別符号で特定の利用を制限しているか |
| 制限された利用を可能にしたか | 他人の識別符号の入力、制限を免れる情報・指令の入力等 |
| 承諾など、条文上の除外に当たらないか | 管理者や利用権者の承諾等を条件に沿って確認する |

「なりすまし型」と、弱点を突いて制限を免れる「セキュリティホール型」が学習上の代表例です。秘密のパスワードを盗む方法だけに限定されません。

## どんな場面で使う？

| 具体例 | 判断の進め方 |
|---|---|
| 他人の認証情報を無断使用し、LAN経由で制限機能を利用可能にする | 正しいパスワードでも、なりすまし型の条件を確認 |
| 認証の弱点を突き、ネットワーク経由で管理機能を利用可能にする | パスワードなしでも制限を免れる行為を確認 |
| 自分の正当な権限で閲覧した資料を規程に反して持ち出す | 持出しの不正と、不正アクセス行為の成立を分ける |
| 認証情報を入手したが、まだ入力していない | 不正アクセス行為そのものとは分け、不正取得等を確認 |

自分の権限での操作でも、内容によって営業秘密侵害や[電子計算機使用詐欺](/sg/computer-fraud/)等が問題になる場合があります。「この条文の要件に当たらない」と「適切な行動」は別です。

## よくある誤解・混同

- 社員なので必ず正当な利用 → その機能を使う権限・承諾を確認する。
- データを盗んだ後でなければ成立しない → 制限された利用を可能にする行為が論点。
- 他人の認証情報を入力したら、承諾等を見ず必ず該当 → 条文上の除外も確認する。
- アクセス制御がない対象の妨害は何をしても適法 → この法律の不正アクセス行為と、他の法令による規制は別。

## 確認問題（SG試験対策）

アクセス制御のある社内サーバについて、不正アクセス行為そのものの判断として最も適切なものはどれか。

- ア. 社員であれば、他人の識別符号を無断使用してLAN経由で制限機能を利用しても対象外である。
- イ. 識別符号を入手しただけでも、必ず不正アクセス行為そのものに当たる。
- ウ. 他人の識別符号を正当な承諾なく入力し、LAN経由で制限された利用を可能にした行為を確認する。
- エ. パスワードを使わず制限を免れた行為は、対象にならない。

### 解説

- ア：社員という立場だけで権限や承諾は決まりません。
- イ：不正取得等の別類型と分けます。
- ウ：ネットワーク経由・制御・制限された利用と承諾の条件を読む判断です。
- エ：弱点を突いて制限を免れる場合も確認します。

## まとめ（試験直前用）

- 回線、アクセス制御、制限された利用、承諾等の条件を読む。
- ログイン成功と正当な利用を同一視しない。
- 不正取得等の周辺行為と、不正アクセス行為そのものを分ける。
