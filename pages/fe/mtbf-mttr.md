## まず結論

**MTBFはシステムが故障せずに稼働していた時間の平均、MTTRは故障後に修理していた時間の平均**です。

基本情報技術者試験では、英語を細かく暗記するより、まず次の対応で切ると判断しやすいです。

```text
MTBF
→ 動いていた時間
→ 大きいほどよい

MTTR
→ 直していた時間
→ 小さいほどよい
```

稼働時間を `t`、修理時間を `r` とすると、

```text
MTBF = 稼働時間 t の平均
MTTR = 修理時間 r の平均
```

です。

信頼性・可用性・保守性という評価の観点と指標の対応は、[RASISの5要素の違い](/fe/rasis/) で整理しています。

MTBFそのものの計算を、複数台の総稼働時間まで含めて詳しく確認したい場合は、[MTBFとは？](/fe/mtbf/) を参照してください。

MTBF・MTTRから求めた稼働率を、直列・並列構成へ広げる計算は、[直列・並列システムの稼働率](/fe/series-parallel-system-availability/) で整理しています。故障率が時間とともにどう変わるかは、[バスタブ曲線](/fe/bathtub-curve/) を参照してください。

## 直感的な説明

システムの状態を、次の繰り返しとして考えます。

```text
稼働 → 故障 → 修理 → 稼働 → 故障 → 修理 → …
 t1            t2            t3
        r1            r2            r3
```

このとき、

- `t1, t2, t3, ...` は、故障せずに動いていた時間
- `r1, r2, r3, ...` は、故障してから直すまでの時間

です。

そのため、MTBFは `t` の平均、MTTRは `r` の平均になります。

試験中は、次のように読むとシンプルです。

```text
t = time running
→ MTBF

r = repair
→ MTTR
```

## 定義・仕組み

MTBFは **Mean Time Between Failures** の略で、日本語では平均故障間隔と呼ばれます。

稼働時間が `t1, t2, ..., tn` のとき、

```text
MTBF = (t1 + t2 + ... + tn) / n
```

です。

一方、MTTRは **Mean Time To Repair** の略で、日本語では平均修理時間と呼ばれます。

修理時間が `r1, r2, ..., rn` のとき、

```text
MTTR = (r1 + r2 + ... + rn) / n
```

です。

つまり、式を見たときは、**何の時間を平均しているか**を確認すれば判断できます。

| 指標 | 平均する時間 | 良い方向 |
|---|---|---|
| MTBF | 稼働時間 | 大きい |
| MTTR | 修理時間 | 小さい |

さらに、MTBFとMTTRから稼働率を求める代表的な式は次のとおりです。

```text
稼働率 = MTBF / (MTBF + MTTR)
```

直感的には、

```text
動いている時間
──────────────
動いている時間 + 直している時間
```

です。

そのため、

```text
MTBFが大きい
→ 長く故障せずに動く
→ 稼働率が上がる

MTTRが小さい
→ 故障しても早く直る
→ 稼働率が上がる
```

と判断できます。

このテーマは、基本情報技術者試験のシステム構成要素や信頼性に関係する内容です。公式の出題範囲やシラバスは、[IPA：基本情報技術者試験](https://www.ipa.go.jp/shiken/kubun/fe.html) から確認できます。

## 科目Aでどう出る？

科目Aでは、稼働と修理を繰り返す図から、MTBF・MTTRの式を選ぶ問題や、稼働率を求める問題が出題されます。

最初に確認するのは、**記号が何を表しているか**です。

```text
稼働時間 t
→ MTBF

修理時間 r
→ MTTR
```

そのうえで、次の順番で選択肢を切ります。

```text
1. MTBFに稼働時間が入っているか
2. MTTRに修理時間が入っているか
3. 稼働時間と修理時間を混ぜて平均していないか
```

例えば、

```text
MTBF = 平均(t)
MTTR = 平均(r)
```

なら正しい対応です。

一方で、

```text
MTBF = 平均(r)
MTTR = 平均(t)
```

なら、役割が逆なので誤りです。

また、`t + r` をそのままMTBFやMTTRとして平均している選択肢も、まず疑います。

MTBFはあくまで**稼働時間の平均**、MTTRはあくまで**修理時間の平均**だからです。

### ITILの可用性管理：MTBF・MTTR・MTRS・MTBSIの違い

ITILの可用性管理では、**保守性（回復の早さ）**を問われたら、故障の発生間隔ではなく、サービスを回復するまでの時間に注目します。

| 指標 | 英語 | 何を測るか | 試験での切り分け |
|---|---|---|---|
| MTBF | Mean Time Between Failures | 故障せずに稼働する平均時間 | 信頼性：故障しにくいか |
| MTTR | Mean Time To Repair | 故障した機器などの平均修理時間 | 保守性：修理しやすいか |
| MTRS | Mean Time to Restore Service | サービス中断から利用可能になるまでの平均時間 | **保守性：サービスを早く回復できるか** |
| MTBSI | Mean Time Between Service Incidents | サービス中断から次の中断までの平均時間 | 信頼性：中断が起こりにくいか |

ここでは、ITILのサービス指標と、機器の故障・修理を測る指標を比較しています。**MTTRとMTRSは対象が違う**ため、同じ時間になるとは限りません。

```text
サービス利用可能 → サービス中断 → 修理完了 → サービス回復
                      |← 機器の修理 →|
                      |← サービス回復までの時間 →|
```

例えば、サーバの修理に30分かかり、その後のデータ復元・動作確認に20分かかったとします。この例では機器の修理時間は30分ですが、サービス回復までには50分かかります。複数回の平均をとる場合も、**何の終了時点を測っているか**が重要です。

#### 科目Aの選択肢を切る

「ITILの可用性管理において、保守性を表すKPIはどれか」という問題では、次のように判断します。

| 選択肢にある説明 | 判断 |
|---|---|
| 一定期間内の中断の数 | 中断の発生状況を測る。回復の早さではない |
| 平均故障間隔（MTBF） | 故障しにくさ＝信頼性 |
| **平均サービス回復時間（MTRS）** | **サービス回復の早さ＝保守性。正解** |
| 平均サービス・インシデント間隔（MTBSI） | 中断の起こりにくさ＝信頼性 |

注意したいのは、**可用性管理で使う指標が、すべて保守性を表すわけではない**ことです。中断回数や故障間隔は可用性の分析に役立ちますが、設問が「保守性」を尋ねたら回復時間を選びます。

関連する品質の観点は[RASISの5要素](/fe/rasis/)で、利用者から見たサービスの利用可能性は[サービスの可用性](/fe/service-availability/)で確認できます。

## 科目Bでどう使う？

科目Bでは、システムの稼働状況を表すデータから、平均値や稼働率を計算する形で考えることがあります。

例えば、

```text
MTBF = 900時間
MTTR = 100時間
```

なら、

```text
稼働率 = 900 / (900 + 100)
       = 0.9
       = 90%
```

です。

コードや表を追うときも、

```text
稼働時間を足す
→ MTBF側

修理時間を足す
→ MTTR側
```

と意味を確認してから計算すると読みやすくなります。

## よくある誤解・混同

MTBFとMTTRで最も多い混同は、**どちらが稼働時間で、どちらが修理時間かを逆にすること**です。

| 誤解 | 正しい理解 |
|---|---|
| MTBFは修理時間の平均 | MTBFは稼働時間の平均 |
| MTTRは稼働時間の平均 | MTTRは修理時間の平均 |
| MTBFは小さいほどよい | MTBFは大きいほどよい |
| MTTRは大きいほどよい | MTTRは小さいほどよい |
| MTBFとMTTRを足した値が稼働時間 | MTBF + MTTR は1サイクルの平均時間のイメージ |

特に試験では、英語の略称だけで考えるより、次の日本語に戻す方が安全です。

```text
MTBF
→ 壊れるまで、どれくらい長く動けたか

MTTR
→ 壊れてから、どれくらい早く直せたか
```

## まとめ（試験直前用）

- MTBFは平均故障間隔で、**稼働時間の平均**
- MTTRは平均修理時間で、**修理時間の平均**
- `t = 稼働時間` ならMTBF側
- `r = repair` ならMTTR側
- MTBFは大きいほどよい
- MTTRは小さいほどよい
- ITILの保守性を問われたらMTRS（平均サービス回復時間）を選ぶ
- MTBSIはサービス中断の間隔であり、回復時間ではない
- 稼働率は `MTBF / (MTBF + MTTR)`

試験中は、まず

```text
動いていた時間 → MTBF
直していた時間 → MTTR
```

と置き換えると、式の選択肢を切りやすくなります。
