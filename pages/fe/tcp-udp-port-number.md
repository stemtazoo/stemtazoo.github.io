## まず結論

ポート番号は、**コンピュータの中で「どの通信・プログラムにデータを届けるか」を識別するための番号**です。

基本情報技術者試験では、まず次の図をイメージしてください。

```text
行き：PC → Webサーバ

PC                         Webサーバ
50001  ───────────────→    80
送信元                     宛先


戻り：Webサーバ → PC

PC                         Webサーバ
50001  ←───────────────    80
宛先                       送信元
```

往復通信では、

> **戻りのパケットでは、行きの「送信元」と「宛先」が入れ替わる**

と考えるのがポイントです。

## 直感的な説明

IPアドレスとポート番号は、**住所と部屋番号**で考えると分かりやすくなります。

```text
IPアドレス
    ↓
建物の住所

ポート番号
    ↓
部屋番号
```

IPアドレスによって通信相手のコンピュータまで届けられても、そのコンピュータでは複数のプログラムが動いています。

```text
PC
┌──────────────────┐
│ 50001番 ← Web通信       │
│ 50002番 ← 別の通信      │
│ 50003番 ← 別の通信      │
└──────────────────┘
```

そこでポート番号を使って、どの通信へデータを渡すかを区別します。

英語では、**IP address identifies the host, port number identifies the service/process** と整理するとイメージしやすいです。

### Web通信を図で追ってみる

PCからWebサーバへHTTPの要求を送る例を考えます。

```text
① PCから要求

PC                         Webサーバ
50001  ─── HTTP要求 ───→   80
```

このとき、

- 送信元ポート番号：50001
- 宛先ポート番号：80

です。

Webサーバが返事をすると、

```text
② Webサーバから応答

PC                         Webサーバ
50001  ←── HTTP応答 ────   80
```

となります。

今度は、

- 送信元ポート番号：80
- 宛先ポート番号：50001

です。

つまり、

```text
行き
50001 → 80

戻り
50001 ← 80
```

と考えればOKです。

## 定義

TCPやUDPでは、通信するアプリケーションやサービスを識別するために**16ビットのポート番号**を使用します。

ポート番号の範囲は0～65535です。

IANAでは、おおまかに次のように区分されています。

| 範囲 | 区分 | ポイント |
|---|---|---|
| 0～1023 | System Ports | HTTPなど代表的なサービスで使われる |
| 1024～49151 | User Ports | 登録されたアプリケーションなどで使われる |
| 49152～65535 | Dynamic/Private Ports | 一時的な通信などで利用される |

試験では、古い資料や説明で名称が異なる場合があります。まずは**0～1023に代表的なサービスのポート番号がある**ことと、クライアント側では一時的なポート番号が使われることを押さえれば十分です。

代表例として、

```text
HTTP  → 80
HTTPS → 443
```

があります。

### プロキシが入ると「通信を2本」に分ける

プロキシサーバを経由する問題では、クライアントからWebサーバまでを1本の通信として追わないことが重要です。

例えば、クライアントAが8080番で待ち受けるプロキシBを経由し、80番で待ち受けるWebサーバCへアクセスする場合は、次の**2本の通信**に分けます。

```text
通信①                     通信②
A ⇔ B                     B ⇔ C
    8080                       80

クライアントA ⇔ プロキシB   プロキシB ⇔ WebサーバC
```

プロキシBはAから受け取ったTCP通信をそのままCへ通すのではなく、**B自身がCへ別のTCP通信を開始**します。

仮に、A側の一時ポートを `p1`、BがCへ接続するときの一時ポートを `p2` とすると、4方向は次のようになります。

| 通信 | 送信元ポート | 宛先ポート |
|---|---:|---:|
| A → B：HTTP要求 | p1 | **8080** |
| B → A：HTTP応答 | **8080** | p1 |
| B → C：HTTP要求 | p2 | **80** |
| C → B：HTTP応答 | **80** | p2 |

図では、次のように考えると分かりやすくなります。

```text
A                  B                  C
p1               8080   p2            80
│                  │     │              │
│─── HTTP要求 ───→│     │              │
│←── HTTP応答 ────│     │              │
│                        │── HTTP要求 ─→│
│                        │←─ HTTP応答 ──│
```

ここから分かる重要なルールは、

> **サービス側のポート番号は、要求では「宛先」、応答では「送信元」になる。**

ということです。

8080番はAとBの通信でBが待ち受けるポートなので、

```text
A → B の要求
宛先 = 8080

B → A の応答
送信元 = 8080
```

となります。

一方、BとCの通信ではCの80番を使うので、宛先8080にはなりません。

試験中は、問題文の横にまず、

```text
A ⇔ B：8080
B ⇔ C：80
```

と書いてから、矢印の向きを確認すると判断しやすくなります。

プロキシが「クライアントの代わりに別の通信を行う」仕組みについては、[プロキシサーバとは？DNS・DHCP・NATとの違いと見分け方](/fe/proxy-server/)もあわせて確認してください。

### 送信元ポートと宛先ポート

パケットには、

```text
送信元ポート番号
宛先ポート番号
```

の両方があります。

例えば、

```text
PC:50001 → Webサーバ:80
```

なら、

```text
送信元 = PCの50001
宛先   = Webサーバの80
```

です。


### FE科目A：代表的なプロトコルはTCPかUDPか？

ポート番号を覚えるときは、**アプリケーションの名前・役割・主に使うTCP/UDP・代表的なポート番号**をひとまとめに整理しましょう。

| プロトコル | 主な役割 | 基本となる通信方式 | 代表的なポート |
|---|---|---|---|
| **FTP** | ファイル転送 | **TCP** | 制御用21、アクティブモードのデータ用20 |
| **NTP** | コンピュータの時計を同期 | **UDP** | **123** |
| **POP3** | メールサーバからメールを受信 | **TCP** | 110 |
| **TELNET** | 遠隔端末操作 | **TCP** | 23 |
| **DNS** | ドメイン名とIPアドレスなどを対応付ける | **UDPとTCPの両方** | 53 |
| **DHCP（IPv4）** | IPアドレスなどの設定を自動配布 | **UDP** | サーバ67、クライアント68 |

**試験で「FTP・NTP・POP3・TELNETのうちUDPを使うのは？」と問われたら、NTPを選びます。** これは代表的な利用方法に基づく判断です。

FTPは一般にTCPでファイルを転送します。**20番は従来のアクティブモードのデータ接続で使う代表例**であり、FTP通信ではいつも20番と21番を両方使うとは限りません。

#### 例外もセットで覚える

- **DNS：UDPだけではない。** 通常の名前解決でUDP 53を使うことが多い一方、応答内容などに応じてTCP 53も使用します。
- **HTTPS：TCPだけと決め付けない。** HTTP/1.1やHTTP/2を使うHTTPS通信は主にTCP 443ですが、**HTTP/3はUDP上のQUIC**を使います。通常のHTTPSでは443番が代表的です。
- **DHCP：IPv4の基本例。** DHCPv4はUDP 67（サーバ）・68（クライアント）を使います。DHCPv6は別のポート番号（UDP 546・547）なので、IPv4と混同しないようにしましょう。

このように、**「プロトコルの名前」と「ポート番号」だけでなく、実際にどの通信方式を使うか**を判断します。IANAのポート番号登録表では同じサービス名にTCP・UDPが載る場合もあるため、**登録されていることと、そのプロトコルが通常その方式で通信することは分けて考える**のが大切です。

### TCP・UDPの判断をするオリジナル確認問題

社内の監視システムで、機器の時刻を定期的に同期する通信を設定する。**通常のNTPによる時刻同期**で使用するトランスポート層のプロトコルと代表的なサーバ側ポート番号の組合せとして最も適切なのはどれか。

- ア：TCP・21番
- イ：UDP・123番
- ウ：TCP・110番
- エ：TCP・23番

## どんな場面で使う？

### Webサイトを見る

ブラウザからWebサーバへHTTP通信する場合、

```text
ブラウザ
   │
   │ 宛先 80
   ▼
Webサーバ
```

のように、サーバ側のサービスをポート番号で指定します。

### 同じPCで複数の通信を行う

同じPCから複数の通信を行っていても、ポート番号によって区別できます。

```text
PC
50001 ───→ WebサーバA
50002 ───→ WebサーバB
50003 ───→ 別サービス
```

戻ってきたデータについても、宛先ポート番号を見ることで、どの通信へ渡すべきか判断できます。

## よくある誤解・混同

### 戻りも「50001 → 80」になる

違います。

通信方向が逆になるので、

```text
行き
PC:50001 → Server:80

戻り
PC:50001 ← Server:80
```

です。

表にするとさらに分かりやすくなります。

| 通信 | 送信元 | 宛先 |
|---|---|---|
| PC → Webサーバ | 50001 | 80 |
| Webサーバ → PC | 80 | 50001 |

**戻りでは送信元と宛先を入れ替える**と判断します。

### Web通信なら両方とも80番

これも違います。

80番はHTTPサービスを提供するWebサーバ側で使われる代表的なポート番号です。

クライアント側では、その通信を識別するための別のポート番号が使われます。

```text
PC                 Webサーバ
50001 ─────────→    80
```

### IPアドレスがあればポート番号はいらない

IPアドレスだけでは、通信先のコンピュータまでは識別できても、**その中のどのサービス・通信へ届けるか**を区別できません。

```text
IPアドレス
「どのコンピュータ？」

ポート番号
「その中のどの通信・サービス？」
```

この2つを分けて考えます。

### 50001という番号を暗記する

暗記する必要はありません。

問題文で、

```text
PC側 = 50001
Webサーバ側 = 80
```

と与えられているなら、重要なのは番号そのものではなく**通信方向**です。

## 標準仕様で確認する

TCP・UDPのポート番号と割当ての考え方は、IETF/IANAの一次資料で確認できます。

- [RFC 6335：Service Name and Transport Protocol Port Number Registry](https://www.rfc-editor.org/info/rfc6335)
- [IANA：Service Name and Transport Protocol Port Number Registry](https://www.iana.org/assignments/service-names-port-numbers/)
- [RFC 5905：NTPv4](https://www.rfc-editor.org/rfc/rfc5905)
- [RFC 7766：DNS Transport over TCP](https://www.rfc-editor.org/rfc/rfc7766)
- [RFC 9114：HTTP/3](https://www.rfc-editor.org/rfc/rfc9114)

RFC 6335では、ポート番号空間を **System Ports（0～1023）・User Ports（1024～49151）・Dynamic Ports（49152～65535）** に分けています。

代表的なサービスの現在の登録状況を確認するときは、IANAのレジストリが一次情報です。

FE試験では全ポート番号を覚える必要はなく、HTTP 80、HTTPS 443などの代表例と、**送信元・宛先のどちらのポートか**を見分けることを優先します。

## まとめ（試験直前用）

- IPアドレス → **どのコンピュータか**
- ポート番号 → **その中のどの通信・サービスか**
- HTTPの代表的なポート番号は80
- **NTPは通常UDP 123、FTP・POP3・TELNETは基本的にTCP**
- **DNSはUDP/TCP両方、HTTP/3はUDP上のQUIC**
- パケットには送信元ポートと宛先ポートがある
- 往復通信では**送信元と宛先が入れ替わる**
- プロキシを経由するときは、**クライアント⇔プロキシ**と**プロキシ⇔Webサーバ**の2本に分ける
- 問題文でクライアント側のポート番号が指定されていたら、その番号を使って考える
- 動的ポートの具体的な番号を暗記する必要はない

試験中は、問題文の横に次のように書くだけでも判断しやすくなります。

```text
行き：50001 → 80
戻り：50001 ← 80
```

> **「戻りは矢印を逆にする」――まずこれを図にすると、送信元と宛先を取り違えにくくなります。**
