## まず結論

クライアントサーバ方式は、**システムの機能を「サービスを要求する側」と「サービスを提供する側」に分ける方式**です。

```text
クライアント
「処理してください」
      │
      │ 要求
      ▼
    サーバ
「処理します」
      │
      │ 結果
      ▼
クライアント
```

- クライアント：サービスを要求する側
- サーバ：サービスを提供する側

基本情報技術者試験では、次の一文を判断軸にします。

> **機械の種類ではなく、「要求する側」と「提供する側」という役割で判断する。**

また、クライアントサーバ方式は、異なる役割・機能を分担する**垂直分散**の考え方として整理できます。

```text
垂直分散 → 異なる役割を分担
水平分散 → 同じ役割を複数に分散
```

## 直感的な説明

レストランをイメージすると分かりやすくなります。

```text
客
「料理をお願いします」
      │ 注文
      ▼
   キッチン
「料理を作ります」
      │ 料理
      ▼
     客
```

コンピュータに置き換えると、

```text
クライアント
「このデータをください」
        │
        ▼
データベースサーバ
「検索して返します」
        │
        ▼
クライアント
```

となります。

大切なのは、**パソコンだからクライアント、高性能コンピュータだからサーバ、と決まるわけではない**ことです。

```text
× PC = クライアント
× ワークステーション = サーバ

○ 要求する役割 = クライアント
○ 提供する役割 = サーバ
```

英語でも、**client requests, server provides** と考えると覚えやすくなります。

### 垂直分散と水平分散

ここは試験で混同しやすいポイントです。

#### 垂直分散

**異なる機能・役割を分ける**考え方です。

```text
     システム
        │
  ┌─────┴─────┐
  ▼           ▼
画面・要求    データ処理
クライアント   サーバ
```

上下に役割を分けるイメージです。

#### 水平分散

**同じような機能・役割を複数のコンピュータへ分散する**考え方です。

```text
          処理
           │
    ┌──────┼──────┐
    ▼      ▼      ▼
 サーバA  サーバB  サーバC
   同じ役割を分担
```

複数台で処理を受け持ち、負荷を分散するイメージです。

```text
垂直分散
→ 役割を「分ける」

水平分散
→ 同じ役割を「増やして分ける」
```

## 定義

クライアントサーバ方式は、ネットワーク上の処理を、**サービスを要求するクライアントと、サービスを提供するサーバに分けて実行するシステム構成**です。

例えば、データベースを利用するシステムなら、

```text
[クライアント]
画面表示
入力
検索要求
     │
     ▼
[DBサーバ]
データ保存
検索処理
更新処理
```

のように役割を分担できます。

### クライアント

サーバへ処理やサービスを要求します。

例：

- Webページを要求する
- データベース検索を要求する
- ファイルを要求する

### サーバ

クライアントからの要求を受けて、サービスを提供します。

例：

- Webサーバ
- データベースサーバ
- ファイルサーバ

### 2層と3層

クライアントサーバ方式では、役割の分け方によって2層や3層の構成があります。

```text
2層

クライアント
     │
     ▼
DBサーバ
```

```text
3層

クライアント
     │
     ▼
アプリケーションサーバ
     │
     ▼
DBサーバ
```

層が増えても、**役割を分けてサービスを要求・提供する**という基本は同じです。

## 科目Aでどう出る？

試験では、**要求する側と提供する側の取り違え**や、**密結合システムとの混同**を狙う説明に注意します。クライアントサーバ方式の定義は、コンピュータの台数や機種ではなく、役割の分担です。

## どんな場面で使う？

### データベースを複数利用者で利用する

```text
PC A ─┐
PC B ─┼→ DBサーバ
PC C ─┘
```

データをサーバ側で管理し、各クライアントから利用できます。

### Webシステム

Webブラウザも身近な例です。

```text
ブラウザ
「ページをください」
     │
     ▼
Webサーバ
「ページを返します」
```

### 役割ごとに機能を分離する

クライアント側の画面処理とサーバ側のデータ処理などを分けることで、役割を整理できます。

## よくある誤解・混同

### パソコンがクライアント、ワークステーションがサーバ

違います。

```text
機械の種類
   ×
役割で決まる
   ○
```

試験では「何のコンピュータか」ではなく、**サービスを要求するか、提供するか**を見ます。

### データを各端末へ分散する方式

クライアントサーバ方式の定義ではありません。

データベースを利用する典型的な構成では、データをDBサーバ側で管理し、クライアントが要求を送ります。

```text
クライアント
     │ 検索要求
     ▼
  DBサーバ
     │ 結果
     ▼
クライアント
```

### クライアントサーバ方式 = 水平分散

ここが特に重要です。

```text
クライアント
     ↓
   サーバ

役割が違う
→ 垂直分散
```

一方、

```text
サーバA  サーバB  サーバC
   ＼      │      ／
      同じ処理
```

のように、同じ役割を複数台へ分けるのが水平分散です。

### サーバは必ず1台

「サーバ」は物理的な1台のコンピュータそのものではなく、サービスを提供する役割を指します。

構成によって複数台のサーバを利用することもあります。

### 密結合システムと同じ意味？

**同じ意味ではありません。** クライアントサーバ方式は「サービスを要求する側と提供する側」という**役割分担**の話です。一方、密結合・疎結合は、複数の処理装置やシステムの**結び付き方**を区別する考え方です。

| 用語 | 判断するポイント |
|---|---|
| クライアントサーバ方式 | 誰が要求し、誰が提供するか |
| 密結合システム | 処理装置が主記憶などを共有し、密接に連携する構成 |
| 疎結合システム | 独立したコンピュータが通信して連携する構成 |

ネットワークを介して独立した端末とサーバが通信する一般的なクライアントサーバ構成を、**密結合システムと決めつける選択肢は誤り**です。

### クライアントはサービスを提供する側？

基本的には違います。クライアントは**要求する側**、サーバは**提供する側**です。なお、クライアントも画面表示や入力チェックなどの処理を行うため、「何も処理しない端末」という理解も正しくありません。

## まとめ（試験直前用）

- クライアント = **サービスを要求する側**
- サーバ = **サービスを提供する側**
- PCやワークステーションなど、機械の種類で判断しない
- クライアントサーバ方式は役割・機能を分ける
- **異なる役割を分ける → 垂直分散**
- **同じ役割を複数へ分ける → 水平分散**
- データベースを端末へ分散することが定義ではない

> **「要求する側」と「提供する側」に分かれていたら、まずクライアントサーバ方式を考える。**
