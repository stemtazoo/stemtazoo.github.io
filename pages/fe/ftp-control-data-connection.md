## まず結論

FTP（File Transfer Protocol）は、ネットワーク上でファイルを送受信するためのプロトコルです。**ログインや転送指示をやり取りする「制御接続」と、ファイル本体などを送る「データ接続」を分ける**のが特徴です。

FEの科目Aでは、まず **制御接続はサーバ側TCP/21**、従来の**アクティブモードのデータ接続はサーバ側TCP/20を送信元として使う**、と整理しましょう。ただし、**パッシブモードではデータ接続にTCP/20を使うとは限りません**。

## 直感的な説明

FTPを「倉庫への荷物の出し入れ」に例えてみます。

- **制御接続**：受付で「ログインしたい」「このファイルを送って」と伝える窓口
- **データ接続**：実際のファイル（荷物）を運ぶ通路

受付で指示を出すことと、荷物を運ぶことは別の仕事です。FTPではこれらを別のTCP接続に分けています。

```text
PC（FTPクライアント）              FTPサーバ
        │                              │
        ├──── ログイン・転送指示 ────→│
        │       制御接続：TCP/21       │
        │←──────── 応答 ──────────────┤
        │                              │
        │←────── ファイル本体 ───────→│
        │         データ接続           │
        │                              │
```

上図は**通信の役割を示した概念図**です。データ接続を**どちらが開始するか**は、次のアクティブ／パッシブモードで変わります。

## 定義・仕組み

### 2種類のTCP接続

| 接続 | やり取りするもの | ポート番号の要点 |
|---|---|---|
| 制御接続（control connection） | ログイン情報、コマンド、応答 | FTPサーバ側の代表的なポートは**TCP/21** |
| データ接続（data connection） | ファイル内容、ディレクトリ一覧など | 接続モードで使い方が変わる。**TCP/20は主にアクティブモードのサーバ側送信元** |

制御接続はコマンドを交換する間、通常維持されます。データ接続は、ファイル転送や一覧取得の際に使います。どちらも**TCP**です。

### アクティブモード：サーバからデータ接続を開始

従来のアクティブモードでは、クライアントがデータ受信用のポートをサーバに知らせ、**サーバからクライアントへデータ接続を開始**します。

```text
[制御接続]
PC（一時ポート） ────────→ FTPサーバ：21/TCP

[データ接続の開始：アクティブモードの典型例]
PC（通知した受信用ポート） ←──── FTPサーバ：20/TCP
                               ↑
                         サーバ側の送信元
```

ここでの **20番はサーバ側の送信元ポート**です。「FTPなら通信先の宛先がいつも20番」という意味ではありません。転送するファイルの内容は双方向に流れ得るため、**接続の開始方向とデータの流れる方向も別物**です。

### パッシブモード：クライアントからデータ接続を開始

パッシブモードでは、サーバがデータ接続用の待受ポートを知らせ、**クライアントからサーバへ接続**します。

```text
[制御接続]
PC（一時ポート） ────────→ FTPサーバ：21/TCP

[データ接続の開始：パッシブモード]
PC（別の一時ポート） ───→ FTPサーバ：通知されたポート
                              （例：50010/TCP）
```

この「50010」は仕組みを説明するための**仮の番号**です。パッシブモードのデータ接続先が常に50010番になるわけではありません。

| 比較 | アクティブモード | パッシブモード |
|---|---|---|
| データ接続を開始する側 | FTPサーバ | FTPクライアント |
| サーバ側のデータ接続ポート | 伝統的には送信元TCP/20 | サーバが通知する待受ポート |
| 接続を考える際の注目点 | クライアント側への新規接続 | クライアント側からの新規接続 |

ファイアウォールやNATがある環境では、クライアント側への新規接続を必要としないパッシブモードが扱いやすい場合があります。

## 科目Aでどう出る？

### まず「何をしているプロトコルか」を区別する

ポート番号を思い出す前に、通信の**目的**を見ると選択肢を絞れます。

| プロトコル | 主な役割 | 代表的なポート |
|---|---|---|
| FTP | ファイル転送 | 制御TCP/21、アクティブモードのデータ接続でTCP/20 |
| SMTP | メールの送信・転送 | TCP/25（サーバ間転送など） |
| POP3 | メールの受信 | TCP/110 |
| SNMP | ネットワーク機器などの監視・管理 | UDP/161（要求・応答）、UDP/162（通知受信） |

この表は**代表例**です。SMTPのメール投稿にはTCP/587など、暗号化された別方式には別のポートもあります。SNMPでも通知方式や構成によって扱いが異なる場合があります。

**「ファイルを転送する」「指示とデータ用に接続を分ける」→ FTP**、と用途から判断するのが基本です。

### 20番と21番の覚え方

- **21番：指示や応答をやり取りする制御接続**
- **20番：従来のアクティブモードでのデータ接続のサーバ側送信元**
- **パッシブモード：データ接続はサーバが通知したポートへ接続**

「FTP＝20と21」を暗記するだけでなく、**どの接続の、どちら側のポートなのか**まで確認しましょう。

## どんな場面で使う？

FTPでサーバ上のファイル一覧を取得し、必要なファイルをダウンロードする場面を考えます。

1. クライアントが**制御接続**を確立してログインする。
2. 制御接続で一覧取得やファイル取得を指示する。
3. **データ接続**を使って一覧やファイル本体を転送する。
4. 制御接続では処理結果などの応答を受け取る。

標準のFTPは**パスワードや転送内容を暗号化しません**。実務で機密データを扱う場合は、SFTP（SSHベース）やFTPS（FTPをTLSで保護）など、適切な安全な転送方法を検討します。**SFTPはFTPと同じプロトコルではありません**。

## よくある誤解・混同

### 「FTPのデータ転送ポートは常に20番」

誤りです。TCP/20は従来の**アクティブモード**で用いられる代表例です。パッシブモードのデータ接続はサーバが通知したポートへクライアントが接続します。

### 「20番と21番は送信元・宛先に必ず一つずつ入る」

誤りです。制御接続とデータ接続は**別々のTCP接続**です。制御接続ではサーバ側TCP/21を利用し、アクティブモードのデータ接続ではサーバ側の送信元TCP/20が典型です。

### 「FTPではファイル転送も制御接続だけで行う」

誤りです。FTPではコマンド用の制御接続とは別に、データ接続を設けます。

### 「FTPとSFTPは同じ仕組み」

誤りです。SFTPはSSHを利用する別のプロトコルです。FTPSはFTPをTLSで保護します。

## まとめ（試験直前用）

- FTPは**ファイル転送**を行うプロトコル。
- **制御接続**はログイン・コマンド・応答に使い、サーバ側は通常**TCP/21**。
- **データ接続**はファイル内容や一覧などに使う。
- 従来の**アクティブモード**では、サーバが**TCP/20を送信元**としてデータ接続を開始する。
- **パッシブモード**では、クライアントがサーバから通知されたポートへデータ接続を開始する。
- 「20番は常にデータ転送先の宛先ポート」と考えない。

## 確認問題

あるファイル転送システムでは、コマンドの送受信とファイル本体の転送で別々のTCP接続を利用する。この仕組みの説明として最も適切なものはどれか。

- ア：制御接続とデータ接続は、必ず両方ともサーバ側TCP/21へ接続する。
- イ：FTPの制御接続は通常サーバ側TCP/21を利用し、データ接続の開始方向は接続モードによって異なる。
- ウ：パッシブモードでは、FTPサーバが必ずTCP/20からクライアントへデータ接続を開始する。
- エ：標準FTPでは、制御接続とデータ接続の内容が必ず暗号化される。

**正解：イ**

- **ア**：データ接続は制御接続と別です。両方がサーバ側TCP/21を使うわけではありません。

- **エ**：標準FTP自体には暗号化がありません。安全な転送方式との違いに注意します。
