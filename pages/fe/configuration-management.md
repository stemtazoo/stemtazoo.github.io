## まず結論

**構成管理は、ソフトウェアを構成する成果物について「何を・どの版で・どの組合せで使っているか」を識別し、変更を管理する考え方**です。

FE科目Aでは、まず次の言葉で切り分けます。

```text
版・バージョン・変更履歴
→ 構成管理

進み具合
→ 進捗管理

レビュー・品質
→ 品質管理

人・組織
→ 組織管理
```

特に **「プログラムのバージョン」** が出てきたら、構成管理を疑います。

ただし、**構成管理＝バージョン管理だけ**ではありません。

例えば「システム v2.0」を再現したいとき、プログラムAだけの版が分かっても十分ではありません。

**そのシステムを構成していた各成果物の版や組合せが分かること**が重要です。

## 定義・仕組み

### 構成品目とは

構成管理の対象として識別・管理するものを、構成品目として考えます。

例えば次のような成果物です。

- ソースコード
- プログラム
- ライブラリ
- 設定ファイル
- 設計書
- マニュアル

試験では「プログラムだけを管理する」と狭く考えないことがポイントです。

### 構成管理で何をする？

構成管理では、対象となる成果物を識別し、その版や変更を追跡できるようにします。

```text
何を管理する？
↓
構成品目を識別

どの版？
↓
バージョンを管理

何が変わった？
↓
変更履歴を管理

どの組合せ？
↓
システムの構成を把握
```

これによって「現在のシステムが、どの成果物のどの版で構成されているか」を確認しやすくなります。

### バージョン管理との違い

バージョン管理は、ファイルなどの変更履歴や版を管理する仕組みです。

構成管理では、それに加えて**複数の構成品目の関係や組合せ**まで考えます。

```text
バージョン管理
→ このファイルは何版？

構成管理
→ このシステムは
   何の何版を組み合わせたもの？
```

Gitはバージョン管理に使われる代表的なツールですが、**Gitそのものと構成管理は同じ意味ではありません。**

### ベースライン

開発では、ある時点で承認された構成を基準として扱うことがあります。これをベースラインと呼びます。

```text
承認された構成
↓
基準として固定
↓
変更するときは変更管理
```

「好きなときに自由に書き換える」のではなく、基準となる構成を明確にして変更を追跡することが大切です。

## 科目Aでどう出る？

科目Aでは、構成管理そのものの定義だけでなく、別の管理活動と混ぜた選択肢が出やすいテーマです。

| 問題文のキーワード | 判断 |
|---|---|
| プログラムの版、バージョン | 構成管理 |
| 構成品目の組合せ | 構成管理 |
| 変更内容・変更履歴 | 構成管理 |
| 作業の進み具合 | 進捗管理 |
| レビュー結果、品質 | 品質管理 |
| 人員配置、組織編成 | 組織管理 |

試験では、**「何を管理しているのか」**を先に探すと選択肢を切りやすくなります。

```text
版？
→ 構成管理

進捗？
→ 進捗管理

品質？
→ 品質管理

人？
→ 組織管理
```

## 科目Bでどう使う？

科目Bでは「構成管理」という用語を直接答えるより、開発や変更の場面を読むための前提知識として役立ちます。

例えば、障害修正後に以前の版へ戻す必要がある場面では、どのファイルをどの状態へ戻すのかが分からなければ安全に復元できません。

```text
変更前の状態を識別できる
↓
変更内容を追跡できる
↓
必要なら以前の構成を確認できる
```

## どんな場面で使う？

複数人で開発したり、複数の版を保守したりするときに重要になります。

例えば、利用者から「本番環境だけ不具合が出る」と報告された場合です。

```text
本番環境
A v3.1 + B v1.5

テスト環境
A v3.2 + B v1.5
```

このように構成が違えば、同じソフトウェア名でも動作が異なる可能性があります。

構成を記録しておけば、環境差を確認する手掛かりになります。

## よくある誤解・混同

### 構成管理と進捗管理

```text
何％終わった？
いつ終わる？
→ 進捗管理

どの版を使っている？
→ 構成管理
```

### 構成管理と品質管理

レビュー結果や不具合件数など、成果物の品質を見ること自体は構成管理の中心ではありません。

```text
品質はどうか？
→ 品質管理

どの成果物のどの版か？
→ 構成管理
```

### 構成管理とバージョン管理

**バージョン管理は構成管理を支える重要な要素ですが、構成管理の方が見る範囲が広い**と考えると整理しやすくなります。

### Gitを使えば構成管理は完了？

Gitでソースコードの変更履歴を管理することは有効ですが、構成管理では設定ファイル、ライブラリ、文書、リリース時の組合せなども対象になり得ます。

```text
Gitを使う
≠
構成管理のすべてが自動的に完了
```

## 確認問題

次のうち、構成管理の対象として最も直接的なものはどれでしょうか。

1. 開発チームの作業消化率
2. プログラムのバージョン
3. レビューで発見した指摘件数
4. プロジェクトメンバーの役割分担

<details>
<summary>答えを見る</summary>

正解は **2** です。

```text
作業消化率 → 進捗管理
バージョン → 構成管理
レビュー結果 → 品質管理
役割分担 → 組織管理
```

</details>

## まとめ（試験直前用）

- 構成管理は「何を・どの版で・どの組合せで使うか」を管理する
- 「版・バージョン・変更履歴」が出たら構成管理を疑う
- 進み具合は進捗管理、レビュー結果は品質管理、人の編成は組織管理
- バージョン管理は構成管理を支える要素だが、両者は同じ意味ではない
- プログラムだけでなく、設定ファイル・ライブラリ・設計書なども構成品目になり得る
