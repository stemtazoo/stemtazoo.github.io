## まず結論

**スコープとは、プロジェクトで「何を実現し、どこまでを対象にするか」という範囲**です。

基本情報技術者試験では、**成果物・要求事項・作業範囲・境界を明確にする**ならスコープの定義、**範囲の変更を確認して管理する**ならスコープの管理、と判断します。

> 「何をどこまでやる？」ならスコープ。「起こるかもしれない問題にどう備える？」ならリスク。

## 直感的な説明

社内でデータ分析ツールを開発するとします。

最初に、次の機能を作ると決めました。

~~~text
今回の開発範囲
├─ CSVファイルを読み込む
├─ グラフを表示する
└─ レポートを出力する

今回の開発範囲に含めない
└─ AIによる将来予測
~~~

このように**含めるものと含めないものを明確にする**のが、スコープを定義するイメージです。

開発途中で「AI予測機能も追加したい」と言われたら、すぐに作業を増やすのではなく、納期・費用・必要な作業などへの影響を確認して、変更を認めるか判断します。

これが**スコープの変更管理**です。

## 定義・仕組み

### スコープの定義

スコープの定義では、プロジェクトの目標、成果物、要求事項、境界などを明確にします。

| 確認すること | データ分析ツールの例 |
|---|---|
| 成果物 | 動作する分析ツール |
| 要求事項 | CSVを読み込み、グラフを表示できる |
| 範囲 | 読み込み・グラフ・レポート機能 |
| 範囲外 | AI予測機能 |

ここで大切なのは、**成果物の範囲**と、それを作るための**作業の範囲**の両方を意識することです。

### スコープの管理

スコープを決めた後も、要求が追加・変更されることがあります。

~~~text
変更要求が出る
      ↓
スコープへの影響を確認する
      ↓
納期・費用・品質・リスクなどを検討する
      ↓
変更を承認するか判断する
      ↓
承認した内容を計画へ反映する
~~~

**変更を一切認めないことがスコープ管理ではありません。** 必要な変更を適切に判断し、無秩序な範囲拡大を防ぐことが重要です。

このように要求が次々と追加され、範囲が管理されないまま広がることを、**スコープクリープ**と呼びます。

## 科目Aでどう出る？

科目Aでは、説明文がどのマネジメント対象に当たるかを問われます。

| 問題文の手掛かり | 判断 |
|---|---|
| 目標、成果物、要求事項、境界を明確にする | **スコープ** |
| 作業範囲の変更を管理する | **スコープ** |
| 情報を誰に、いつ、どう伝えるか | コミュニケーション |
| 外部から製品・サービスを入手する | 調達 |
| 不確実な事象を特定し、対応を考える | リスク |

### 「機会」「脅威」が出たら必ずリスク？

そうとは限りません。

例えば、スコープ変更によって生じる機会を生かし、脅威となる影響を抑える、という説明なら、**管理の中心はスコープの変更**です。

一方、将来起こるかもしれない不確実な事象を洗い出し、発生確率や影響を評価するなら、**リスクマネジメント**です。

**一つの単語だけで選ばず、何を管理するための活動かを確認する**のが判断のコツです。

## どんな場面で使う？

例えば、当初予定していなかった「スマートフォン対応」を顧客から追加で求められた場合です。

担当者がその場で引き受けると、開発工数や納期が想定より増える可能性があります。

スコープ管理では、追加機能の必要性を確認し、費用・納期・他の成果物への影響を検討してから変更を判断します。

プロジェクトマネジメントの規格やガイドには版による構成・用語の違いがあります。古い過去問で扱われる JIS Q 21500 の対象群と、現在の規格・ガイドの分類を、そのまま同一視しないようにします。

FE試験の最新の出題範囲は、[IPA：試験要綱・シラバス](https://www.ipa.go.jp/shiken/syllabus/gaiyou.html)で確認できます。

## よくある誤解・混同

**誤解1：スコープは作業の一覧だけを指す**

→ 作業だけでなく、成果物や要求事項、範囲の境界も関係します。

**誤解2：スコープ管理とは変更を禁止すること**

→ 変更の影響を評価し、適切な手続で判断することです。

**誤解3：「脅威」「機会」という語があれば必ずリスク**

→ 何を対象に管理しているかで判断します。スコープ変更の影響を管理する話ならスコープです。

**誤解4：スコープとWBSは同じもの**

→ スコープはプロジェクトの対象範囲、WBSは成果物や作業を管理しやすい単位へ分解したものです。

## まとめ（試験直前用）

- **成果物・要求事項・境界を決める → スコープの定義**
- **範囲の追加・変更を管理する → スコープの管理**
- **不確実な事象そのものを管理する → リスク**
- **「機会」「脅威」だけで判断せず、管理対象を読む**
