## まず結論

マッシュアップとは、**公開されている複数のWebサービスやAPIを組み合わせて、新しいサービスを提供する考え方**です。

基本情報技術者試験では、次のように判断すると選択肢を切りやすいです。

```text
公開されている複数のサービスを利用する
↓
組み合わせて新しいサービスを作る
→ マッシュアップ
```

試験で**「公開されている複数のサービスを利用して、新たなサービスを提供する」**と説明されたら、マッシュアップを選びます。

## 直感的な説明

マッシュアップは、料理でいうと**既にある食材やソースを組み合わせて、新しい料理を作る**イメージです。

```text
地図サービス
+
店舗情報サービス
+
口コミサービス
↓
周辺のお店を地図上に表示するサービス
```

全部を一から作るのではなく、既存の公開サービスを組み合わせて別の価値を作るのがマッシュアップです。

## 定義・仕組み

マッシュアップは、複数のWebサービスやAPIを組み合わせて、新しいアプリケーションやサービスを作る開発の考え方です。

| 用語 | 意味 |
|---|---|
| Webサービス | Web経由で利用できるサービス |
| Web API | 他のシステムから機能やデータを利用するための窓口 |
| マッシュアップ | 複数の公開サービスやAPIを組み合わせる考え方 |
| 新サービス | 組み合わせによって提供される新しい価値 |

例えば、天気情報API、地図API、交通情報APIを組み合わせると、移動計画を支援するサービスを作れます。

```text
天気情報 + 地図情報 + 交通情報
↓
外出に便利な案内サービス
```

このテーマは、基本情報技術者試験の「ストラテジ系」や「システム活用」「Webサービス」と関係する内容です。公式の出題範囲やシラバスは、[IPA：基本情報技術者試験](https://www.ipa.go.jp/shiken/kubun/fe.html) から確認できます。

## Web APIとの関係

マッシュアップでは、Web APIがよく使われます。

ただし、マッシュアップとWeb APIは同じ意味ではありません。

| 用語 | 位置づけ | ざっくり |
|---|---|---|
| Web API | 機能やデータを利用するための窓口 | 部品を呼び出す入口 |
| マッシュアップ | 複数のサービスを組み合わせる考え方 | 組み合わせて新サービスを作る |
| JSON | APIでやり取りされるデータ形式の一つ | データの形 |

```text
Web API
→ 使うための窓口

マッシュアップ
→ 複数の窓口を組み合わせて新サービスを作る
```

## 3種類のマッシュアップを切り分ける

マッシュアップは、**どのように複数のWebサービスを組み合わせるか**によって、次の3種類に整理できます。

| 種類 | 何を組み合わせる？ | 判断の合図 |
|---|---|---|
| プレゼンテーションマッシュアップ | 複数サービスの表示内容 | 画面上に別サービスの内容を表示 |
| データマッシュアップ | 複数サービスから取得したデータ | データを集めて統合・加工 |
| ロジックマッシュアップ | 複数サービスの入出力処理 | あるサービスの出力を別サービスの入力へつなぐ |

FE試験では、用語の定義だけでなく、**具体例からどの種類かを判断する問題**にも注意します。

### プレゼンテーションマッシュアップ

複数のWebサービスが提供するコンテンツを、1つの画面上にまとめて表示する方式です。

```text
店舗情報ページ
+
外部の地図サービス
↓
店舗の場所を地図付きで表示
```

判断のポイントは、**表示内容を組み合わせている**ことです。

### データマッシュアップ

複数のWebサービスからデータを取得し、それらを統合・加工して利用する方式です。

```text
複数の経済指標サービス
↓
データを取得・統合
↓
1つのグラフとして表示
```

判断のポイントは、**複数のデータを集めて統合・加工している**ことです。

### ロジックマッシュアップ

複数のWebサービスの入出力処理を連結し、一連の処理として利用する方式です。

```text
宿泊施設検索サービス
↓
宿泊施設の一覧を取得
↓
空室検索サービスへ入力
↓
空室状況を取得
```

ここでは、1つ目のサービスの出力を、2つ目のサービスの入力として利用しています。

試験では、次の形を見つけるとロジックマッシュアップを判断しやすくなります。

```text
サービスAの出力
↓
サービスBの入力
→ ロジックマッシュアップ
```

### 3種類を一気に切り分ける

```text
画面に別サービスの内容を載せる
→ プレゼンテーション

複数のデータを集めて統合・加工する
→ データ

Aの出力をBの入力につないで処理する
→ ロジック
```

「複数のWebサービスを使っている」だけでは、3種類のどれかまでは決まりません。**表示・データ・処理のどこを組み合わせているか**を確認します。

## 科目Aでどう出る？

科目Aでは、まずマッシュアップそのものを他の用語と切り分ける問題があります。

| 問題文の表現 | 選びたい用語 |
|---|---|
| 公開されている複数のサービスを利用して新サービスを提供する | マッシュアップ |
| 既存プログラムから仕様を導き出す | リバースエンジニアリング |
| 既存プログラムを部品化して組み合わせる | コンポーネント指向 |
| クラスライブラリを利用して開発する | ライブラリ利用・オブジェクト指向の文脈 |

決め手は、**公開されている複数のサービス**です。

```text
公開サービス + 組み合わせ + 新サービス
→ マッシュアップ
```

さらに、具体的な利用例からマッシュアップの種類を問われる場合は、次の順で考えると切り分けやすくなります。

```text
1. 複数のWebサービスを組み合わせているか？
   ↓ Yes
2. 何を組み合わせているか？
   ├─ 表示 → プレゼンテーション
   ├─ データ → データ
   └─ 入出力処理 → ロジック
```

### 「組み合わせる」だけで決めない

選択肢に「組み合わせる」と書かれていても、対象が異なれば別の用語です。

```text
公開Webサービスを組み合わせる
→ マッシュアップ

プログラム部品を組み合わせる
→ コンポーネント指向

既存プログラムから仕様を調べる
→ リバースエンジニアリング
```

### Ajaxとの違いにも注意

Web画面の一部だけを更新する説明は、マッシュアップではなくAjaxの文脈です。

```text
複数のWebサービスを組み合わせる
→ マッシュアップ

ページ全体を再読込みせず、一部分だけ更新する
→ Ajax
```

地図をドラッグしたときにページ全体を読み直さず、地図部分だけを更新するような説明なら、Ajaxを疑います。

## どんな場面で使う？

マッシュアップは、外部サービスの機能やデータを活用し、短期間で新しいサービスを作る場面で使われます。

例えば、次のような組合せです。

- 地図サービス + 店舗情報
- 予約情報 + 外部決済サービス
- 天気情報 + 交通情報

外部APIを利用するため、次の点も考慮します。

- 認証方法
- APIの利用制限
- 外部サービスの停止
- 仕様変更
- 利用規約や料金

ただし、FE試験では運用上の詳細より、**複数の公開サービスを組み合わせて新しい価値を作る**という定義が中心です。

## よくある誤解・混同

| 混同 | 正しい切り分け |
|---|---|
| マッシュアップは仕様を解析すること | 仕様を導き出すのはリバースエンジニアリング |
| マッシュアップはプログラム部品を組み合わせるだけ | 公開WebサービスやAPIを組み合わせる文脈で出やすい |
| マッシュアップとWeb APIは同じ | Web APIは窓口。マッシュアップは複数サービスを組み合わせる考え方 |
| プレゼンテーション・データ・ロジックは同じ | 表示・データ・入出力処理のどこを組み合わせるかで異なる |
| 画面の一部更新はマッシュアップ | ページ全体を再読込みせず一部更新するのはAjaxの文脈 |
| マッシュアップはクラスライブラリ利用のこと | クラスライブラリ利用はプログラム部品利用の文脈 |

特に、次の切り分けが重要です。

```text
既存プログラムから仕様を調べる
→ リバースエンジニアリング

プログラム部品を組み合わせる
→ コンポーネント指向

公開Webサービスを組み合わせる
→ マッシュアップ
```

## さらに注意したいひっかけ

| ひっかけ表現 | なぜ注意する？ |
|---|---|
| 既存プログラムから仕様を導く | リバースエンジニアリングの説明 |
| 既存プログラムを部品化する | コンポーネント指向の説明 |
| クラスライブラリを使う | ライブラリ利用・オブジェクト指向の説明 |
| 公開サービスを1つだけ単独で使う | マッシュアップでは複数サービスの組合せが中心 |
| サービスの仕様を逆解析する | マッシュアップではなく解析・調査の話 |
| 別サービスの内容を画面に表示する | プレゼンテーションマッシュアップ |
| 複数サービスのデータを統合する | データマッシュアップ |
| サービス同士の入出力をつなぐ | ロジックマッシュアップ |
| ページの一部だけを再読込みする | Ajaxの説明 |

## まとめ（試験直前用）

- マッシュアップは、公開されている複数のWebサービスやAPIを組み合わせて新サービスを提供する考え方
- まず「公開サービス」「複数」「新サービス」でマッシュアップかどうかを判断する
- 表示を組み合わせる → プレゼンテーションマッシュアップ
- データを統合・加工する → データマッシュアップ
- サービスAの出力をサービスBの入力へつなぐ → ロジックマッシュアップ
- ページ全体を再読込みせず一部だけ更新する → Ajax
- 既存プログラムから仕様を導くのはリバースエンジニアリング
- 既存プログラムを部品化して組み合わせるのはコンポーネント指向
- Web APIは利用する窓口、マッシュアップは組み合わせて新サービスを作る考え方
