## まず結論

キャッシュメモリは、**CPUがよく使うデータや命令を一時的に保存し、主記憶へのアクセス回数を減らす高速なメモリ**です。

基本情報技術者試験では、まず次の2点を押さえると選択肢を切りやすくなります。

> **キャッシュメモリは、CPUと主記憶の速度差を埋める。**

さらに書込み方式では、次の切り分けが重要です。

- **キャッシュと主記憶の両方へ書く** → ライトスルー
- **まずキャッシュだけへ書き、あとで主記憶へ反映する** → ライトバック

キャッシュメモリは、命令を並列に処理する装置でも、主記憶の容量不足を補う仕組みでもありません。

## 直感的な説明

CPUを作業する人、主記憶を遠くにある資料棚だと考えます。

必要な資料を使うたびに、毎回遠くの棚まで取りに行くと時間がかかります。

そこで、よく使う資料を机の上に置いておきます。

```text
遠くの資料棚 ＝ 主記憶
机の上       ＝ キャッシュメモリ
作業する人   ＝ CPU
```

一度取り出した資料を机の上に置いておけば、次に同じ資料が必要になったとき、すぐに使えます。

キャッシュメモリも同じように、主記憶から読み出したデータや命令の一部を保存しておきます。

書込み方式も、この「机」と「資料棚」で考えると分かりやすいです。

```text
ライトスルー
→ 机のメモを書き換えたら、資料棚の原本もすぐ直す

ライトバック
→ まず机のメモだけ直し、あとで原本へ反映する
```

## 定義・仕組み

キャッシュメモリは、CPUと主記憶の速度差を埋めるために使われます。

```text
CPU
 ↓ 高速
キャッシュメモリ
 ↓
主記憶
```

一般に、CPUは非常に高速に動作しますが、主記憶へのアクセスには比較的時間がかかります。

CPUが主記憶からデータを読み出すたびに待つと、処理効率が低下します。

そこで、使用したデータや命令をキャッシュメモリにコピーして保持します。

### キャッシュヒット

CPUが必要とする内容がキャッシュメモリにある場合を、**キャッシュヒット**といいます。

```text
CPUがデータを要求
→ キャッシュメモリにある
→ すぐに読み出せる
```

この場合、主記憶にアクセスする必要がないため、高速に処理できます。

### キャッシュミス

必要な内容がキャッシュメモリにない場合を、**キャッシュミス**といいます。

```text
CPUがデータを要求
→ キャッシュメモリにない
→ 主記憶から読み出す
→ キャッシュメモリにも保存する
```

最初のアクセスでは主記憶から読み出しますが、その後に同じ内容を使う場合は、キャッシュヒットになる可能性があります。

通常、この処理をアプリケーションプログラムが明示的に行うのではなく、キャッシュ制御の仕組みが処理します。

### 局所性

キャッシュメモリが効果を発揮する背景には、プログラムの**局所性**があります。

| 種類 | 意味 |
|---|---|
| 時間的局所性 | 一度使ったデータや命令は、近いうちに再び使われやすい |
| 空間的局所性 | ある場所を使うと、その近くの場所も使われやすい |

例えば、ループ処理では同じ命令を繰り返し実行するため、時間的局所性があります。

配列を先頭から順番に読む処理では、近くのデータを続けて使うため、空間的局所性があります。

### ライトスルー方式

**ライトスルー（write through）**は、CPUがデータを書き換えたときに、**キャッシュと主記憶の両方を更新する方式**です。

```text
CPUが書込み
   ↓
キャッシュ更新
   ↓
主記憶も更新
```

主記憶の内容が常に最新になりやすく、管理が比較的分かりやすいのが特徴です。

一方で、書込みのたびに主記憶へアクセスするため、主記憶への書込み回数は増えます。

### ライトバック方式

**ライトバック（write back）**は、CPUがデータを書き換えたときに、**まずキャッシュだけを更新する方式**です。

主記憶への反映は、そのキャッシュブロックが入れ替えられるときなど、後のタイミングで行います。

```text
CPUが書込み
   ↓
キャッシュだけ更新
   ↓
後で主記憶へ反映
```

主記憶への書込み回数を減らせる一方、キャッシュと主記憶の内容が一時的に異なるため、管理はライトスルーより複雑になります。

### ライトスルーとライトバックの比較

| 方式 | 書込み時 | 主記憶への反映 | 特徴 |
|---|---|---|---|
| ライトスルー | キャッシュと主記憶を更新 | その都度 | 管理しやすいが書込み回数が増える |
| ライトバック | キャッシュを更新 | 後で反映 | 書込み回数を減らせるが管理が複雑 |

### SRAMとDRAM

一般に、キャッシュメモリには高速な**SRAM**が使われ、主記憶には大容量化しやすい**DRAM**が使われます。

| 比較 | SRAM | DRAM |
|---|---|---|
| 主な用途 | キャッシュメモリ | 主記憶 |
| 速度 | 高速 | SRAMより低速 |
| 容量 | 小さめ | 大きくしやすい |
| 価格 | 高い | 比較的安い |
| リフレッシュ | 不要 | 必要 |

キャッシュメモリが小容量なのは、高速なSRAMが高価だからです。

このテーマは、基本情報技術者試験の「コンピュータ構成要素」や「メモリ」と関係する内容です。公式の出題範囲やシラバスは、[IPA：基本情報技術者試験](https://www.ipa.go.jp/shiken/kubun/fe.html)から確認できます。

## 科目Aでどう出る？

科目Aでは、キャッシュメモリの**役割・ヒット／ミス・書込み方式**を問う問題が出ます。

### 判断軸1：何の速度差を埋める？

キャッシュメモリが埋めるのは、基本的に

**CPUと主記憶の速度差**

です。

「実記憶と仮想記憶の容量差を埋める」という説明は、キャッシュメモリの説明ではありません。

### 判断軸2：ライトスルーとライトバック

次の言い換えを覚えておくと切りやすいです。

```text
キャッシュと主記憶を同時に更新
→ ライトスルー

キャッシュだけ更新し、あとで主記憶へ反映
→ ライトバック
```

特に、**「ブロックの入替え時に主記憶へ書き戻す」**という表現があれば、ライトバックを疑います。

名前からも判断できます。

- スルー → 主記憶までそのまま通して書く
- バック → あとから主記憶へ書き戻す

### 判断軸3：キャッシュミス時の動作

キャッシュに目的のデータがなければ、主記憶から必要なデータを取得してキャッシュへ読み込みます。

「キャッシュミスすると割込みが発生し、アプリケーションプログラムが主記憶から転送する」という説明は不適切です。

### 判断軸4：TLB・MMU・主記憶と混同しない

「高速化」という言葉だけでキャッシュメモリを選ばず、**何を高速化・管理するのか**を見ます。

| 用語 | 主な役割 | 問題文で注目する言葉 |
|---|---|---|
| キャッシュメモリ | CPUと主記憶の速度差を埋める | CPU、主記憶、速度差、再アクセス |
| TLB | 仮想アドレスから物理アドレスへの変換を高速化する | 仮想アドレス、物理アドレス、アドレス変換 |
| MMU | 仮想記憶やアドレス変換を管理する | メモリ管理、ページング、アドレス変換 |
| 主記憶 | 実行中のプログラムやデータを保持する | プログラム、データ、記憶 |

試験中は、次のように切ると分かりやすいです。

```text
CPUと主記憶の速度差
→ キャッシュメモリ

アドレス変換を高速化
→ TLB

仮想記憶・アドレス変換を管理
→ MMU

実行中のプログラムやデータを保持
→ 主記憶
```

### 正しい選択肢の見分け方

次のような表現があれば、キャッシュメモリの説明である可能性が高いです。

- CPUと主記憶の速度差を埋める
- 主記憶から読み出した内容を一時的に保持する
- 再アクセスを高速化する
- 主記憶へのアクセス回数を減らす
- ヒット率が高いほど平均アクセス時間が短くなる
- ライトスルーでは主記憶も同時に更新する
- ライトバックでは主記憶への反映を後で行う

### 平均アクセス時間

問題によっては、キャッシュメモリを使ったときの平均アクセス時間を計算します。

基本的な考え方は次のとおりです。

```text
平均アクセス時間
＝ ヒットした場合の時間
＋ ミスした場合の時間
```

ヒット率が高いほど、主記憶へアクセスする回数が減るため、平均アクセス時間は短くなります。

ただし、計算式は問題文で示される条件によって変わることがあります。キャッシュと主記憶を直列に調べるのか、別の前提があるのかを確認してから計算します。

## どんな場面で使う？

キャッシュメモリは、CPUの処理速度を生かすために使われます。

例えば、同じ命令を何度も実行するループ処理では、命令がキャッシュメモリに保持されやすくなります。

```text
同じ命令を繰り返す
→ キャッシュヒットしやすい
→ 主記憶へのアクセスが減る
→ 処理が速くなる
```

配列を順番に処理する場合も、近くのデータをまとめて読み込むことでキャッシュが働きやすくなります。

一方、広い範囲のデータへばらばらにアクセスすると、必要なデータがキャッシュに残りにくく、キャッシュミスが増えることがあります。

実際のCPUでは、L1・L2・L3のように複数段階のキャッシュを持つ構成も一般的です。

```text
CPU
↓
L1キャッシュ
↓
L2キャッシュ
↓
L3キャッシュ
↓
主記憶
```

FE試験では細かな製品仕様よりも、**高速だが小容量の記憶を間に置いて平均アクセス時間を短くする**という役割を押さえておくことが重要です。

## よくある誤解・混同

### キャッシュと仮想記憶の違い

```text
キャッシュ
→ CPUと主記憶の速度差を埋める

仮想記憶
→ 主記憶だけでは足りないメモリ空間を補う
```

「速度差」と「容量」を混同しないようにします。

### キャッシュとTLBの違い

どちらもCPUの処理を速くするために使われますが、保存しているものの役割が違います。

```text
キャッシュメモリ
→ よく使うデータや命令を保持
→ 主記憶へのアクセスを減らす

TLB
→ アドレス変換の結果を保持
→ 仮想アドレスから物理アドレスへの変換を速くする
```

問題文に「仮想アドレス」「物理アドレス」「アドレス変換」が出てきたら、キャッシュメモリではなくTLBを疑います。

### キャッシュとMMUの違い

MMUは、メモリ管理やアドレス変換を担当する仕組みです。

```text
キャッシュメモリ
→ データアクセスを速くする

MMU
→ 仮想記憶・アドレス変換を管理する
```

「高速な一時記憶」か「メモリ管理」かで切り分けます。

### キャッシュミスは割込みではない

キャッシュミス時には主記憶からデータを読み込みますが、通常のキャッシュミスをアプリケーション側の割込み処理で対応するとは考えません。

### ライトスルーとライトバックを逆にしない

| 誤解 | 正しい理解 |
|---|---|
| ライトスルーはキャッシュだけ更新する | 主記憶もその都度更新する |
| ライトバックは主記憶も毎回更新する | まずキャッシュだけ更新し、後で書き戻す |

### キャッシュは現在でも重要

半導体メモリの性能は向上していますが、CPUの高速化も進んでいるため、CPUと主記憶の速度差を埋めるキャッシュメモリは現在でも重要です。

### キャッシュとバッファの違い

キャッシュとバッファは、どちらも一時的にデータを保持しますが、目的が異なります。

```text
キャッシュ
→ 同じデータの再利用を高速化する

バッファ
→ 処理速度や転送単位の違いを調整する
```

試験では、「再利用」「再アクセス」「同じデータ」という表現があればキャッシュを疑います。

## まとめ（試験直前用）

- キャッシュメモリは **CPUと主記憶の速度差を埋める**。
- **アドレス変換の高速化 → TLB、仮想記憶・アドレス変換の管理 → MMU**。
- データがキャッシュにある → **キャッシュヒット**、ない → **キャッシュミス**。
- **キャッシュと主記憶の両方へ書く → ライトスルー**。
- **キャッシュだけ更新し、あとで主記憶へ書く → ライトバック**。
- 「容量差を埋める」と「速度差を埋める」を混同しない。
