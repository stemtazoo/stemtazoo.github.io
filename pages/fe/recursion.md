## まず結論

再帰処理とは、**関数の中から自分自身を呼び出す処理**です。

基本情報技術者試験では、再帰そのものの定義よりも、**「再帰呼び出しの前」と「再帰呼び出しの後」で処理されるタイミングが違う**ことを理解しているかが重要です。

試験中は、次のように切り分けると追いやすくなります。

```text
再帰呼び出しより前の処理 → 奥へ進むときに実行
再帰呼び出し             → さらに奥へ進む
再帰呼び出しより後の処理 → 戻ってくるときに実行
```

この「行き」と「戻り」を分けて考えるのが最大のポイントです。

---

## 直感的な説明

例えば、次のような処理を考えます。

```text
function f() {
    行きの処理
    f()
    戻りの処理
}
```

このとき、最初の `f()` がすぐに最後まで終わるわけではありません。

途中で再び `f()` を呼ぶので、処理はいったん奥へ進みます。

イメージは次のとおりです。

```text
1回目 f()
  ↓
2回目 f()
  ↓
3回目 f()
  ↓
終了条件
  ↑
3回目の残りを実行
  ↑
2回目の残りを実行
  ↑
1回目の残りを実行
```

つまり、再帰処理は

> **先に奥まで進み、あとから逆向きに戻る**

と考えると分かりやすくなります。

英語では、再帰呼び出しより前を **before recursion**、後を **after recursion** と分けて考えると整理しやすいです。

## 定義・仕組み

### 再帰処理には終了条件が必要

再帰関数には、必ず処理を止める条件が必要です。

例えば次のような形です。

```text
function f(n) {
    if n == 0 {
        return
    }

    f(n - 1)
}
```

`n == 0` が終了条件です。

これがないと、自分自身を呼び続けることになり、最終的にはコールスタックを使い切ってエラーになる可能性があります。

スタックそのものについては、[スタックとは？LIFO・push・popの考え方](/fe/stack/)も確認してください。

### 再帰呼び出しの前後で実行タイミングが違う

次の例を見てみます。

```text
function f(n) {
    if n == 0 {
        return
    }

    print(n)
    f(n - 1)
    print(n)
}
```

`f(3)` を実行すると、最初の `print(n)` は奥へ進むときに実行されます。

```text
3
2
1
```

一方、再帰呼び出しの後ろにある `print(n)` は、戻ってくるときに実行されます。

```text
1
2
3
```

全体では、次の順になります。

```text
3
2
1
1
2
3
```

ここが、再帰問題で最も混乱しやすい部分です。

## どんな場面で使う？

再帰処理は、同じ構造を繰り返し処理する問題で使われます。

代表例は次のとおりです。

- 木構造の探索
- フォルダ階層の探索
- 階乗の計算
- 深さ優先探索
- 分割統治法

基本情報技術者試験では、実際に再帰関数を書くよりも、**与えられた処理をトレースする問題**として出ることが多いです。

### 複数のスタックと再帰を組み合わせる場合

例えば、次の処理を考えます。

```text
function f() {
    if A is empty {
        return
    }

    Aからpopした値をCへpushする
    f()
    Cからpopした値をBへpushする
}
```

この場合、再帰呼び出しより前では、AからCへ値を移します。

```text
before recursion
A → C
```

Aが空になるまで奥へ進み、その後、戻るときにCからBへ値を移します。

```text
after recursion
C → B
```

例えば初期状態が次の場合、

```text
A = [1, 2, 3]
B = [1, 2, 3]
C = [1, 2, 3]
```

奥へ進む間は、Aの末尾から順番に `3 → 2 → 1` がCへ移動します。

```text
A = []
C = [1, 2, 3, 3, 2, 1]
```

その後、戻るときにCの末尾から `1 → 2 → 3` がBへ移ります。

```text
B = [1, 2, 3, 1, 2, 3]
```

ポイントは、**再帰呼び出しの後ろの処理を、すぐには実行しない**ことです。

## よくある誤解・混同

### 誤解1：コードは上から下まで毎回そのまま実行される

再帰呼び出しに到達すると、その時点で現在の関数はいったん中断されます。

```text
処理A
f()
処理B
```

なら、`処理B` はすぐには実行されません。

呼び出した `f()` が終了して戻ってきてから実行されます。

### 誤解2：再帰呼び出しの後ろの処理も「行き」で実行する

これは典型的なひっかけです。

```text
before recursion → 行き

after recursion  → 戻り
```

と分けてください。

### 誤解3：再帰とスタックは別物なので関係ない

再帰呼び出しでは、呼び出し元へ戻るための情報がコールスタックに積まれます。

そのため、再帰はスタックと強く関係しています。

ただし試験問題では、内部実装を細かく考えるよりも、**「どこまで進んで、どの順番で戻るか」**を追うことが重要です。

---

## まとめ（試験直前用）

- 再帰 = **関数の中から自分自身を呼び出す**
- 必ず **終了条件** を確認する
- 再帰呼び出しより前 = **行きで実行**
- 再帰呼び出しより後 = **戻りで実行**
- 処理を追うときは、まず奥まで進んでから逆向きに戻る
- スタック操作が含まれる場合も、`push` / `pop` の場所より先に **再帰の前後** を切り分ける

試験中に迷ったら、コードへ次の2つを書き込むだけでもかなり整理できます。

```text
before recursion

after recursion
```

再帰問題は、すべてを頭の中だけで追うより、呼び出し回数ごとに状態を書き出す方が安全です。
