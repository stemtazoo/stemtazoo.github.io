## まず結論

クリティカルパスとクリティカルチェーンの違いは、**資源制約まで考えるか**です。

```text
作業の前後関係と所要時間から最長経路を求める
→ クリティカルパス

人員・設備などの資源制約も考え、バッファで遅れを管理する
→ クリティカルチェーン
```

基本情報技術者試験では、用語名を丸暗記するより、**問題文が「経路」を見ているのか、「資源制約」を見ているのか**を確認します。

## 直感的な説明

例えば、作業Aと作業Bに前後関係がなく、同時に進められるとします。

```text
作業A ─────
作業B ─────
```

作業のつながりだけを見るなら、並行して進められます。

しかし、AとBを担当できる人が同じ1人だけなら、現実には同時に進められません。

```text
作業上は並行できる
        ↓
同じ担当者が必要
        ↓
同時にできない
```

この違いを考えるのが、クリティカルチェーン法です。

初心者向けには、次のように覚えると分かりやすいです。

```text
クリティカルパス
→ 作業の道順を見る

クリティカルチェーン
→ 作業の道順＋使える人や設備を見る
```

## 定義・仕組み

### クリティカルパス

クリティカルパスは、プロジェクトの開始から終了までの経路のうち、**所要時間の合計が最も長い経路**です。

その経路の長さが、プロジェクトを完了するために必要な最短所要期間を決めます。

詳しくは、[クリティカルパスとは？](/fe/critical-path/)で確認できます。

### クリティカルチェーン

クリティカルチェーン法では、作業の前後関係だけでなく、**人員・設備などの資源制約**も考慮してスケジュールを組みます。

さらに、遅れに備える余裕を**バッファ**として管理します。

詳しくは、[クリティカルチェーン法とは？](/fe/critical-chain/)で確認できます。

### 2つを比較する

| 見るポイント | クリティカルパス | クリティカルチェーン |
|---|---|---|
| 作業の前後関係 | 見る | 見る |
| 作業時間 | 見る | 見る |
| 最長経路 | 重視する | 土台として考える |
| 人員・設備の制約 | 中心ではない | **重視する** |
| バッファ | 中心ではない | **使って遅れを管理する** |
| 試験のキーワード | 最長経路、余裕時間 | 資源制約、バッファ |

このテーマは、基本情報技術者試験の「プロジェクトマネジメント」と関係する内容です。公式の出題範囲やシラバスは、[IPA：基本情報技術者試験](https://www.ipa.go.jp/shiken/kubun/fe.html) から確認できます。

## 科目Aでどう出る？

科目Aでは、問題文のキーワードからどちらの考え方かを判断します。

### 最長経路・余裕時間が中心

```text
開始から終了までの経路を比較する
最も長い経路を求める
余裕時間を求める
```

このような説明なら、クリティカルパスを疑います。

### 資源制約・バッファが中心

```text
同じ人員を複数作業で使う
設備を同時に使えない
資源の競合を考える
バッファで遅れを管理する
```

このような説明なら、クリティカルチェーンを疑います。

### 「資源」が出たらさらに切り分ける

資源という言葉だけでクリティカルチェーンと決めてはいけません。

```text
資源を追加して期間を短縮
→ クラッシング

限られた資源を考慮して計画
→ クリティカルチェーン
```

クラッシングとの違いは、[クラッシングとファストトラッキングの違い](/fe/crashing-vs-fast-tracking/)も確認すると整理しやすくなります。

## どんな場面で使う？

### クリティカルパスが役立つ場面

- プロジェクト全体の最短所要期間を求める
- 遅れると全体へ影響する作業を見つける
- どの経路が全体日程を決めているか確認する

### クリティカルチェーンが役立つ場面

- 同じ担当者を複数の作業で使う
- 同じ設備を複数作業で共有する
- 資源の取り合いで計画どおり進まない可能性がある
- 遅れをバッファでまとめて管理したい

つまり、

```text
作業のつながりを中心に見る
→ クリティカルパス

現実に使える人・設備まで見る
→ クリティカルチェーン
```

と考えます。

## よくある誤解・混同

### 「クリティカル」が付くので同じ意味？

同じではありません。

クリティカルパスは最長経路を中心に考えますが、クリティカルチェーンは資源制約まで考慮します。

### 資源を使う話ならクリティカルチェーン？

そうとは限りません。

```text
資源を増やす
→ クラッシング

資源が限られていることを考慮する
→ クリティカルチェーン
```

**追加するのか、制約として扱うのか**を確認します。

### クリティカルチェーンではクリティカルパスを考えない？

クリティカルチェーンは、作業の依存関係を無視する方法ではありません。

作業のつながりを考えた上で、さらに資源制約を加えて現実的なスケジュールを考えます。

### バッファ＝各作業を長めにする？

単純に各作業へ余裕時間を足すだけ、と覚えないようにします。

クリティカルチェーンでは、遅れに備える余裕をバッファとしてまとめて管理する考え方が重要です。

## まとめ（試験直前用）

- **最長経路・余裕時間**が中心ならクリティカルパス
- **資源制約・バッファ**が中心ならクリティカルチェーン
- クリティカルチェーンは、人員や設備の競合まで考える
- 資源を**追加**するのはクラッシング、資源を**制約として考える**のはクリティカルチェーン
- 迷ったら「経路だけを見ているか、使える人・設備まで見ているか」で切る
