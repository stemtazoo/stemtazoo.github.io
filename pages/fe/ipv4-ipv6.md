## まず結論

IPv4とIPv6は、**アドレスの長さと表記方法**で見分けると迷いにくくなります。

基本情報技術者試験では、まず次の対応を押さえます。

| 項目 | IPv4 | IPv6 |
|---|---|---|
| アドレス長 | 32ビット | 128ビット |
| 主な表記 | 10進数 | 16進数 |
| 区切り記号 | `.`（ドット） | `:`（コロン） |
| 表記例 | `192.168.1.10` | `2001:db8::1` |

試験中は、次の一言に置き換えると判断しやすくなります。

```text
32ビット・ドット区切り
→ IPv4

128ビット・コロン区切り
→ IPv6
```

## 直感的な説明

IPアドレスは、ネットワーク上の機器を識別するための「住所」のようなものです。

IPv4では32ビットで住所を表していましたが、インターネットの普及によって使えるアドレスが不足してきました。

そこで、より多くのアドレスを表せるようにしたのがIPv6です。

```text
IPv4
32ビット
↓
アドレス不足
↓
IPv6
128ビット
```

つまり、IPv6は単に数字が大きくなったのではなく、**利用できるIPアドレスの数を大幅に増やすためにアドレス長が拡張された**と考えると覚えやすくなります。

### 同じ尺度でアドレス長を比べる

長さは4倍ですが、表せる組合せの数は4倍ではありません。ビットが一つ増えるたびに組合せは2倍になるため、IPv4は **2の32乗**、IPv6は **2の128乗** 通りです。これはビット列としての総数で、すべてを通常の端末に割り当てられるという意味ではありません。

## 定義・仕組み

### IPv4

IPv4（Internet Protocol version 4）は、IPアドレスを**32ビット**で表します。

32ビットを8ビットずつ4つに分け、それぞれを10進数で表し、ドットで区切るのが一般的です。

```text
192.168.1.10

192 . 168 . 1 . 10
```

各部分は8ビットなので、0〜255の範囲になります。

```text
8ビット × 4
= 32ビット
```

FE試験では、IPv4について次の表現が手掛かりになります。

- 32ビット
- 10進数
- 8ビットずつ4つ
- ドット区切り

### IPv6

IPv6（Internet Protocol version 6）は、IPアドレスを**128ビット**で表します。

IPv6では、128ビットを16ビットずつ8つに分け、それぞれを16進数で表してコロンで区切ります。

```text
2001:0db8:0000:0000:0000:0000:0000:0001
```

つまり、

```text
16ビット × 8
= 128ビット
```

です。

FE試験では、IPv6について次の表現が手掛かりになります。

- 128ビット
- 16進数
- 16ビットずつ8つ
- コロン区切り

### IPv6では0を省略できる

IPv6はそのまま書くと長いため、表記を短くするルールがあります。

各16ビットの組の先頭の0は省略できます。また、連続する0の組をまとめて `::` と表せます。`::` は一つのアドレス内で1回だけ使えます。

```text
2001:0db8:0000:0000:0000:0000:0000:0001

↓

2001:db8::1
```

このため、IPv6のアドレスを見たときに「8ブロックないからIPv6ではない」と判断しないよう注意します。

### ネットワーク範囲はプレフィックス長で示す

IPアドレスのうち、先頭から何ビットをネットワークの識別に使うかを示すのが**プレフィックス長**です。

| 表記例 | 意味 |
|---|---|
| IPv4：`192.0.2.10/24` | 32ビット中、先頭24ビットがネットワークを識別する部分 |
| IPv6：`2001:db8:1234:5678::1/64` | 128ビット中、先頭64ビットがネットワークを識別する部分 |

IPv4の `/24` は、サブネットマスク `255.255.255.0` と同じ区切りを表します。IPv6では、このようなドット区切りのマスクではなく、通常 `/64` などのプレフィックス長で範囲を示します。

`/64` はIPv6でよく使われる例ですが、**IPv6のすべてのプレフィックスが64ビットとは限りません**。また、`/64` が付いてもアドレス全体の長さは128ビットのままです。

サブネットに分ける考え方自体はIPv4にもあります。「ネットワーク部分を区別するようになった」がIPv6だけの変更点とは判断しません。

### 固定長なのは基本ヘッダー

ヘッダーは、アドレスなど、パケットを届けるための制御情報を持つ部分です。IPv6の**基本ヘッダーは40バイトの固定長**です。必要に応じて、その後に拡張ヘッダーを付けられます。

したがって、「IPv6のヘッダーは固定長」と覚えるときは、**基本ヘッダーの話**だと押さえます。拡張ヘッダーを含むヘッダー全体や、パケット全体が常に40バイトという意味ではありません。

### IPv4とIPv6のアドレス数

IPv4は32ビットなので、理論上は次の数のアドレスを表せます。

```text
2^32
```

IPv6は128ビットなので、

```text
2^128
```

通りのアドレスを表せます。

試験では具体的な巨大な数を覚えるよりも、**IPv6はIPv4より非常に広いアドレス空間を持つ**と理解しておけば十分です。

このテーマは、基本情報技術者試験のネットワーク分野でIPアドレスや通信プロトコルを理解する基礎になります。公式の出題範囲やシラバスは、[IPA：基本情報技術者試験](https://www.ipa.go.jp/shiken/kubun/fe.html) から確認できます。

IPアドレスとMACアドレスの役割の違いは、[IPアドレスとMACアドレスの違いとは？ルータ経由の宛先を切り分ける](/fe/ip-mac-address-routing/)で整理しています。

## 科目Aでどう出る？

科目Aでは、IPv4とIPv6について**数字や表記方法を組み合わせて問う問題**が出ます。

まず、次の判断表で切り分けます。

| 問題文の表現 | 判断 |
|---|---|
| IPアドレスは32ビット | IPv4 |
| IPアドレスは128ビット | IPv6 |
| 10進数をドットで区切る | IPv4 |
| 16進数をコロンで区切る | IPv6 |
| `192.168.1.1` のような表記 | IPv4 |
| `2001:db8::1` のような表記 | IPv6 |

特に、

```text
IPv4 = 32
IPv6 = 128
```

はそのまま問われることがあるため、迷わず答えられるようにします。

### IPv6で変わった点か、IPv4にもある点か

「IPv4にはなく、IPv6で追加・変更された仕様」を問われたら、機能の有無だけでなく、**IPv4と比べて何が変わったか**を確認します。

| 説明 | 判断 |
|---|---|
| アドレス長を32ビットから128ビットへ拡張 | IPv6での変更点 |
| 基本ヘッダーを40バイトの固定長にした | IPv6での変更点。拡張ヘッダーは別 |
| サブネットマスクでネットワークを区切る | IPv4にもある。IPv6では通常プレフィックス長で範囲を示す |
| ネットワーク部分と端末を識別する部分を分ける | IPv4にもある考え方 |
| プライベートアドレスを使う | IPv4にもある。IPv6で初めて導入されたものではない |

IPv4のプライベートアドレスの範囲は、[IPv4のグローバルIP・プライベートIPの見分け方](/fe/ipv4-global-private-address/)で確認できます。

**アドレスを有効利用する工夫**と、**アドレスそのものを長くして空間を広げる変更**を分けるのがポイントです。サブネットマスクやプライベートアドレスという語だけでIPv6を選ばないようにします。

### 「64ビット」に引っ張られない

IPv6では、ネットワーク部分やインタフェース識別子を64ビットずつ扱う構成を目にすることがあります。

しかし、**IPv6アドレス全体の長さは128ビット**です。

問題文が「IPv6のIPアドレスは何ビットか」と聞いている場合は、128ビットを選びます。

## どんな場面で使う？

IPv4とIPv6は、どちらもネットワーク上で通信相手を識別し、パケットを届けるために使われます。

現在はIPv4とIPv6が併存しており、ネットワークやサービスによって利用状況が異なります。

FE試験では実務上の普及状況を細かく覚えるよりも、まず次の基礎を優先します。

```text
IPv4
→ 32ビット
→ ドット区切り

IPv6
→ 128ビット
→ コロン区切り
```

また、IPv6ではIPv4のARPをそのまま使うのではなく、近隣探索の仕組みが使われます。ARPとの関係は、[ARPとは？IPアドレスからMACアドレスを調べる仕組み](/fe/arp/)もあわせて確認すると理解しやすくなります。

## よくある誤解・混同

### IPv6はIPv4の2倍の長さ？

違います。

```text
IPv4 = 32ビット
IPv6 = 128ビット
```

なので、IPv6のアドレス長はIPv4の**4倍**です。

### IPv6は10進数で書く？

基本的には違います。

IPv6では16進数を使い、コロンで区切ります。

```text
IPv4
192.168.1.1

IPv6
2001:db8::1
```

### IPv6は必ず8ブロック全部を書く？

違います。

0が連続する部分などは省略表記を使えるため、短いIPv6アドレスもあります。

### IPv6ならARPを使う？

IPv4でIPアドレスからMACアドレスを調べる代表的な仕組みがARPです。

IPv6ではARPをそのまま使わず、近隣探索（Neighbor Discovery）の仕組みを利用します。

ネットワーク機器とIPアドレスの関係も整理したい場合は、[ルータ・リピータ・ブリッジ・スイッチングハブの違いとは？OSI参照モデルで見分ける方法](/fe/network-devices-router-repeater-bridge-switch/)も参考になります。

### IPv6なら自動的に暗号化される？

IPv6を使うだけで、通信が自動的に暗号化されるわけではありません。[IPsec](/fe/ipsec/)はIPv4でもIPv6でも使える仕組みであり、利用には適切な設定や鍵の管理が必要です。

IPv6ノード要件のRFC 8504では、IPsecのサポートは推奨（SHOULD）です。**サポートの要件と、実際の通信で暗号化を使っているかは別**に判断します。「IPv6だから必ず安全」とは考えません。

## 標準仕様で確認する

IPv6の基本仕様は、IETFのInternet Standardである **RFC 8200「Internet Protocol, Version 6 (IPv6) Specification」** で確認できます。

- [RFC 8200：Internet Protocol, Version 6 (IPv6) Specification](https://www.rfc-editor.org/info/rfc8200/)

RFC 8200では、IPv6がIPv4の後継として設計され、IPアドレスの大きさを **32ビットから128ビットへ拡張**したことが説明されています。

なお、IPv6アドレスの形式や表記規則そのものは、別の仕様であるRFC 4291で定義されています。

- [RFC 4291：IP Version 6 Addressing Architecture](https://www.rfc-editor.org/info/rfc4291/)

IPsecのサポート要件は、[RFC 8504：IPv6 Node Requirements（13.1節）](https://www.rfc-editor.org/rfc/rfc8504.html#section-13.1)で確認できます。

FE試験では、まず **IPv4＝32ビット、IPv6＝128ビット** を判断軸にし、IPv4にもある仕組みをIPv6だけの特徴として選ばないようにします。

## まとめ（試験直前用）

- IPv4は32ビット・10進数のドット区切り、IPv6は128ビット・16進数のコロン区切り
- IPv6のアドレス長は4倍だが、表せる組合せの数は4倍ではない
- サブネットやプライベートアドレスはIPv4にもあり、IPv6だけの導入事項ではない
- IPv6の基本ヘッダーは40バイト。プレフィックス長とアドレス全体の長さも区別する
- IPv6を使うだけで自動的に暗号化されるわけではない
