## まず結論

スクラムでは、スプリントの中で複数のイベントを使い分けます。

基本情報技術者試験では、**「いつ行うか」と「何を確認するか」**で切り分けると判断しやすいです。

```text
開始時に計画する
→ スプリントプランニング

毎日、進捗を確認・調整する
→ デイリースクラム

成果物を確認する
→ スプリントレビュー

進め方を振り返って改善する
→ スプリントレトロスペクティブ
```

特に、**毎日・短時間・進捗確認**が出てきたら、デイリースクラムを考えます。

## 直感的な説明

スクラムは、短い期間である「スプリント」を繰り返しながら開発を進める方法です。

1回のスプリントを、次のような流れで考えると分かりやすいです。

```text
スプリント開始
  ↓
スプリントプランニング
  ↓
毎日の開発
  └ デイリースクラム
  ↓
スプリント終了
  ├ スプリントレビュー
  └ スプリントレトロスペクティブ
```

つまり、

- 最初に計画する
- 毎日すり合わせる
- 最後に成果物を見る
- 最後に進め方を振り返る

という役割分担です。

## 定義・仕組み

### スプリントプランニング

スプリントの開始時に行うイベントです。

そのスプリントで、

- 何を実現するか
- どの作業に取り組むか
- どのように進めるか

を整理します。

試験では、

```text
スプリントの開始時
作業計画を決める
```

とあれば、スプリントプランニングを考えます。

### デイリースクラム

スプリント中に毎日行う短いイベントです。

開発の進み具合を確認し、必要に応じて今後の作業を調整します。

試験では、

```text
毎日
短時間
進捗を共有
今後の作業を調整
```

が重要なキーワードです。

「毎日決まった時間に進捗状況を共有する」とあれば、デイリースクラムと判断しやすくなります。

### スプリントレビュー

スプリントの終わりに、そのスプリントでできた成果を確認するイベントです。

関係者と一緒に成果物を確認し、今後の方向性を考えます。

試験では、

```text
成果物を確認する
ステークホルダーに見せる
```

とあれば、スプリントレビューを考えます。

### スプリントレトロスペクティブ

スプリントの終わりに、チームの進め方を振り返るイベントです。

例えば、

- うまくいったこと
- うまくいかなかったこと
- 次に改善すること

を話し合います。

試験では、

```text
振り返り
改善
次のスプリントに生かす
```

とあれば、スプリントレトロスペクティブを考えます。

## 科目Aでどう出る？

科目Aでは、イベント名そのものよりも、**具体的な活動内容からイベントを選ぶ**問題が出ます。

| 問題文の表現 | 判断 |
|---|---|
| スプリント開始時に計画を立てる | スプリントプランニング |
| 毎日、進捗や今後の作業を共有する | デイリースクラム |
| 完成した成果物を確認する | スプリントレビュー |
| チームの進め方を振り返って改善する | スプリントレトロスペクティブ |

迷ったら、まず次の2点を確認します。

```text
いつ行う？
何を見る？
```

この2つで、かなり切り分けやすくなります。

## どんな場面で使う？

スクラムのイベントは、それぞれ役割が違います。

### 開始時なら「計画」

```text
これから何をやる？
どう進める？
```

を決めるなら、スプリントプランニングです。

### 毎日なら「進捗の調整」

```text
今どこまで進んだ？
次に何をする？
問題はある？
```

を確認するなら、デイリースクラムです。

### 終了時に成果を見るなら「レビュー」

```text
何ができた？
成果物はどうか？
```

を見るなら、スプリントレビューです。

### 終了時に進め方を見るなら「レトロスペクティブ」

```text
やり方はどうだった？
次はどう改善する？
```

を見るなら、スプリントレトロスペクティブです。

## よくある誤解・混同

### レビューとレトロスペクティブを混同する

ここは特に重要です。

```text
成果物を見る
→ スプリントレビュー

進め方を見る
→ スプリントレトロスペクティブ
```

「何を振り返るのか」を見ると判断しやすくなります。

### デイリースクラムは上司への進捗報告会

そう覚えると混乱しやすいです。

デイリースクラムは、単なる報告ではなく、**チームが今後の作業を調整するためのイベント**として捉えるのが重要です。

試験では、

```text
毎日
短時間
進捗確認
作業調整
```

をセットで押さえます。

### スプリントプランニングとデイリースクラムを混同する

どちらも作業の話をしますが、タイミングが違います。

```text
スプリント開始時
→ スプリントプランニング

スプリント中に毎日
→ デイリースクラム
```

「いつ行うか」を先に見ると切り分けやすいです。

## 原典で確認する

Scrumの定義は、共同考案者のKen SchwaberとJeff Sutherlandが公開している **The Scrum Guide** で確認できます。

- [The Scrum Guide（公式）](https://scrumguides.org/scrum-guide.html)
- [Scrum Guide ダウンロードページ](https://scrumguides.org/download.html)

2020年版Scrum Guideでは、Sprintを他のイベントを含むコンテナとして位置付け、Sprint Planning、Daily Scrum、Sprint Review、Sprint Retrospectiveの目的をそれぞれ定義しています。

FE試験では、原典の細かな説明を暗記するより、**イベントの目的**で切り分けるのが重要です。

```text
計画を立てる
→ Sprint Planning

Sprint Goalに向けた進捗を確認し、今後の作業を調整
→ Daily Scrum

成果と環境の変化を確認し、次を検討
→ Sprint Review

品質と有効性を高める改善を計画
→ Sprint Retrospective
```

## まとめ（試験直前用）

- 開始時に計画する → スプリントプランニング
- 毎日、進捗と作業を調整する → デイリースクラム
- 成果物を確認する → スプリントレビュー
- 進め方を振り返って改善する → スプリントレトロスペクティブ
- 迷ったら「いつ行うか」「何を見るか」で判断する

```text
計画
→ Planning

毎日
→ Daily Scrum

成果物
→ Review

改善
→ Retrospective
```
