## まず結論

スクラムでは、スプリントの中で複数のイベントを使い分けます。

基本情報技術者試験では、**「いつ行うか」と「何を確認するか」**で切り分けると判断しやすいです。

```text
開始時に計画する
→ スプリントプランニング

毎日、進捗を検査して今後の作業を調整する
→ デイリースクラム

成果を確認し、次を検討する
→ スプリントレビュー

進め方を振り返って改善する
→ スプリントレトロスペクティブ
```

特に、**毎日・短時間・進捗確認・作業調整**が出てきたら、デイリースクラムを考えます。

## 直感的な説明

スクラムは、短い期間である「スプリント」を繰り返しながら開発を進める方法です。

1回のスプリントを、次のような流れで考えると分かりやすいです。

```text
スプリント開始
  ↓
スプリントプランニング
  ↓
毎日の開発
  └ デイリースクラム
  ↓
スプリント終了に向けて
  ├ スプリントレビュー
  └ スプリントレトロスペクティブ
```

つまり、**計画 → 毎日の調整 → 成果の確認 → 改善**という役割分担です。

## 定義・仕組み

### スプリントプランニング

スプリントを開始するためのイベントです。

そのスプリントで、**なぜ価値があるのか・何を完成できるのか・どのように作業するのか**を考え、スプリントの作業計画を作ります。

試験では、

```text
スプリント開始
作業計画
何を・どう進めるか
```

とあれば、スプリントプランニングを考えます。

### デイリースクラム

スプリント中に毎日行う、**開発者（Developers）の15分間のイベント**です。

目的は、**スプリントゴールに対する進捗を検査し、必要に応じてスプリントバックログを適応させ、今後の作業を調整すること**です。

過去問題では、

```text
昨日やったこと
今日やること
障害になっていること
```

のような説明が手掛かりになることがあります。

ただし、これは**必ずこの3項目を順番に話すという現在の公式ルールではありません**。Scrum Guide 2020では、デイリースクラムの構成や進め方は、目的を達成できる限り開発者が選べます。

試験対策では、

```text
毎日
短時間
スプリントゴールへの進捗を確認
今後の作業を調整
```

を判断軸にする方が安全です。

### スプリントレビュー

スプリントの成果を検査し、今後の適応を考えるイベントです。

Scrum Teamとステークホルダーが、何が達成されたかや環境の変化を確認し、次に何をするかを話し合います。

試験では、

```text
成果を確認
ステークホルダー
今後を検討
```

とあれば、スプリントレビューを考えます。

### スプリントレトロスペクティブ

**品質と有効性を高める方法を計画する**ためのイベントです。

人・相互作用・プロセス・ツールなど、仕事の進め方を振り返り、改善につなげます。

試験では、

```text
振り返り
進め方
改善
```

とあれば、スプリントレトロスペクティブを考えます。

## 科目Aでどう出る？

科目Aでは、イベント名そのものよりも、**具体的な活動内容からイベントを選ぶ**問題が出ます。

| 問題文の表現 | 判断 |
|---|---|
| スプリント開始時に計画を立てる | スプリントプランニング |
| 毎日、進捗を確認して今後の作業を調整する | デイリースクラム |
| 成果を確認し、ステークホルダーと次を検討する | スプリントレビュー |
| 仕事の進め方を振り返って改善する | スプリントレトロスペクティブ |

迷ったら、

```text
いつ行う？
↓
何を確認・改善する？
```

の順に見ます。

### 「昨日・今日・障害」が出たら？

過去問題では、デイリースクラムを「昨日やったこと」「今日やること」「障害になっていること」を共有するイベントとして説明することがあります。

これはデイリースクラムを見抜く強い手掛かりです。

ただし、暗記するなら、

```text
昨日・今日・障害
→ 過去問題ではDaily Scrumの手掛かり

本質
→ Sprint Goalへの進捗を検査し、今後の作業を調整
```

と二段階で覚えておきましょう。

## どんな場面で使う？

### 開始時なら「計画」

```text
これから何をやる？
どう進める？
→ スプリントプランニング
```

### 毎日なら「進捗の検査と調整」

```text
Sprint Goalに向けてどう進んでいる？
次の作業をどう調整する？
→ デイリースクラム
```

### 成果を見るなら「レビュー」

```text
何ができた？
環境はどう変わった？
次に何をする？
→ スプリントレビュー
```

### 進め方を見るなら「レトロスペクティブ」

```text
やり方はどうだった？
次はどう改善する？
→ スプリントレトロスペクティブ
```

## よくある誤解・混同

### レビューとレトロスペクティブを混同する

ここは特に重要です。

```text
成果・次に何をするか
→ スプリントレビュー

仕事の進め方・改善
→ スプリントレトロスペクティブ
```

「何を振り返るのか」を見ると判断しやすくなります。

### デイリースクラムは上司への進捗報告会

そう覚えると混乱しやすいです。

デイリースクラムは、**開発者がスプリントゴールへの進捗を検査し、今後の作業を調整するためのイベント**です。

```text
上司への報告
→ 本質ではない

開発者による進捗の検査・作業調整
→ Daily Scrum
```

### 「昨日・今日・障害」は必須の3質問

現在のScrum Guideでは必須ではありません。

過去問題を解くためのキーワードとしては有効ですが、**公式の目的と、よく使われてきた進め方を混同しない**ようにします。

### スプリントプランニングとデイリースクラムを混同する

どちらも作業について話しますが、タイミングが違います。

```text
スプリント開始
→ スプリントプランニング

スプリント中に毎日
→ デイリースクラム
```

## 原典で確認する

Scrumの定義は、共同考案者のKen SchwaberとJeff Sutherlandが公開している **The Scrum Guide** で確認できます。

- [The Scrum Guide（公式）](https://scrumguides.org/scrum-guide.html)
- [Scrum Guide ダウンロードページ](https://scrumguides.org/download.html)

2020年版Scrum Guideでは、Sprintを他のイベントを含むコンテナとして位置付け、Sprint Planning、Daily Scrum、Sprint Review、Sprint Retrospectiveの目的をそれぞれ定義しています。

特にデイリースクラムについては、**「昨日・今日・障害」という固定形式ではなく、Sprint Goalへの進捗を検査して今後の作業を調整することが目的**だと押さえておくと、古い説明と現在の定義を混同しにくくなります。

## まとめ（試験直前用）

- 開始時の計画 → スプリントプランニング
- 毎日の進捗確認・作業調整 → デイリースクラム
- 成果と今後を確認 → スプリントレビュー
- 進め方を振り返って改善 → スプリントレトロスペクティブ
- 「昨日・今日・障害」はDaily Scrumの手掛かりだが、現在の必須形式ではない

```text
計画 → Planning
毎日 → Daily Scrum
成果 → Review
改善 → Retrospective
```
