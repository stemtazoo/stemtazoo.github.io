## まず結論

**桁落ちは、値がほぼ等しい数同士を減算したときに、上位の有効数字が打ち消し合い、結果の有効桁数が少なくなる現象**です。

基本情報技術者試験では、次の4つを発生条件で切り分けます。

| 用語 | 典型的な発生条件 | 試験で見る言葉 |
|---|---|---|
| 桁落ち | 近い値同士の減算 | ほぼ等しい、有効桁数が減る |
| 桁あふれ | 表現可能な範囲を超える | 最大値を超える、オーバーフロー |
| 丸め誤差 | 表現できない下位桁を丸める | 四捨五入、切捨て、切上げ |
| 情報落ち | 大きさが大きく異なる数の加減算 | 小さい数の下位桁が反映されない |
| 打切り誤差 | 無限に続く計算などを途中で終了 | 途中で打ち切る、有限項で近似 |
| アンダーフロー | 絶対値が小さすぎて表現範囲を下回る | 小さすぎる、最小値を下回る |

```text
近い値を引く
→ 桁落ち

最大値を超える
→ 桁あふれ

下位桁を丸める
→ 丸め誤差

大きい値に小さい値を足す
→ 情報落ち

途中で計算を止める
→ 打切り誤差

小さすぎて表現範囲を下回る
→ アンダーフロー
```

このページでは、**桁落ち・桁あふれ・丸め誤差・情報落ちの見分け方**を中心に扱います。浮動小数点表示そのものの基本は[浮動小数点表示](/fe/floating-point-representation/)、ビット形式は[浮動小数点形式](/fe/floating-point-format/)を参照してください。

## 直感的な説明

コンピュータは、無限に多くの桁を保持できません。

そのため、数値を限られた桁数で表現すると、計算の途中で情報が失われることがあります。

桁落ちは、**よく似た二つの数を引いたとき、先頭の数字がまとめて消えてしまう**イメージです。

```text
1.2345678
-1.2345666
----------
0.0000012
```

二つの数は、先頭から多くの桁が同じです。

減算すると、それらの桁が打ち消し合い、結果に残る有効数字は `1.2` のように少なくなります。

```text
入力：多くの有効数字をもつ
↓ 近い値同士を減算
結果：有効数字が少なくなる
```

「値そのものが小さくなったこと」ではなく、**結果を信頼できる有効桁数が減ったこと**がポイントです。

## 定義・仕組み

### 有効桁数とは

有効桁数は、数値の精度を表す意味のある桁の数です。

例えば、次の値では先頭の0は有効数字に数えません。

```text
0.0000012
```

意味のある数字は `1` と `2` なので、有効数字は2桁です。

コンピュータの浮動小数点形式では、仮数部に保持できる有効数字の桁数が限られます。

浮動小数点形式の符号部・指数部・仮数部については、[浮動小数点形式とは？符号・指数部・仮数部のビット列を読む方法](/fe/floating-point-format/)でも整理しています。

### 桁落ち

桁落ちは、ほぼ等しい値同士を減算したときに起こります。

```text
ほぼ等しい数
- ほぼ等しい数
↓
上位桁が打ち消される
↓
有効桁数が減る
```

絶対値がほぼ等しく、符号が異なる数を加算する場合も、実質的には近い値同士の減算なので桁落ちが起こることがあります。

```text
1.2345678 + (-1.2345666)
```

### 多数の値を加算するときの情報落ち対策

多数の数値を加算するときは、**絶対値の小さいものから順に加算すると、情報落ちを抑えられる場合があります。**

```text
大きい値 + 小さい値 + 小さい値 + …
→ 小さい値がその都度失われやすい

小さい値 + 小さい値 + …
→ 小さい値を先にまとめる
→ その後で大きい値と加算
```

試験では、**「絶対値の小さい順に加算」→「情報落ちの抑制」**と結び付けます。

### 打切り誤差

打切り誤差は、本来は無限に続く計算などを有限回で打ち切ることで生じる誤差です。

```text
無限級数などを途中まで計算
→ そこで終了
→ 打切り誤差
```

「途中で計算をやめる」「有限項で近似する」が判断の合図です。

### アンダーフロー

アンダーフローは、計算結果の絶対値が小さすぎて、その数値形式で表現できる範囲を下回る現象です。

```text
小さい値との演算で有効桁が反映されない
→ 情報落ち

数そのものが小さすぎて表現範囲外
→ アンダーフロー
```

この二つは「有効桁」と「表現範囲」で切り分けます。

### 桁あふれ

桁あふれは、演算結果がコンピュータで表現できる最大値を超える現象です。

```text
表現可能な最大値
＜
演算結果
```

例えば、3桁までしか扱えない仕組みで、次を計算する場合です。

```text
900 + 200 = 1100
```

結果を格納する桁が足りません。

桁あふれは、精度ではなく**表現できる範囲**の問題です。

### 丸め誤差

丸め誤差は、表現できる桁数より下の部分を、四捨五入・切捨て・切上げしたときに生じる誤差です。

例えば、小数第3位までしか保持できないとします。

```text
1.23456
↓ 四捨五入
1.235
```

元の値と、丸めた後の値には差があります。

この差が丸め誤差です。

### 情報落ち

情報落ちは、非常に大きい数と非常に小さい数を加減算したとき、小さい方の下位桁が結果に反映されなくなる現象です。

```text
12345678 + 0.001
```

保持できる有効桁数が限られていると、小さい方の `0.001` が結果から消える場合があります。

```text
大きな数
＋ 小さな数
↓
小さい数の情報が失われる
```

## 科目Aでどう出る？

科目Aでは、用語の定義をそのまま問うだけでなく、現象の説明から用語を選ばせる形で出題されます。

判断するときは、まず**どのような演算をしているか**を確認します。

### 桁落ちを選ぶ目印

- 値がほぼ等しい
- 浮動小数点数同士を減算する
- 上位桁が打ち消される
- 有効桁数が大幅に減る

```text
近い値 − 近い値
→ 桁落ち
```

#### 「同符号の加算・減算」で迷ったら

絶対値がほぼ等しい**同符号**の2数なら、加算では上位桁は打ち消されません。減算すると上位桁が相殺されるため、桁落ちが起こりやすくなります。

### 桁あふれを選ぶ目印

- 最大値を超える
- 表現可能な範囲を超える
- オーバーフローする

```text
範囲を超える
→ 桁あふれ
```

### 丸め誤差を選ぶ目印

- 表現できる桁数に限度がある
- 最下位桁より小さい部分を処理する
- 四捨五入、切捨て、切上げを行う

特に、問題文に **「最下位桁より小さい部分」** と **「四捨五入・切上げ・切捨て」** が並んでいれば、丸め誤差と判断しやすくなります。

```text
最下位桁より小さい部分を処理する
→ 丸め誤差

下位桁を丸める
→ 丸め誤差
```

### 情報落ちを選ぶ目印

- 大きさが大きく異なる数を加減算する
- 小さい方の数が結果に反映されない
- 一方の数の下位桁が消える

```text
大きい値 ＋ 小さい値
→ 情報落ち
```

### 仮数部のビット数は「数値全体の桁数」ではない

例えば `1.01₂ × 2^18` は、指数で小数点の位置を動かすことで大きな値を表します。**仮数の精度は、数値全体が何桁になるかではなく、先頭の有効な1からどこまで細かく保持できるか**を示します。

一般的なIEEE 754単精度形式では、仮数部として保存する小数部分は23ビットですが、正規化された通常の数は先頭の `1` を省略しているため、**有効精度は計24ビット**です。試験で独自形式が指定されたら、その形式の定義を優先してください。

### 指数をそろえると、なぜ情報落ちが起こる？

小さい数の下位の情報が届かなくなる仕組みを、次の加算で見ます。

```text
大きい数：1.01₂ × 2^18
小さい数：1.01₂ × 2^-5

指数の差：18 - (-5) = 23
```

大きい数の指数18にそろえると、小さい方の仮数を**右へ23桁ずらす**ことになります。

```text
大：1.01                  × 2^18
小：0.000…000101          × 2^18
          ↑   ↑
       小数第23位・25位に1がある
```

正規化した数の有効精度が24ビットなら、先頭の1を含めて**小数第23位まで**保持できます。小さい数の最初の1（小数第23位）は残せても、次の1（小数第25位）は保持範囲の外です。

つまり、この例では**小さい数が丸ごと必ず消えるわけではなく、一部の下位ビットが失われる**のがポイントです。実際の格納値は丸め規則の影響も受けます。

もし小さい数が `1₂ × 2^-5` だけなら、IEEE 754単精度のような24ビットの有効精度では、加算結果を正確に保持できます。一方、**先頭の1を含めて23ビット精度**の独自形式なら、その小さい数の1は保持範囲外です。

### 10進数で比べると、情報落ちと桁落ちは別の現象

ここでは有効数字が4桁で、最も近い表現可能な値へ丸める例を考えます。

| 現象 | 正確な計算 | 有限桁で起こること |
|---|---|---|
| 情報落ち | `12300 + 4 = 12304` | 4桁精度では `1.230 × 10^4` となり、足した4が消える |
| 桁落ち | `1.2345 - 1.2344 = 0.0001` | 入力にわずかな誤差があると、共通する上位桁が消え、残った差に対して誤差の割合が大きくなる |

**桁落ちは「結果が小さいから誤り」ではありません。** 近い値の減算で元の値にあった誤差が目立ち、結果の信頼できる有効桁が減ることが問題です。入力が完全に正確なら、減算結果も正確な場合があります。

### 科目A：選択肢を切る3ステップ

1. **近い値の差か？** → 上位桁が打ち消されるなら桁落ちを疑う
2. **指数の差が大きいか？** → 指数をそろえ、小さい方の下位ビットが仮数の精度からはみ出すなら情報落ちを疑う
3. **桁数か値の範囲か？** → 下位桁の丸めなら丸め誤差、数値そのものが範囲外なら桁あふれ・アンダーフロー

「指数差が大きい」「引き算がある」だけで即決せず、**どの桁が失われるか**を確認するのが安全です。

### 絶対値の小さい順に加算する問題

問題文に「多数の数値を、絶対値の小さいものから順に加算する」とあれば、**情報落ちを抑える工夫**を疑います。

```text
小さい値を先にまとめる
↓
大きい値との差を小さくする
↓
小さい値の情報を残しやすくする
```

### 選択肢を切る比較表

| 説明 | 判断 |
|---|---|
| ほぼ等しい値の減算で有効桁数が減る | 桁落ち |
| 計算結果が最大値を超える | 桁あふれ |
| 最下位桁より小さい部分を四捨五入・切上げ・切捨てする | 丸め誤差 |
| 小さい値の下位桁が結果に残らない | 情報落ち |
| 無限に続く計算を途中で終了する | 打切り誤差 |
| 小さすぎて表現可能範囲を下回る | アンダーフロー |

## 科目Bでどう使う？

科目Bでは、これらの用語を直接答える問題よりも、小数計算や比較処理の注意として役立ちます。

例えば、次のような比較です。

```text
0.1 + 0.2 == 0.3
```

浮動小数点数では、内部表現や丸めの影響によって、期待どおりに等しいと判定できない場合があります。

10進数の `0.1` が2進数では有限小数にならない理由は、[有限小数になる条件とは？](/fe/finite-fraction-radix/)で、分母の素因数から整理しています。

そのため、プログラムでは許容誤差を使って比較することがあります。

```text
|計算結果 - 期待値| < 許容誤差
```

科目Bでは、細かな数値解析よりも、**浮動小数点数は常に完全に正確とは限らない**という前提を押さえておくと読みやすくなります。

## どんな場面で使う？

これらの誤差は、浮動小数点数を使う計算で注意が必要です。

- 科学技術計算
- センサデータの処理
- 統計計算
- シミュレーション
- 多数の小さな値を繰り返し加算する処理

### 桁落ちを避ける考え方

桁落ちは、近い値同士を直接引かない式へ変形することで防げる場合があります。

例えば、次の式です。

```text
√(x+1) - √x
```

`x` が大きいと、二つの平方根は近い値になります。

分母と分子を有理化すると、次の形に変えられます。

```text
√(x+1) - √x
= 1 / (√(x+1) + √x)
```

これにより、近い値同士を直接減算せずに計算できます。

ただし、有理化がすべての問題に使えるわけではありません。

```text
近い値同士の減算を避ける形へ式を変える
→ 桁落ちを抑えられる場合がある
```

## よくある誤解・混同

### 桁落ちと情報落ち

この二つは、どちらも有効な情報が失われるため混同しやすい用語です。

| 比較 | 桁落ち | 情報落ち |
|---|---|---|
| 数の大きさ | ほぼ等しい | 大きく異なる |
| 典型的な演算 | 減算 | 加算・減算 |
| 起きること | 上位桁が打ち消され、有効桁数が減る | 小さい数の下位桁が反映されない |

```text
近い数を引く
→ 桁落ち

大きい数に小さい数を加える
→ 情報落ち
```

### 桁落ちと丸め誤差

```text
減算による打消し
→ 桁落ち

有限桁に収める
→ 丸め誤差
```

### 桁落ちと桁あふれ

```text
桁落ち
→ 精度の問題

桁あふれ
→ 表現範囲の問題
```

### 桁落ちは値が小さくなることではない

減算結果が小さくなるだけで、必ず桁落ちになるわけではありません。

問題は、上位桁が打ち消されたことで、入力値に含まれていた誤差が結果に対して相対的に大きくなり、有効桁数が減ることです。

### 丸め誤差は計算ミスではない

コンピュータが有限桁で数値を表現する以上、丸め誤差を完全に避けられない場合があります。

計算方法やデータ型を工夫して、誤差の影響を小さくすることが大切です。

## 確認問題

次のうち、情報落ちの説明として最も適切なものはどれでしょうか。

1. ほぼ等しい二つの値を減算し、有効桁数が減少する
2. 演算結果が表現可能な最大値を超える
3. 表現できない下位桁を四捨五入する
4. 大きさが大きく異なる数を加算し、小さい方の値が結果に反映されない

## 国際標準で確認する

浮動小数点演算の丸めや例外処理などを定める代表的な国際標準が **IEEE 754** です。

- [IEEE：IEEE 754-2019 - Standard for Floating-Point Arithmetic](https://standards.ieee.org/ieee/754/6210/)

FE試験では規格の細かな丸めモードなどを暗記する必要はありません。まず、誤差の原因を見て切り分けます。

```text
近い値を引く
→ 桁落ち

大きい値と小さい値を演算
→ 情報落ち

有限桁へ丸める
→ 丸め誤差

表現範囲を超える
→ オーバーフロー／アンダーフロー
```

## まとめ（試験直前用）

- 桁落ちは、ほぼ等しい値同士の減算で有効桁数が減る現象
- 桁あふれは、演算結果が表現可能な範囲を超える現象
- 丸め誤差は、表現できない下位桁を丸めることで生じる誤差
- 情報落ちは、大きさが異なる数の加減算で小さい数の情報が失われる現象
- 絶対値の小さい順に加算すると、情報落ちを抑えられる場合がある
- 打切り誤差は、無限に続く計算などを途中で終了することで生じる
- アンダーフローは、小さすぎて表現可能範囲を下回る現象
- 仮数部23ビットと、IEEE 754単精度の有効精度24ビット（省略された先頭の1を含む）は区別する
- 「近い値を引く」「大＋小」「途中で止める」「小さすぎる」で原因から切り分ける
