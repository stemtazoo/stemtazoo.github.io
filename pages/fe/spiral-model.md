## まず結論

スパイラルモデルとは、**各サイクルでリスクを評価・低減し、その結果をもとに次の開発活動を決めながら、開発工程を反復する手法**です。

基本情報技術者試験では、次の切り分けが重要です。

```text
リスクを評価しながら開発工程を繰り返す
→ スパイラルモデル

試作品を作って利用者と要求を確認する
→ プロトタイピングモデル
```

どちらにも「繰り返す」という特徴があるため、**反復の目的と、リスクをどう扱うか**を見るのが判断のコツです。

## 直感的な説明

新しい販売管理システムで、要求や性能に不確かな点がある場面を考えます。

```text
第1周：利用者の要求が曖昧
→ 画面の試作品で要求を確認し、不確かさを減らす

第2周：受注が集中したときの性能が不明
→ 性能を検証し、設計方針を決める

第3周：残るリスクを評価
→ 次に開発する範囲と進め方を決める
```

この例のポイントは、機能を順番に追加することだけでなく、**その時点のリスクに応じて、試作・検証・開発などの進め方を選ぶこと**です。

一方、プロトタイピングモデルでは、早い段階で試作品を作って利用者に見せます。

```text
試作品を作る
→ 利用者に見せる
→ 要求を確認する
→ 修正する
```

こちらは、開発工程全体を部分ごとに回すことよりも、**利用者と完成イメージを共有して要求を明確にすること**が中心です。

## 定義・仕組み

スパイラルモデルは、反復とリスクへの対応を組み合わせた開発モデルです。各サイクルでは、次のように進めます。

```text
目的・選択肢・制約を整理する
→ リスクを評価し、低減する
→ 次の段階の成果物を開発・検証する
→ 結果を評価し、次のサイクルを計画する
```

リスクの内容に応じて、試作品による要求確認や性能検証を行うこともあります。**各周で同じ工程を同じ深さで繰り返すとは限りません。**

開発の初期段階で全てを固定するのではなく、途中の評価や変更を取り込みやすい点が特徴です。

ただし、繰り返しが多くなると、進捗や費用を管理しにくくなることもあります。

### 代表的な開発モデルの比較

| 開発モデル | 中心となる考え方 | 問題文の手掛かり |
|---|---|---|
| ウォーターフォールモデル | 工程を上流から下流へ順番に進める | 各工程を完了してから次へ進む |
| スパイラルモデル | リスクを評価・低減しながら開発工程を反復する | リスク分析、評価結果に応じた次の活動、反復 |
| プロトタイピングモデル | 試作品を使って要求を確認する | 試作品、利用者に提示、要求の確認・明確化 |

プロトタイピングモデルを中心に整理したい場合は、[プロトタイピングモデルとは？スパイラルモデルとの違い]({{ '/fe/prototyping-model/' | relative_url }})もあわせて確認してください。

工程を順番に進めるモデルとの違いは、[ウォーターフォールモデルとは？工程を順番に進める開発手法]({{ '/fe/waterfall-model/' | relative_url }})で確認できます。

## 科目Aでどう出る？

科目Aでは、開発モデルの説明文から該当する名称を選ぶ問題として出やすいテーマです。

問題文に次の表現があれば、スパイラルモデルを疑います。

- 各サイクルでリスクを分析・評価する
- リスクを減らすために試作や検証を行う
- 評価結果を次の開発活動や計画に反映する

一方、次の表現があればプロトタイピングモデルです。

- 早い段階で試作品を作る
- 利用者に操作してもらう
- 完成イメージを共有する
- 曖昧な要求を確認・明確化する

試験中は、単に「繰り返す」「段階的に作る」という言葉だけで断定しないことが大切です。機能を少しずつ追加する開発にも当てはまるため、リスク分析や評価の説明と組み合わせて読みます。

```text
何を重視する？

リスクを評価・低減しながら開発を反復
→ スパイラル

試作品の提示と修正
→ プロトタイピング
```

さらに、問題文に「工程を順番に完了してから次へ進む」とあれば、ウォーターフォールモデルです。

## どんな場面で使う？

スパイラルモデルは、要求や技術上の不確かさが大きく、リスクを確かめながら開発を進めたいときに使われます。

特に、次のような場面に向きます。

- 新技術で必要な性能が出るか確かめたい
- 重要な要求の不確かさを早めに減らしたい
- リスク評価を次の段階への投資や開発判断に反映したい

要求を明確にするための試作品は、スパイラルモデルの中でも使えます。プロトタイピングは、スパイラルモデルと組み合わせられない別方式という意味ではありません。

## よくある誤解・混同

最も多い混同は、スパイラルモデルとプロトタイピングモデルです。

| 誤解 | 正しい理解 |
|---|---|
| 繰り返す開発は全てプロトタイピングモデル | 反復だけでは断定せず、リスク評価を伴うかを見る |
| 試作品を作ることがスパイラルモデルの決め手 | 要求確認が中心ならプロトタイピング。スパイラルでもリスク低減に試作品を使える |
| スパイラルモデルは工程を一度だけ順番に進める | それはウォーターフォールモデルの特徴 |
| リレーショナルモデルも開発モデルの一つ | リレーショナルモデルはデータベースのデータモデル |

特に注意したいのは、プロトタイピングモデルも修正を繰り返すことです。

```text
リスク評価をもとに開発工程を反復する
→ スパイラルモデル

試作品を見せて要求確認を繰り返す
→ プロトタイピングモデル
```

## 原典で確認する

スパイラルモデルは、Barry W. Boehmが1988年にIEEEの *Computer* 誌で発表した論文 **“A Spiral Model of Software Development and Enhancement”** で体系的に示されています。

- [IEEE：A Spiral Model of Software Development and Enhancement](https://doi.org/10.1109/2.59)

この原著で重要なのは、スパイラルモデルが単なる「工程を何度も繰り返す方法」ではなく、**リスクを評価しながら次の開発活動を決めていく risk-driven（リスク駆動）のアプローチ**として説明されている点です。

CMU/SEIの[Spiral Development: Experience, Principles, and Refinements](https://www.sei.cmu.edu/library/spiral-development-experience-principles-and-refinements-spiral-development-workshop-february-9-2000/)でも、反復とリスクの低減が特徴として整理されています。FEでは、次の組合せで理解します。

```text
反復する
＋
各サイクルでリスクを検討する
→ スパイラルモデル
```

## まとめ（試験直前用）

- スパイラルモデルは、リスクを評価・低減しながら開発工程を反復する
- プロトタイピングモデルは、試作品を利用者に見せて要求を明確にする
- 「反復」「段階的」だけで断定せず、リスクへの対応を見る
- 工程を順番に一度ずつ進めるのはウォーターフォールモデル
- 試作品による要求確認は、スパイラルモデルの中でも使える
