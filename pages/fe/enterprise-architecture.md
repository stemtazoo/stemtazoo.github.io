## まず結論

エンタープライズアーキテクチャ（EA）とは、**企業や組織全体の業務と情報システムを、全体最適の視点で整理・設計するための考え方**です。

FE試験では、まず次の4体系を押さえます。

```text
Business
→ ビジネスアーキテクチャ

Data
→ データアーキテクチャ

Application
→ アプリケーションアーキテクチャ

Technology
→ テクノロジアーキテクチャ
```

一言でまとめると、

```text
業務
↓
データ
↓
アプリケーション
↓
技術基盤
```

の4つです。

## 直感的な説明

EAは、会社全体を「上から順に整理する設計図」のようなものです。

例えば、新しいシステムを作るとき、いきなりサーバやソフトを決めるのではなく、

```text
どんな業務をする？
↓
どんなデータを使う？
↓
どんなアプリケーションが必要？
↓
どんな技術で実現する？
```

という順番で考えると、全体のつながりが見えやすくなります。

これを4つに分けたものが、EAの基本的な分類です。

## 定義・仕組み

エンタープライズアーキテクチャでは、組織全体を複数の視点から整理します。

### ビジネスアーキテクチャ

ビジネスアーキテクチャは、**業務・組織・業務フローなどを整理する体系**です。

```text
何をする組織か
どんな業務を行うか
誰が担当するか
どんな流れで業務を進めるか
```

といった内容を扱います。

判断キーワードは、

```text
業務
組織
業務フロー
役割
```

です。

### データアーキテクチャ

データアーキテクチャは、**業務やシステムで使うデータの内容や関係を整理する体系**です。

例えば、

```text
顧客
商品
注文
在庫
```

といったデータが、

```text
どんな情報を持つか
どのデータと関係するか
どこで使われるか
```

を整理します。

判断キーワードは、

```text
データ
情報
項目
関係
エンティティ
```

です。

### アプリケーションアーキテクチャ

アプリケーションアーキテクチャは、**業務を支える情報システムやアプリケーションの機能・構成を整理する体系**です。

例えば、

```text
販売管理システム
在庫管理システム
会計システム
```

などの役割や関係を整理します。

判断キーワードは、

```text
システム
アプリケーション
機能
処理
```

です。

### テクノロジアーキテクチャ

テクノロジアーキテクチャは、**システムを実現するための技術基盤を整理する体系**です。

例えば、

```text
ハードウェア
OS
ネットワーク
ミドルウェア
データベース製品
```

などです。

判断キーワードは、

```text
技術
ハードウェア
ソフトウェア
ネットワーク
基盤
```

です。

## 科目Aでどう出る？

科目Aでは、4体系の名前を問う問題や、説明から正しい体系を選ぶ問題が考えられます。

まずは、4つをそのまま覚えるのが有効です。

```text
Business
Data
Application
Technology
```

頭文字で、

```text
B
D
A
T
```

と整理しても構いません。

### 説明から見分ける

| 問題文の中心 | 判断 |
|---|---|
| 業務・組織・業務フロー | ビジネスアーキテクチャ |
| 情報・データ・項目間の関係 | データアーキテクチャ |
| 情報システム・機能・処理 | アプリケーションアーキテクチャ |
| ハード・ソフト・ネットワーク | テクノロジアーキテクチャ |

### 選択肢を切るとき

EAの4体系として出てきたら、

```text
Business
Data
Application
Technology
```

に含まれるかを確認します。

例えば、

```text
システムアーキテクチャ
ソフトウェアアーキテクチャ
バスアーキテクチャ
```

は、一般的なIT用語として使われることはありますが、EAの4体系そのものではありません。

## どんな場面で使う？

EAは、大規模な組織や複数システムを持つ企業で、全体を整理したい場面で使われます。

例えば、

- 部門ごとにバラバラな業務を標準化したい
- 重複しているシステムを整理したい
- データの持ち方を統一したい
- 将来のシステム構成を整理したい
- 経営戦略とIT戦略をつなげたい

といった場面です。

ポイントは、個別システムだけを見るのではなく、**企業全体として最適かどうかを見る**ことです。

## よくある誤解・混同

### EAはシステム構成図のこと？

違います。

EAは、単なるシステム構成図ではなく、

```text
業務
データ
アプリケーション
技術
```

を含めて組織全体を整理する考え方です。

### データアーキテクチャとアプリケーションアーキテクチャは同じ？

違います。

```text
データそのもの・データ間の関係
→ データアーキテクチャ

そのデータを使って処理するシステム
→ アプリケーションアーキテクチャ
```

と切り分けます。

### テクノロジアーキテクチャとアプリケーションアーキテクチャは同じ？

違います。

```text
業務機能を実現するシステム
→ アプリケーションアーキテクチャ

そのシステムを動かす技術基盤
→ テクノロジアーキテクチャ
```

です。

### ソフトウェアアーキテクチャはEAの4体系？

EAの4体系として覚えるのは、

```text
Business
Data
Application
Technology
```

です。

「ソフトウェアアーキテクチャ」という言葉自体は一般的なIT用語ですが、EAの4体系そのものではありません。

## 確認問題（基本情報技術者試験対策）

エンタープライズアーキテクチャの4体系に含まれるものとして、最も適切なものはどれか。

- ア. システムアーキテクチャ
- イ. ソフトウェアアーキテクチャ
- ウ. データアーキテクチャ
- エ. バスアーキテクチャ

<details markdown="1">
<summary>▶ クリックして答えと解説を見る（ここを開く）</summary>

**正解：ウ**

エンタープライズアーキテクチャの4体系は、次の4つです。

```text
ビジネスアーキテクチャ
データアーキテクチャ
アプリケーションアーキテクチャ
テクノロジアーキテクチャ
```

したがって、正解はデータアーキテクチャです。

</details>

## まとめ（試験直前用）

- EAは、組織全体の業務と情報システムを全体最適の視点で整理する考え方
- 4体系は **Business / Data / Application / Technology**
- ビジネスは業務、データは情報、アプリケーションはシステム機能、テクノロジは技術基盤
- 「システムアーキテクチャ」「ソフトウェアアーキテクチャ」「バスアーキテクチャ」はEAの4体系そのものではない
- **業務 → データ → アプリケーション → 技術基盤** の順で整理すると覚えやすい
