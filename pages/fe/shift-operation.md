## まず結論

シフト演算とは、**ビット列を左または右にずらす操作**です。

基本情報技術者試験では、まず次の関係を押さえると判断しやすいです。

```text
左シフト → 2倍するイメージ
右シフト → 2で割るイメージ
```

さらに、シフトと加算を組み合わせると、2進数の掛け算を実現できます。

```text
乗数の最下位ビットを見る
→ 1なら被乗数を結果に加える
→ 被乗数を左シフト
→ 乗数を右シフト
→ 次のビットを調べる
```

試験では、**どのビットを見るか、どちらを左・右にシフトするか** が判断ポイントになります。

## 直感的な説明

シフト演算は、ビット列を横にずらす操作です。

例えば、次の2進数を考えます。

```text
0000 0110
```

これは10進数で `6` です。

1ビット左にずらすと、次のようになります。

```text
0000 1100
```

これは10進数で `12` です。

つまり、1ビット左にずらすと、値は2倍になります。

反対に、次のビット列を1ビット右にずらすとします。

```text
0000 1100
↓ 右に1ビット
0000 0110
```

`12` が `6` になるので、右シフトは2で割るイメージです。

この「左にずらすと2倍」という性質を使うと、掛け算もできます。

10進数の筆算で桁が一つ左へ進むと10倍になるのと同じように、2進数では桁が一つ左へ進むと2倍になります。

そのため、2進数の各桁が `1` のときだけ、対応する2の累乗分を加えていけば積を求められます。

## 定義・仕組み

シフト演算では、ビット列を指定した方向に移動します。

| 操作 | 意味 | 数値のイメージ |
|---|---|---|
| 左シフト | ビット列を左へずらす | 2倍、4倍、8倍 |
| 右シフト | ビット列を右へずらす | 1/2、1/4、1/8 |

1ビット左にずらすと2倍、2ビット左にずらすと4倍になります。

```text
0000 0011 = 3
0000 0110 = 6   ← 左に1ビット
0000 1100 = 12  ← 左に2ビット
```

右シフトでは、1ビット右にずらすと2で割ったような値になります。

```text
0000 1100 = 12
0000 0110 = 6   ← 右に1ビット
0000 0011 = 3   ← 右に2ビット
```

ただし、右にずらして割り切れない場合は、下位ビットが落ちます。

例えば、`7` は2進数で `0000 0111` です。

```text
0000 0111 = 7
右に1ビット
0000 0011 = 3
```

10進数でいうと、`7 ÷ 2 = 3 あまり 1` なので、あまりに相当するビットが落ちたと考えます。

### シフトと加算で掛け算を行う

符号なし2進数の乗算では、乗数のビットを下位から順に調べる方法があります。

考え方は次のとおりです。

```text
乗数の最下位ビットが1
→ 現在の被乗数を結果へ加える

次の桁へ進む
→ 被乗数を1ビット左シフト
→ 乗数を1ビット右シフト
```

例えば `3 × 3` を考えます。

```text
X = 3 = 0011   ← 被乗数
Y = 3 = 0011   ← 乗数
Z = 0          ← 結果
```

1回目は、Yの最下位ビットが `1` です。

```text
Z = Z + X = 0 + 3 = 3
Xを左シフト → 6
Yを右シフト → 1
```

2回目も、Yの最下位ビットが `1` です。

```text
Z = Z + X = 3 + 6 = 9
Xを左シフト → 12
Yを右シフト → 0
```

結果は `Z = 9` となり、`3 × 3 = 9` が得られます。

ここで重要なのは、次の対応です。

```text
Yの最下位ビットを見る
Xは左シフト
Yは右シフト
```

Xを左シフトするのは、調べる桁が一つ上がるたびに重みが2倍になるからです。

Yを右シフトするのは、次に調べるビットを最下位へ移動させるためです。

## 科目Aでどう出る？

科目Aでは、ビット列を左または右にシフトした結果や、シフトを使った処理の穴埋めを選ぶ問題が出題されます。

まずは、方向と倍率を対応させます。

| 問題文の表現 | 判断 |
|---|---|
| 左に1ビットシフト | 2倍 |
| 左に2ビットシフト | 4倍 |
| 左に3ビットシフト | 8倍 |
| 右に1ビットシフト | 2で割る |
| 右に2ビットシフト | 4で割る |
| 右に3ビットシフト | 8で割る |

例えば、`0000 1010` は10進数で `10` です。

左に1ビットシフトすると、次のようになります。

```text
0000 1010
↓ 左に1ビット
0001 0100
```

これは10進数で `20` です。

反対に、右に1ビットシフトすると、次のようになります。

```text
0000 1010
↓ 右に1ビット
0000 0101
```

これは10進数で `5` です。

乗算アルゴリズムの問題では、次の3点を見ると選択肢を切りやすくなります。

```text
1. 乗数のどのビットを判定するか
   → 最下位ビット

2. 被乗数をどちらへ動かすか
   → 左シフト

3. 乗数をどちらへ動かすか
   → 右シフト
```

つまり、**「最下位ビット・Xは左・Yは右」** が判断軸です。

## 科目Bでどう使う？

科目Bでは、プログラム中で `<<` や `>>` のような演算子が使われる場合があります。

一般に、次のように読みます。

```text
x << 1 → xを左に1ビットシフト
x >> 1 → xを右に1ビットシフト
```

例えば、`x = 6` のとき、`x << 1` は次のように考えます。

```text
6 = 0000 0110
左に1ビット
0000 1100 = 12
```

一方で、`x >> 1` は次のようになります。

```text
6 = 0000 0110
右に1ビット
0000 0011 = 3
```

シフトと加算による乗算処理なら、擬似コードは次のような形になります。

```text
Z = 0

乗数Yのビットを順番に調べる
  Yの最下位ビットが1なら
    Z = Z + X

  Xを1ビット左シフト
  Yを1ビット右シフト
```

科目Bでは、コードを一行ずつ追う前に、

> **Yの各ビットが1なら、その桁に対応するXをZへ加えている**

と処理全体の目的をつかむと読みやすくなります。

## よくある誤解・混同

シフト演算でよくある誤解は、**左右の方向と倍率を逆に覚えてしまうこと** です。

| 誤解 | 正しい理解 |
|---|---|
| 左シフトは半分になる | 左シフトは2倍方向 |
| 右シフトは2倍になる | 右シフトは半分方向 |
| 2ビット左シフトは2倍 | 2ビット左シフトは4倍 |
| 右シフトで落ちたビットも残る | 右に押し出されたビットは落ちる |
| 乗算では乗数の最上位ビットを見る | 下位から処理する方式では最下位ビットを見る |
| 乗算ではXを右、Yを左へ動かす | Xは左、Yは右へシフトする |
| 符号付き整数でも必ず単純に半分 | 算術シフトでは符号ビットの扱いに注意 |

シフトには、論理シフトと算術シフトという考え方もあります。

| 種類 | 空いたビットの扱い | 主な用途 |
|---|---|---|
| 論理シフト | 空いたところに0を入れる | 符号なしのビット列 |
| 算術シフト | 符号を保つように扱う | 符号付き整数 |

問題文に「符号なし」「論理シフト」とあれば、空いた部分には0が入ると考えます。

一方、符号付き整数の右シフトでは、算術シフトによって符号ビットを保つ場合があります。

## まとめ（試験直前用）

- シフト演算は、ビット列を左または右にずらす操作
- 左シフトは2倍方向、右シフトは半分方向
- 乗数を下位から調べる乗算では、**最下位ビット**を見る
- ビットが1なら、現在の被乗数を結果へ加える
- 次の桁では、**被乗数Xを左シフト、乗数Yを右シフト**する
- 論理シフトは空いたところに0、算術シフトは符号ビットに注意

試験中は、**「最下位ビット・Xは左・Yは右」** と整理すると判断しやすくなります。
