## まず結論

プログラムの著作権では、次の3点を分けて考えると選択肢を切りやすくなります。

```text
具体的に作られたプログラム
→ 著作権の保護対象になり得る

プログラム言語・規約・解法
→ プログラム著作物の保護は及ばない

正当に入手したプログラムを利用するための
必要な範囲の複製・改変
→ 認められる場合がある
```

つまり、**「著作権で保護される」ことと「一切コピーや改変ができない」ことは同じではありません。**

FE試験では、保護対象かどうかだけでなく、**誰が・何のために・どこまで利用するのか**を見ることが大切です。

## 直感的な説明

著作権は、アイデアやルールそのものではなく、**創作的に表現されたもの**を守る制度です。

プログラムで考えると、次のように整理できます。

```text
Pythonというプログラム言語
→ プログラムを書くためのルール

Pythonで具体的に書いたプログラム
→ 具体的な表現
```

同じように、

```text
処理の考え方・アルゴリズム
→ 方法・アイデア側

そのアルゴリズムを具体的なコードとして表現したもの
→ 著作物になり得る
```

さらに、正当に入手したプログラムを自分のコンピュータで使う場面では、利用に必要な範囲で複製や改変が認められる場合があります。

例えば、

```text
故障に備えてバックアップする
利用環境へ適合させるため必要な変更をする
```

といった行為を、すべて「著作物を複製・改変したから直ちに違法」とは判断しません。

## 定義・仕組み

### プログラム本体は著作物になり得る

著作権法では、プログラムは著作物になり得ます。

実際に記述されたプログラムについて創作的な表現があれば、プログラムの著作物として保護対象になり得ます。

```text
具体的なソースコード
→ 保護対象になり得る
```

制度の原文は、[e-Gov法令検索：著作権法](https://elaws.e-gov.go.jp/document?lawid=345AC0000000048)で確認できます。

### 言語・規約・解法には保護が及ばない

著作権法では、プログラムの著作物に対する保護は、その著作物を作成するために用いる**プログラム言語、規約、解法**には及ばないとされています。

| 保護が及ばないもの | 直感的な意味 |
|---|---|
| プログラム言語 | プログラムを記述するための体系 |
| 規約 | プログラムで使う特別な約束やルール |
| 解法 | 処理を実現するための指令の組合せ方法 |

FE試験では、「解法」をアルゴリズムと結び付けて考えると分かりやすいです。

```text
アルゴリズムそのもの
→ 方法・考え方
→ プログラム著作物の保護は及ばない

具体的に記述したコード
→ 表現
→ 保護対象になり得る
```

### 正当に入手したプログラムの利用に必要な複製・改変

プログラムの複製物を正当に所有している人は、そのプログラムをコンピュータで利用するために必要と認められる範囲で、複製や翻案を行える場合があります。

文化庁も、プログラムの著作物の複製物の所有者について、滅失・毀損に備えたバックアップや、利用のため必要な範囲の変更などが認められる場合があると説明しています。

- [文化庁：著作権解説集（プログラムの著作物の複製物の所有者による複製など）](https://pf.bunka.go.jp/chosaku/chosakuken/h22_manga/comment/list_ha.html)

試験では、次のように整理します。

```text
正当に入手したプログラム
＋
自分が利用するために必要
＋
必要な範囲
→ 複製・改変が認められる場合がある
```

ただし、これは**第三者への自由な配布や販売まで認める**という意味ではありません。

### バックアップは常に禁止ではない

「著作権者から特に許可されていなければ、バックアップ目的でも一切複製できない」という理解は適切ではありません。

正当に所有するプログラムについて、利用上必要なバックアップが認められる場合があります。

一方で、元のプログラムを他人へ譲渡するなどして所有権を失った場合には、バックアップの扱いにも注意が必要です。

### フリーソフトウェアでも著作権はある

インターネット上で無料公開されているソフトウェアでも、著作権がなくなるわけではありません。

```text
無料で利用できる
→ 利用条件・料金の話

著作権が存在するか
→ 著作物として保護されるかの話
```

OSSやフリーソフトウェアの利用条件については、[GPLとは？改変・配布・ソースコード公開の判断基準]({{ '/fe/gpl-license/' | relative_url }})もあわせて確認すると整理しやすくなります。

### 操作マニュアル・データベースも別に判断する

ソフトウェアの操作マニュアルは、文章や図などに創作的な表現があれば著作物になり得ます。

また、データベースも一律に保護対象外ではなく、情報の選択や体系的な構成に創作性がある場合は著作物として保護されることがあります。

基本情報技術者試験の公式な出題範囲やシラバスは、[IPA：基本情報技術者試験](https://www.ipa.go.jp/shiken/kubun/fe.html)から確認できます。

## 科目Aでどう出る？

科目Aでは、プログラムについて「何が保護されるか」「どの利用が認められるか」を選択肢から判断する問題が出ます。

まず、次の2段階で考えると整理しやすいです。

```text
1. 何が保護対象か？
2. その利用行為は認められる範囲か？
```

### 判断軸1：表現か、方法か

| 選択肢の表現 | 判断 |
|---|---|
| 具体的に作られたプログラム | 保護対象になり得る |
| プログラム言語 | 保護が及ばない |
| プログラムの規約 | 保護が及ばない |
| アルゴリズム・解法 | 保護が及ばない |
| 操作マニュアル | 表現に創作性があれば保護対象になり得る |
| データベース | 選択・体系的構成に創作性があれば保護対象になり得る |

### 判断軸2：利用に必要な範囲か

| 問題文の表現 | 判断の方向 |
|---|---|
| 正当に購入したプログラムを利用環境へ適合させるために必要な改変 | 認められる場合がある |
| 正当に所有するプログラムの利用に必要なバックアップ | 認められる場合がある |
| バックアップ目的でも複製は必ず違法 | 誤りを疑う |
| アルゴリズムそのものも著作物として保護される | 誤りを疑う |
| 購入したから第三者へ自由にコピーして配布できる | 誤りを疑う |

試験中は、次のように短く整理できます。

```text
表現
→ 保護され得る

言語・規約・解法
→ 保護は及ばない

自分が正当に入手したプログラムを
利用するために必要な範囲
→ 複製・改変が認められる場合がある

他人へ自由に配布
→ 別問題。自由とは限らない
```

著作物一般の引用・私的使用・Web掲載などは、[著作権法で認められる利用とは？]({{ '/fe/copyright-permitted-use/' | relative_url }})で整理しています。

## どんな場面で使う？

### 購入したソフトウェアを自社環境で使う

正当に購入したプログラムを利用するため、利用環境への適合や機能上必要な変更を検討する場面があります。

ここでは、

```text
購入したから何でも自由
```

でも、

```text
著作権があるから一切変更不可
```

でもありません。

**利用に必要な範囲か**という視点が重要です。

### 故障に備えてバックアップする

バックアップ用の複製も、利用上必要な範囲で認められる場合があります。

試験では「バックアップでも必ず違法」という断定に注意します。

### ソフトウェアを開発する

具体的なソースコードは著作物として保護される可能性がありますが、アルゴリズムやノウハウそのものは著作権とは別に考えます。

```text
具体的なソースコード
→ 著作権

アルゴリズムやノウハウ
→ 契約・秘密管理・特許など別の観点も検討
```

また、会社の業務として従業員が作ったプログラムの著作者が誰になるかは、保護対象とは別の問題です。

その点は、[職務著作とは？従業員が作ったプログラムの著作権は誰のもの？]({{ '/fe/work-made-for-hire-copyright/' | relative_url }})で切り分けられます。

## よくある誤解・混同

### ❌ 著作権で保護されるプログラムは一切改変できない

誤りです。

正当に所有しているプログラムを利用するために必要な範囲では、複製や改変が認められる場合があります。

```text
保護される
≠
一切の利用行為が禁止
```

### ❌ バックアップ目的でも、許可がなければ必ず違法

誤りです。

正当に所有するプログラムについて、利用上必要なバックアップが認められる場合があります。

### ❌ プログラム言語もプログラムなので著作権で保護される

誤りです。

プログラム言語は、具体的なプログラムを書くための手段・体系です。

### ❌ アルゴリズムを考えたら、そのアルゴリズム自体が著作権で保護される

誤りです。

```text
アルゴリズム
→ 方法・考え方

具体的なソースコード
→ 表現
```

### ❌ フリーソフトウェアには著作権がない

誤りです。

無料で利用できることと、著作権が存在しないことは別です。

### ❌ プログラムを購入したら、自由に第三者へ複製・配布できる

誤りです。

利用のために必要な複製・改変が認められる場合があることと、第三者への自由な配布は別の話です。

## まとめ（試験直前用）

- プログラム本体は、創作的な表現があれば著作権の保護対象になり得る
- プログラム言語・規約・解法には、プログラム著作物の保護は及ばない
- アルゴリズムそのものと、具体的なコード表現を分ける
- 正当に入手したプログラムは、利用に必要な範囲で複製・改変が認められる場合がある
- バックアップ目的の複製を「常に違法」と考えない
- 購入したから第三者へ自由に配布できるわけではない
- FEでは「何が保護されるか」と「どこまで利用できるか」を分けて判断する

> **表現は守る。言語・規約・解法は別。利用に必要な範囲の複製・改変は認められる場合がある。**
