## まず結論

**DBMS（Database Management System：データベース管理システム）**とは、多数の利用者やアプリケーションがデータベースを安全かつ整合性を保って利用できるよう、**データの定義・検索や更新・アクセス管理・同時実行制御・障害回復**などを行うソフトウェアです。

FE科目Aでは「データそのもの」「DBMSという管理ソフト」「DBAという管理者」を区別します。

| 用語 | 何を指す？ |
|---|---|
| データベース | 目的に沿って組織化したデータの集まり |
| DBMS | データベースを管理・利用するためのソフトウェア |
| DBA | DBMSを設定・運用し、データベースを管理する担当者 |
| SQL | 関係データベースの定義や操作に使われる言語 |

## 直感的な説明

たとえば、工場で「設備台帳」を複数の部署が利用するとします。設計部門は設備を検索し、保全担当は点検履歴を追加し、管理者は閲覧できる項目を制限します。

全員が同じファイルを勝手に書き換えると、更新の衝突や情報漏えいが心配です。**DBMSは、共通データを使うための交通整理役**です。

## 定義・仕組み

### DBMSの代表的な機能

| 機能 | 主な役割 | 具体例 |
|---|---|---|
| データ定義・構成管理 | 表・キー・制約などの構造を管理 | 設備IDを主キーとして定義 |
| データ操作 | データの検索・追加・更新・削除を実行 | 設備の点検日時を更新 |
| 機密保護・権限管理 | 利用者ごとに操作を許可・制限 | 一般社員は閲覧だけ許可 |
| 同時実行制御・整合性管理 | 同時更新による矛盾を防止 | 2人の更新が互いを不正に上書きしないように制御 |
| 保全機能（整合性維持） | 定義した制約などを守り矛盾を防ぐ | 主キー重複の登録を拒否 |
| 障害回復 | ログやバックアップなどを利用して復旧 | 障害後にコミット済み更新を回復 |

これらは関連し合っています。たとえば「在庫数を更新する」には、データ操作だけでなく同時実行制御や障害回復の仕組みも重要です。

### データの定義・構成管理

データベースの表、列、データ型、主キー、外部キーや制約などの構造を定義します。これらの定義は**スキーマ**に関係します。詳しくは[3層スキーマ](/fe/database-schema/)を確認してください。


### 定義機能と保全機能：ルールを決めることと守らせること

**定義機能**は、スキーマを定め、表・列・データ型・主キー・外部キーなどの**構造や制約を設定する**機能です。一方、**保全機能**は、定めた制約などに従ってデータの**整合性を維持する**働きです。

設備台帳を使って、2段階に分けてみましょう。

~~~text
① 定義：設備IDは重複不可、とルールを設定
          ↓
② 保全：同じ設備IDの登録をDBMSが拒否
~~~

例えば、次のSQLは**構造と主キー制約を定義**しています。

~~~sql
CREATE TABLE 設備 (
    設備ID INTEGER PRIMARY KEY,
    設備名 VARCHAR(50) NOT NULL
);
~~~

これはDDL（データ定義言語）による**定義機能**の例です。まだ設備のデータを登録していません。

その後、次のように登録したとします。

~~~sql
INSERT INTO 設備 (設備ID, 設備名)
VALUES (101, '旋盤A');

-- 同じ設備IDをもう一度登録しようとする
INSERT INTO 設備 (設備ID, 設備名)
VALUES (101, '旋盤B');
~~~

2回目の登録は、先に定義した**主キーの一意性制約に違反するため拒否**されます。このように、制約に違反するデータを受け付けず**整合性を保つこと**が保全機能の具体例です。

| 比較 | 定義機能 | 保全機能 |
|---|---|---|
| 何をする？ | 構造・制約を**設定する** | 制約を守らせ、データの**整合性を維持する** |
| 例 | `PRIMARY KEY`、`FOREIGN KEY`を定義 | キーの重複や不正な参照を拒否 |
| 判断語句 | スキーマ、列、データ型、定義 | 整合性、参照制約、矛盾の防止 |

**注意：** 実際のDBMSでは、定義した制約がデータ操作時に検査されるため、両機能は連携しています。問題文に「制約を作る」とあれば定義、「制約違反を防ぐ」とあれば保全、と**何をしている段階か**で判断しましょう。

さらに、保全機能は広くデータの整合性を維持する機能の説明として使われます。**障害回復**はログなどで障害前後の正しい状態へ戻す機能、**機密保護**はアクセス権限などで利用を制限する機能なので、混同しないようにします。

スキーマの詳しい説明は[データベースのスキーマ](/fe/database-schema/)、SQLの書き方は[DDL・CREATE TABLE](/fe/sql-ddl-create-table/)、整合性の考え方は[一貫性と整合性](/fe/database-consistency/)を参照してください。

### 同時実行制御は、複数人の更新を調整する

在庫が10個のとき、2人が同時に「2個取り出す」処理を行うとします。どちらも古い在庫数10を読んで更新すると、実際には6個にすべきなのに8個と記録される可能性があります。

DBMSは、ロックやトランザクション制御などを使って、このような更新競合を防ぎます。ただし、適切なトランザクション設計や分離レベルの設定も必要です。

### 障害回復とバックアップは同じではない

バックアップはデータを復元できるようにコピーを保存することです。DBMSの障害回復は、バックアップに加えてログなどを利用し、障害前後の一貫した状態へ戻す仕組みを含みます。詳しくは[データベースのバックアップと回復](/fe/database-backup-recovery/)を確認してください。

### DBMSとDBAの違い

**DBMSはソフトウェア**、**DBA（Database Administrator）はデータベース管理者という役割**です。DBAはDBMSを設定して権限管理・監視・性能管理・復旧などを行います。[DBAの記事](/fe/database-administrator/)では担当範囲を詳しく整理しています。

## 科目Aでどう出る？

問題文に出る動詞から、どの機能かを判断します。

| 問題文の言葉 | 考える機能 |
|---|---|
| テーブル構造・キー・スキーマを定義する | データ定義・構成管理 |
| 主キー重複や参照制約違反を拒否する | 保全機能（整合性維持） |
| 検索・追加・更新・削除 | データ操作 |
| 権限・利用者ごとの許可 | 機密保護・アクセス制御 |
| 複数利用者による同時更新 | 同時実行制御 |
| ログ・障害後の復旧 | 障害回復 |

- イ：保全機能
- ウ：障害回復機能

### 確認問題

在庫データを複数の端末から更新するシステムで、同時更新による値の矛盾を防ぎたい。DBMSのどの機能が最も直接関係するでしょうか。

- ア：データの構造を定義する機能
- イ：同時実行を制御する機能
- ウ：利用者の画面を設計する機能

<details markdown="1">

**正解：イ**。複数の処理が同じデータを同時に操作するとき、競合を防ぐための同時実行制御が必要です。

- アは表などの構造の定義で、同時更新の競合に直接対応する機能ではありません。
- ウは通常DBMSそのものの主要機能ではなく、アプリケーションの画面設計です。

</details>

## どんな場面で使う？

受発注システム、設備保全履歴、会員管理、在庫管理など、複数利用者が共通のデータを利用する場面です。DBMSは、性能だけでなく、アクセス制御や復旧も含む運用を支えます。

## よくある誤解・混同

### 「DBMS＝データベースそのもの」？

異なります。データベースは管理対象のデータの集まり、DBMSはそれを管理するソフトウェアです。

### 「DBMSがあればデータの矛盾は絶対に起きない」？

いいえ。不適切なトランザクション処理や制約設定、業務ルールの誤りがあれば矛盾は生じ得ます。DBMSの仕組みを適切に使うことが大切です。

### 「DBAとDBMSは同じ」？

DBAは人の**役割**、DBMSは管理に使う**ソフトウェア**です。

## まとめ（試験直前用）

- DBMSはデータベースを定義・利用・保護・管理するソフトウェア。
- **構造の定義／検索・更新／機密保護／保全・整合性維持／同時実行制御／障害回復**を区別する。
- **定義機能はルールを作る、保全機能はルールを守らせる。**
- データベース＝データ、DBMS＝ソフトウェア、DBA＝管理者。
- 競合を防ぐなら同時実行制御、故障後の復旧なら障害回復。
