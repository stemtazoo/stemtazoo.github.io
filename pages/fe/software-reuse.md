## まず結論

ソフトウェア再利用とは、**既に作成・検証したソフトウェア部品を、新しいシステムやソフトウェアの開発で再び利用する考え方**です。

FE試験では、次の2つを分けると判断しやすくなります。

```text
再利用できる部品を作る
→ 汎用性や例外処理などを考える
→ 初期の開発工数は増えることがある

完成した部品を再利用する
→ 新しく作る部分を減らせる
→ 開発工数の削減を期待できる
```

つまり、**「再利用＝部品を作るときから必ず工数が減る」ではありません。**

## 直感的な説明

機械設計で、毎回専用部品を一から設計する場合と、いろいろな製品で使える標準部品を用意する場合を考えてみます。

専用部品なら、今回必要な条件だけを満たせばよいでしょう。

一方、標準部品として何度も使うなら、寸法の違いや使用条件の違いなど、より広い条件を考えて設計する必要があります。

ソフトウェアでも同じように考えられます。

```text
今回だけ使う部品
→ 今回の条件を中心に作る

何度も再利用する部品
→ 様々な使い方を想定する
→ 汎用性を持たせる
→ 異常時も考える
→ 十分に確認する
```

そのため、再利用可能な部品を最初に作るときには手間が増えることがあります。

しかし、一度使える部品ができれば、次の開発ではそれを利用できるため、一から作る部分を減らせます。

## 定義・仕組み

再利用の対象には、ソースコードだけでなく、ライブラリ、コンポーネント、モジュールなど様々な単位があります。

再利用を前提とした部品では、特定の一つの用途だけでなく、複数の場面で使えるように設計する必要があります。

例えば、次のような点を考えます。

| 観点 | 再利用部品で考えること |
|---|---|
| 入力 | 値やデータ数などの違いに対応する |
| 汎用性 | 特定用途だけに依存しすぎない |
| 異常時 | 想定外の入力やエラーを処理する |
| インタフェース | 他のソフトウェアから利用しやすくする |
| 品質 | 繰り返し利用できるよう十分に確認する |

このため、単純に同じ規模の専用ソフトウェアを作る場合と比べると、**再利用可能な部品そのものの開発工数が大きくなることがあります。**

一方、その部品を後から再利用するときには、新規開発する量を減らせます。

```text
最初
再利用部品を設計・実装・確認
→ 工数が必要

2回目以降
既存部品を利用
→ 新規開発部分を減らせる
```

## 科目Aでどう出る？

科目Aでは、再利用による工数削減について、**「部品を作る段階」と「部品を使う段階」を混同させる選択肢**に注意します。

判断するときは、まず「誰の工数について説明しているか」を確認します。

```text
再利用可能な部品を作る側？
→ 汎用性・例外処理などが必要
→ 工数が増えることがある

既存部品を使う側？
→ 新しく作る量を減らせる
→ 工数削減を期待できる
```

また、同じ機能を実現できるなら、多数の小さな部品を組み合わせるより、より大きな単位の部品を再利用できる方が、新しく開発する範囲を大きく減らせる場合があります。

試験では、単に「再利用だから工数削減」と判断せず、**どの段階の話か**を見ることが重要です。

## どんな場面で使う？

同じような機能を複数のシステムで使う場面では、再利用の考え方が役立ちます。

例えば、入力チェックやデータ変換など、複数のシステムで共通して必要になる処理を毎回一から作るのではなく、共通部品として利用する方法があります。

```text
システムA ─┐
システムB ─┼→ 共通部品を利用
システムC ─┘
```

ただし、再利用するには、その部品が新しい利用条件に適しているかを確認することも必要です。

既存コードだから無条件に安全・高品質というわけではありません。

## よくある誤解・混同

### 再利用なら、部品を作る工数も必ず少なくなる

違います。

再利用可能な部品は、複数の用途を想定して汎用的に設計するため、最初の開発工数が増えることがあります。

```text
作る側
→ 手間が増えることがある

使う側
→ 新規開発を減らせる
```

### 小さい部品ほど、必ず工数削減効果が大きい

そうとは限りません。

小さな部品を多数組み合わせるためにも、接続や調整の工数が必要です。

同じ機能を実現できるなら、より大きな単位を再利用できる方が、新規開発する範囲を大きく減らせる場合があります。

### 一度使ったコードなら、そのまま再利用できる

そうとは限りません。

新しいシステムの要求や利用環境に合っているか、必要な品質を満たしているかを確認する必要があります。

## まとめ（試験直前用）

- ソフトウェア再利用は、既存のソフトウェア部品を別の開発でも利用する考え方
- **再利用部品を作る側**は、汎用性や例外処理などのため工数が増えることがある
- **再利用部品を使う側**は、新規開発部分を減らして工数削減を期待できる
- 「再利用＝最初から必ず工数削減」と決めつけない
- 試験では、**作る側か、使う側か**を先に確認する
