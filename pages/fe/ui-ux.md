## まず結論

**UI（User Interface）は、利用者とシステムが情報をやり取りする接点です。UX（User Experience）は、製品やサービスの利用や利用への期待から生じる、利用者の体験・認識・反応です。**

科目Aでは、次の違いを押さえます。

> **ボタン・入力欄・操作への応答などの接点 → UI。利用前の期待から利用後の満足や不安まで含む体験 → UX。**

UIの改善はUXをよくする手段の一つです。ただし、UXには待ち時間やサービスの内容、問い合わせ対応なども影響するため、画面だけで決まるものではありません。

## 直感的な説明

飲食店の予約サイトを考えます。

希望日を選ぶカレンダー、人数の入力欄、「予約を確定する」ボタンはUIです。入力ミスの箇所を示すメッセージや、送信中であることを伝える表示もUIに含まれます。

一方、「条件に合う店を探せた」「迷わず予約できた」「予約が受け付けられたと分かって安心した」という体験はUXの観点です。画面が美しくても、予約が成立したか分からず何度も確認する必要があれば、利用者は不安を感じます。

**UIは利用者が操作・確認する仕組み、UXはその仕組みを含むサービスとの関わりで生じる体験**として区別します。

## 定義・仕組み

### UIとUXの比較

| 比較する観点 | UI | UX |
|---|---|---|
| 日本語での呼び方 | ユーザーインタフェース | ユーザーエクスペリエンス、利用者体験 |
| 着目するもの | 利用者とシステムの情報のやり取り | 利用者が感じる価値、安心、不満などを含む体験 |
| 予約サイトの例 | 日付の選択方法、ボタンの文言、完了通知の表示 | 目的の予約ができ、受付状況を把握して安心できること |
| 改善を考える問い | 何を入力し、何が表示され、どう操作するか | 利用者が目的を達成するまでに、どんな期待や困り事があるか |

UIは画面の見た目に限りません。音声で指示して音声で応答を受け取る仕組みもUIです。アイコンやメニューなどを使う視覚的な操作方式は、UIの一種である**GUI（Graphical User Interface）**です。

GUI部品の具体的な選び方は、[プルダウンメニューとは？](/fe/pull-down-menu/)で確認できます。このページでは、個々の部品よりも、UIとUXの対象範囲の違いを扱います。

### UXは利用前・利用中・利用後にまたがる

ネット予約の例を、利用者の行動順に整理します。

| 段階 | 利用者の状況 | 体験に関わる改善例 |
|---|---|---|
| 利用前 | 料金やキャンセル条件が分からず、予約してよいか迷う | 申込み前に条件を確認できるようにする |
| 利用中 | 入力ミスがあるが、どこを直せばよいか分からない | 該当する入力欄と修正方法を示す |
| 利用直後 | 送信は終わったが、予約が成立したか不安になる | 受付結果と予約内容を確認できるようにする |
| その後 | 日時を変更したいが、手続きが分からない | 変更方法や問い合わせ先を分かりやすく案内する |

この表の改善には、UIの改善も含まれます。**UIとUXは互いに無関係な二択ではなく、UIがUXに影響する関係**です。

例えば、受付結果を表示する仕組みはUIであり、その表示によって「予約できたと分かり安心する」のはUXの側面です。

### UXとユーザビリティの関係

**ユーザビリティ**は、特定の利用者が特定の利用状況で、目的を有効・効率的に、満足して達成できる度合いです。「使いやすさ」と説明されますが、単に操作回数が少ないことだけではありません。

予約サイトなら、希望の予約を正しく完了できるか、余計な手間がかからないか、利用者が満足して使えるかを確認します。

UXでは、こうした利用時の使いやすさに加えて、利用前の期待や利用後の印象なども捉えます。**ユーザビリティとUXは関係が深いものの、同じ意味ではありません。**

## 科目Aでどう出る？

### 選択肢が何を説明しているかを読む

| 選択肢の説明 | 判断する概念 |
|---|---|
| 利用者が入力し、システムから情報を受け取る接点 | UI |
| アイコンやウィンドウなどを用いて視覚的に操作する方式 | GUI |
| 製品やサービスの利用前後も含めた認識や反応 | UX |
| 特定の利用状況で、目的を有効・効率的に、満足して達成できる度合い | ユーザビリティ |

UIの説明なら**接点や操作方式**、UXの説明なら**利用者側の体験や反応**に着目します。

### 改善策と改善の目的を区別する

「予約確定ボタンの文言を分かりやすくし、利用者が安心して申し込めるようにする」という説明では、文言の変更はUIの改善策で、安心して申し込める体験はUXの改善目標です。

そのため、「ボタンを変更したからUXとは無関係」という選択肢は不適切です。反対に、「ボタンの色を変えれば必ずUXが改善する」ともいえません。利用者の困り事に合った変更かを確認する必要があります。

## どんな場面で使う？

画面改修の相談を受けたとき、見た目を変える前に、利用者がどこで困っているかを整理するために使います。

例えば、予約の途中離脱が多い場合、原因がボタンの見つけにくさなら、配置や文言の改善が候補です。しかし、最後の画面で初めて追加料金が分かることが原因なら、料金を提示するタイミングも見直す必要があります。

改善後は、予約を完了できた割合や操作中のつまずき、利用者の感想などを確認します。**一つの数値だけでUX全体が分かると考えず、行動と感想を合わせて確かめる**ことが大切です。

## よくある誤解・混同

### UIは見た目、UXは使いやすさ、とだけ覚えればよい？

それだけでは範囲が狭すぎます。UIには入力方法や操作への応答が含まれ、UXには利用前の期待や利用後の印象も含まれます。

### 見た目が美しければUXもよい？

見た目は体験に影響しますが、目的を達成できなかったり、処理結果が分からなかったりすると、不満や不安が生じます。外観だけでUXの良否は判断できません。

### 操作回数は少なければ少ないほどよい？

入力の手間を減らすことは役立ちますが、予約内容の確認まで省くと、誤った日時で確定してしまうおそれがあります。利用者の目的や誤操作の影響に応じて、確認の必要性を判断します。

### UIが同じなら、誰にとってもUXは同じ？

利用者の経験、目的、利用環境によって体験は異なります。使い慣れた人には分かる略語でも、初めての人には意味が伝わらない場合があります。

## 確認問題（科目A・オリジナル）

ある予約サイトでは、入力画面は見やすく、希望日時の選択も容易である。しかし、送信後に予約が成立したか分からず、利用者から確認の問い合わせが多い。UIとUXの関係を踏まえた対応として、最も適切なものはどれか。

- ア：UIは見やすいため、利用者が感じる不安は改善の対象に含めない。
- イ：UXは画面を操作している間だけの体験なので、送信後の状況は調べない。
- ウ：予約の受付結果と内容を確認できるようにし、利用者の不安や問い合わせが減るかを確認する。
- エ：ボタンの配色を変更すれば、予約成立への不安も必ず解消する。

**正解：ウ**

- ア：見やすさだけでUXは決まりません。予約成立を確認できず不安になる体験も改善対象です。
- イ：UXは操作中だけに限らず、利用前後の認識や反応も含みます。
- ウ：受付状況が分からないという困り事に対応し、変更後の体験まで確認するため適切です。
- エ：配色の変更だけで受付状況が伝わるとは限りません。原因に対応した改善が必要です。

## まとめ（試験直前用）

- **UIは利用者とシステムの接点、UXは利用や利用への期待から生じる体験・認識・反応。**
- UIは見た目だけでなく、入力方法や操作への応答も含む。
- UXは利用中だけでなく、利用前の期待や利用後の印象も含む。
- UIの改善はUXに影響するが、画面だけでUX全体は決まらない。
- 選択肢では、操作する仕組みと、利用者に生じる体験を区別する。
