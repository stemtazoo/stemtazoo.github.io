## まず結論

入力データのチェック問題では、**何が正しいかを確認しているのか**を見るのがポイントです。

特に迷いやすいのが、フォーマットチェックと論理チェックです。

```text
書き方・形式は正しい？
        ↓
フォーマットチェック

値どうしの関係に矛盾はない？
        ↓
論理チェック
```

例えば「注文日が入力日以前か」を調べるのは、日付の書式ではなく **注文日と入力日の関係**を確認しているため、論理チェックです。

## 直感的な説明

入力データを検査する係になったと考えてみましょう。

```text
① 順番どおり？
   → シーケンスチェック

② 同じデータがない？
   → 重複チェック

③ 書き方は正しい？
   → フォーマットチェック

④ 値の組合せとしてあり得る？
   → 論理チェック
```

この4つの「何を見るか」を区別できれば、用語を丸暗記する必要はありません。

## 定義・仕組み

代表的なチェックを整理すると次のようになります。

| チェック | 確認するもの | 例 |
|---|---|---|
| シーケンスチェック | データの順番 | 伝票番号が001→002→003と並んでいるか |
| 重複チェック | 同じデータの重複 | 同じ伝票番号が登録されていないか |
| フォーマットチェック | 書式・形式 | 日付や郵便番号が決められた形式か |
| 論理チェック | 項目間の論理的な関係 | 注文日が入力日より後になっていないか |

### フォーマットチェックと論理チェック

ここが最も重要な切り分けです。

例えば次のデータを考えます。

```text
注文日：2026/09/20
入力日：2026/09/22
```

「注文日が YYYY/MM/DD の形になっているか」を確認するなら、

```text
2026/09/20
     ↓
形式を見る
     ↓
フォーマットチェック
```

一方、「注文日が入力日より後になっていないか」を確認するなら、

```text
注文日        入力日
9/20    ≦     9/22
  │            │
  └── 関係を見る ──┘
          ↓
     論理チェック
```

つまり、

> **1項目の形を見る → フォーマット**
>
> **複数項目の関係を見る → 論理**

と覚えると切り分けやすくなります。

## いつ使う？

入力時のミスや、業務上あり得ないデータを早い段階で見つけるために使います。

例えば、次のようなチェックが考えられます。

```text
貸出日 ≦ 返却日
→ 論理チェック

仕入数 ≧ 販売数
→ 論理チェック

伝票番号が重複していない
→ 重複チェック

郵便番号が決められた形式
→ フォーマットチェック
```

実務では複数のチェックを組み合わせて、入力データの妥当性を確認します。

## よくある誤解・混同

### 「日付を確認する」ならフォーマットチェック？

必ずしもそうではありません。

```text
日付の書き方を見る
2026/09/22
     ↓
フォーマットチェック

2つの日付の前後関係を見る
注文日 ≦ 入力日
     ↓
論理チェック
```

**データ型が日付だから決まるのではなく、何を検査しているかで決まる**ことに注意します。

### シーケンスチェックと論理チェック

どちらも「順序」に見える場合があります。

シーケンスチェックは、データそのものが決められた順番で並んでいるかを確認します。

```text
001 → 002 → 003 → 004
       ↑
データの並び
```

論理チェックは、異なる項目の値の関係に矛盾がないかを確認します。

```text
注文日 ≦ 入力日
   ↑
項目間の関係
```

## まとめ

試験では、チェック名を見たら次の4つに置き換えて考えます。

```text
順番？
→ シーケンス

同じもの？
→ 重複

書き方？
→ フォーマット

値どうしの関係？
→ 論理
```

特に、

> **「AがB以前か」「AがB以上か」のように、複数項目を比較して矛盾を探す → 論理チェック**

という判断基準を持っておくと、選択肢を切りやすくなります。
