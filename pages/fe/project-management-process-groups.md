## まず結論

プロジェクトマネジメントのプロセス群とは、**プロジェクトを管理する活動を「何をしている段階か」でまとめたもの**です。

基本情報技術者試験では、次の5つを押さえます。

| プロセス群 | ひとことで言うと |
|---|---|
| 立ち上げ | プロジェクトを始める |
| 計画 | どう進めるか決める |
| 実行 | 計画したことを実行する |
| 管理 | 進み具合を確認し、必要なら修正する |
| 終結 | プロジェクトを正式に終える |

試験中は、用語を丸暗記するよりも、

> **「始める・決める・やる・確認して直す・終える」のどこか？**

と考えると選択肢を切りやすくなります。

なお、IPAの基本情報技術者試験シラバスでは、「立ち上げ」「計画」「実行」「管理」「終結」の五つのプロセス群を理解することが示されています。

## 直感的な説明

例えば、社内システムを導入するプロジェクトを考えます。

```text
立ち上げ
「このプロジェクトを始めよう」
        ↓
計画
「何を、いつ、誰が、どのくらいの費用で進める？」
        ↓
実行
「計画に沿って作業しよう」
        ↓
管理
「予定どおり？ずれていたら直そう」
        ↓
終結
「成果を確認して正式に終わろう」
```

この流れを頭に置いておくと、知らない用語が選択肢に出ても、**その作業の目的からプロセス群を推測**できます。

ただし、プロセス群は単純な開発工程そのものではありません。実際のプロジェクトでは、計画と実行、管理などが関係しながら進みます。

## 定義・仕組み

### 1. 立ち上げのプロセス群

プロジェクトやフェーズを正式に始めるための活動です。

代表的なイメージは次のとおりです。

```text
プロジェクトを正式に開始する
関係するステークホルダを把握する
```

試験では、**「開始」「承認」「関係者の特定」**が合図になります。

### 2. 計画のプロセス群

プロジェクトの目標を達成するために、**どのように進めるかを具体化する活動**です。

例えば、次のような内容を計画します。

- スコープ
- スケジュール
- コスト
- 品質
- 資源
- リスク
- 調達
- コミュニケーション

WBSによる作業の分解も、計画を具体化するために使われます。詳しくは[WBSとは？](/fe/wbs/)で整理しています。

試験では、**「定義」「計画」「見積り」「作成」**など、これから行うことを決める表現に注目します。

### 3. 実行のプロセス群

計画した内容に従って、**人やその他の資源を使い、実際にプロジェクトの作業を進める活動**です。

```text
計画を作る
→ 計画

計画に従って作業する
→ 実行
```

「実施する」「遂行する」「チームを動かす」といった表現が判断材料になります。

### 4. 管理のプロセス群

プロジェクトが計画どおり進んでいるかを確認し、差異があれば必要な対応を行う活動です。

```text
計画
  ↓ 比較
実績
  ↓
差異を発見
  ↓
必要なら是正
```

試験では、**「監視」「測定」「比較」「差異」「是正」**が強い合図です。

資料によっては「監視・コントロール」と表現されることがありますが、FEではIPAシラバスの「管理のプロセス群」という名称を基準に整理しておくとよいでしょう。

### 5. 終結のプロセス群

プロジェクトやフェーズを**正式に終了させる活動**です。

成果物の受入れや完了手続きなど、「終わらせるための活動」が中心です。

試験では、**「完了」「受入れ」「終了」**といった表現を手掛かりにします。

### プロセス群と対象群は別の分類

ここは特に混同しやすいところです。

IPAシラバスでは、五つの「プロセス群」と、十の「対象群」が別に示されています。

```text
プロセス群
→ いつ・何をしている段階か

対象群
→ 何を管理しているか
```

例えば「スコープ」は対象群の一つです。

一方、「スコープを定義する」という活動は、プロジェクトの進め方を決める**計画**として考えます。

| 見る方向 | 例 |
|---|---|
| プロセス群 | 立ち上げ、計画、実行、管理、終結 |
| 対象群 | スコープ、時間、コスト、品質、リスクなど |

この縦横の違いを理解しておくと、選択肢を整理しやすくなります。

公式の出題範囲は、[IPA：試験要綱・シラバス](https://www.ipa.go.jp/shiken/syllabus/gaiyou.html)で確認できます。

## 科目Aでどう出る？

科目Aでは、ある活動がどのプロセス群に属するかを問う形が考えられます。

まず、問題文の**動詞**に注目します。

| 問題文の合図 | 考えるプロセス群 |
|---|---|
| 開始する、承認する、関係者を特定する | 立ち上げ |
| 定義する、計画する、見積もる | 計画 |
| 実施する、遂行する | 実行 |
| 監視する、測定する、差異を確認する、是正する | 管理 |
| 受け入れる、完了する、終了する | 終結 |

例えば「スコープ」という名詞だけを見ると、プロセス群は判断できません。

```text
スコープを定義する
→ これから行う範囲を決める
→ 計画

進行中のスコープを監視する
→ 計画と実績を確認する
→ 管理
```

**名詞より「何をしているか」を見る**のがポイントです。

## どんな場面で使う？

実務では、プロジェクトマネジメント活動を整理するときに役立つ考え方です。

例えば、新しい設備管理システムを導入するとします。

```text
立ち上げ
→ 導入プロジェクトを正式に開始する

計画
→ 対象範囲、日程、費用、担当を決める

実行
→ 計画に沿って導入作業を進める

管理
→ 進捗や費用を計画と比較し、必要なら修正する

終結
→ 成果を確認し、プロジェクトを終了する
```

プロセス群を知っていると、「今どんな管理活動をしているのか」を整理しやすくなります。

## よくある誤解・混同

### プロセス群は開発工程と同じ

同じではありません。

要件定義、設計、実装、テストなどは、システム開発の工程として整理されるものです。

一方、プロセス群はプロジェクトを**どう管理するか**という視点です。

```text
何を開発している段階か
→ 開発工程

プロジェクトをどう管理しているか
→ プロセス群
```

### 「作成」と書いてあれば全部計画

そうとは限りません。

例えば、プロジェクトを正式に開始するための文書を作る活動は、立ち上げに関係します。

動詞だけで機械的に決めず、**その作業の目的が「始めるため」なのか「進め方を決めるため」なのか**まで確認します。

### ステークホルダに関する活動は全部立ち上げ

違います。

関係者を最初に特定する活動と、プロジェクト中に関係者との関係を管理する活動では役割が異なります。

```text
誰が関係するか把握する
→ 立ち上げ

関係者と調整しながら進める
→ 実行や管理の文脈
```

### スコープはプロセス群の一つ

違います。

スコープは「何を管理するか」という**対象群**です。

計画は「どの段階の活動か」という**プロセス群**です。

FEでは、この二つの分類軸を混ぜないことが重要です。

## まとめ（試験直前用）

- **立ち上げ**：始める
- **計画**：どう進めるか決める
- **実行**：計画したことを行う
- **管理**：計画と実績を比べ、必要なら直す
- **終結**：正式に終える
- プロセス群は「何をしている段階か」、対象群は「何を管理しているか」
- 選択肢では名詞だけでなく、**動詞と目的**を見る

> **始める → 決める → やる → 確認して直す → 終える**

この流れを軸にすると、プロセス名をすべて丸暗記しなくても判断しやすくなります。
