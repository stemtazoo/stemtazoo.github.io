## まず結論

コーディング規約は、プログラムを**安全で読みやすく、保守しやすくするためのルール**です。

FEでは細かな規約を丸暗記するより、次の方向を見ると判断しやすくなります。

| 視点 | 基本的な考え方 |
|---|---|
| 変数 | 1つの変数に複数の役割を持たせない |
| ループ制御 | 用途に合った型を使う |
| 繰返し処理 | むやみに再帰呼出しにしない |
| 失敗する可能性がある処理 | 失敗時の処理も用意する |

特に重要なのは、**失敗する可能性があるなら、失敗した場合も処理する**という考え方です。

## 直感的な説明

同じ整数型だからといって、一つの変数を「件数→添字→金額」のように使い回すと、今何を表しているのか分かりにくくなります。

逆に、countは件数、indexは添字、priceは金額というように役割を分ければ意図が伝わります。

**型が同じ＝同じ変数を使う、ではありません。**

## 定義・仕組み

### 1つの変数には1つの役割

用途が異なるなら、同じデータ型でも別の変数として定義し、用途が分かる名前を付ける方が読みやすくなります。

### ループ制御には用途に合った型

回数や添字を数えるループ制御変数には、その用途に合った整数型を使うのが基本です。浮動小数点数には表現誤差があるため、正確な回数の管理には向きません。

### 再帰呼出しは「繰返しだから使う」ものではない

再帰呼出しは、関数が自分自身を直接または間接的に呼び出す処理です。再帰が自然な問題もありますが、同じ処理を繰り返すだけならループや共通処理の関数化も検討します。

再帰は呼出しごとにスタックを使うため、深くなり過ぎると問題になることがあります。

### メモリ確保は失敗する可能性がある

C言語などで動的にメモリを確保する処理は、必ず成功するとは限りません。

~~~c
p = malloc(size);

if (p == NULL) {
    /* メモリ確保に失敗したときの処理 */
}
~~~

重要なのは関数名の暗記ではなく、**成功するとは限らない処理→結果を確認→失敗時を処理**という流れです。

## 科目Aでどう出る？

選択肢を「安全で読みやすい方向か」で確認します。

| 選択肢の特徴 | 判断 |
|---|---|
| 同じ型なら変数を使い回す | ❌ 役割が分かりにくい |
| 高速化のためループ制御に浮動小数点型 | ❌ 用途に合わない |
| 繰返しは常に再帰呼出し | ❌ 再帰が適するとは限らない |
| メモリ確保失敗時の処理を書く | ⭕ 安全性を高める |

迷ったら、**役割が明確か、用途に合うか、失敗に備えているか**を確認します。

## どんな場面で使う？

複数人で開発すると、書き方が人によって大きく違えばレビューや修正に時間がかかります。

コーディング規約では、命名、書式、変数の扱い、エラー処理、避けるべき記述などに一定のルールを設けます。

目的は見た目をそろえるだけではなく、コードを理解しやすくし、間違いを見つけやすくして、修正・保守をしやすくすることです。

## よくある誤解・混同

### 同じデータ型なら変数を使い回す？

用途が違うなら役割を分けます。わずかな変数削減より、コードの意味が明確であることを優先します。

### 浮動小数点型なら処理が速い？

そのようには判断できません。型は「速そうだから」ではなく、扱うデータと用途に合わせて選びます。

### 同じ処理を繰り返すなら再帰？

**繰返し＝再帰ではありません。** 再帰は問題の構造に合う場合に使う手法です。

### エラー処理は失敗してから考える？

失敗する可能性が分かっている処理では、あらかじめ失敗時の動作を考えます。これはメモリ確保だけでなく、ファイル操作や通信にも共通する考え方です。

## まとめ（試験直前用）

- **役割を明確にする**
- **用途に合った型・方法を使う**
- **失敗する可能性がある処理では失敗時も考える**
- 型が同じでも用途が違えば、むやみに変数を使い回さない
- 繰返しと再帰を同一視しない
- メモリ確保では失敗を確認してから後続処理へ進む

試験では細かな規約の暗記より、**読みやすさ・安全性・保守性を高める方向の選択肢**を探すのがポイントです。
