## まず結論

**プロジェクト統合マネジメント**は、スコープ・納期・コスト・品質・人員など、複数の管理分野を**全体として調整する活動**です。

基本情報技術者試験（FE）では、変更要求が発生したときに、単独の分野だけで決めず、**他の分野への影響も評価して判断する**ことが重要です。

> 変更をすぐ受け入れることでも、すべて拒否することでもありません。全体への影響を考え、必要な承認を得て管理します。

## 直感的な説明

設備監視システムの開発中に「新しいセンサーも追加したい」という要望が出たとします。

```text
新しいセンサーを追加したい
         ↓
機能（スコープ）はどう変わる？
納期は延びる？
費用や人員は足りる？
品質やリスクに影響はある？
         ↓
全体の影響を確認して承認・却下を判断
         ↓
承認された変更を計画と成果物へ反映
```

これが統合マネジメントのイメージです。例えばスコープだけを見て機能を追加すると、納期やコストを守れなくなる場合があります。

## 定義・仕組み

### 統合マネジメントと変更管理

統合マネジメントでは、計画の整合性を保ち、プロジェクト全体を調整します。変更管理はその重要な場面です。

| 手順 | 何をする？ |
|---|---|
| 1. 変更要求を受け付ける | 変更の目的と内容を確認 |
| 2. 影響を分析する | スコープ・スケジュール・費用・品質・リスクなどを検討 |
| 3. 承認・却下を決める | 決められた責任者・変更管理の仕組みで判断 |
| 4. 承認した変更を反映する | 計画・基準・必要な文書を更新 |
| 5. 実施結果を確認する | 変更が適切に反映されているか確認 |

**スコープ管理**は「何をどこまで作るか」、**統合マネジメント**はスコープ変更が納期・費用などにも及ぼす影響を横断的に調整することに着目します。

詳細は[プロジェクトのスコープ](/fe/project-scope/)で扱います。

### PMBOK第6版での10の知識エリア

**PMBOKガイド第6版**では、プロジェクトマネジメントを次の**10の知識エリア**に分けて整理していました。旧版の用語で書かれた問題や教材を読む際に役立ちます。

| 知識エリア（第6版の分類） | 何を管理する？ |
|---|---|
| 統合 | 複数分野を調整し、全体の整合性を確保 |
| スコープ | 実施する作業と成果物の範囲 |
| スケジュール | 作業の日程・進捗 |
| コスト | 予算・費用 |
| 品質 | 成果物やプロセスの品質 |
| 資源 | 人・設備などの資源 |
| コミュニケーション | 情報の共有・伝達 |
| リスク | 不確実性による脅威と機会 |
| 調達 | 外部からの製品・サービス等の入手 |
| ステークホルダー | 関係者の特定と関与の調整 |

**最新版のPMBOKが今も「10の知識エリア」をそのまま採用している、と覚えないこと**が重要です。PMBOKガイド第8版（2025年11月公表）では、7つのパフォーマンス領域（ガバナンス、スコープ、スケジュール、ファイナンス、ステークホルダー、資源、リスク）と6つの基本原則を示しています。

| 比較 | PMBOKガイド第6版 | PMBOKガイド第8版 |
|---|---|---|
| 学習上の代表的な整理 | 10の知識エリア | 7つのパフォーマンス領域 |
| 注目点 | 管理分野ごとの知識・プロセス | 価値の提供と相互に関係する実践領域 |
| FEの学習 | 旧来の選択肢の読み解きに役立つ | 現行のPMI資料との違いに注意 |

### IPAの「10の対象群」とPMBOK第6版の「10の知識エリア」

**IPAの基本情報技術者試験シラバス（Ver.9.2）**では、プロジェクトマネジメントの**10の対象群**として「統合・ステークホルダ・スコープ・資源・時間・コスト・リスク・品質・調達・コミュニケーション」を挙げています。一方、上の表は**PMBOKガイド第6版の10の知識エリア**で、「時間」に相当する領域を「スケジュール」と呼ぶなど、名称や体系の前提が異なります。

| 比較 | IPAのFEシラバス | PMBOKガイド第6版 |
|---|---|---|
| 分類名 | 10の対象群 | 10の知識エリア |
| 日程を管理する項目の名称 | 時間の対象群 | プロジェクト・スケジュール・マネジメント |
| 試験での読み方 | IPAシラバスの用語を基準にする | PMBOKの版が指定されたら、その版の分類で読む |

**どちらも10項目だから同じ分類名だと決めつけず、問題文がどの資料・版を前提にしているか確認してください。**

- [IPA公式：基本情報技術者試験シラバスの最新版](https://www.ipa.go.jp/shiken/syllabus/gaiyou.html)
- [PMI公式：PMBOKガイド第6版](https://www.pmi.org/shop/p-/book/a-guide-to-the-project-management-body-of-knowledge-%28pmbok-guide%29-%E2%80%94-sixth-edition-and-agile-practice-guide-%28english%29/00101602400)

分類が変わっても、**変更要求の影響を横断的に評価し、全体を整合させる**という実務上の考え方は重要です。FEでは問題文が前提とする用語・規格を確認しましょう。

- [PMI公式：PMBOKガイド第8版](https://www.pmi.org/standards/pmbok)
- [PMI日本支部：第8版日本語版の案内](https://www.pmi-japan.org/post-25662/)
- [ISO公式：ISO 21502:2020](https://www.iso.org/standard/74947.html)

### プロセス群・知識エリア・PDCAの違い

| 用語 | 見分ける視点 |
|---|---|
| プロセス群 | 立ち上げ・計画・実行・管理・終結など、**何をしているか** |
| 知識エリア（旧版） | 統合・スコープ・コストなど、**何を管理するか** |
| PDCA | 計画・実行・評価・改善を繰り返す**改善サイクル** |

プロセス群と知識エリアは同じ分類ではありません。また、**PDCAのCheckやActを、PMBOKの特定のプロセス群と完全に一対一対応させない**ことが大切です。

プロセス群の詳細は[5つのプロセス群](/fe/project-management-process-groups/)へ進んでください。

### 触って覚える：変更要求をどう判断する？

まず自分で対応を予想し、その後に理由を開いてください。

<details markdown="1">
<summary>ケース1：機能追加により、予算と納期にも影響が出る</summary>

**統合マネジメントの視点**が重要です。スコープだけでなく費用やスケジュールなどの影響を確認し、変更を判断します。

</details>

<details markdown="1">
<summary>ケース2：今回作る機能と対象外の機能を決める</summary>

中心になるのは**スコープマネジメント**です。作業と成果物の範囲を定義します。

</details>

<details markdown="1">
<summary>ケース3：今後起こるかもしれない部品納期遅延への対応策を考える</summary>

中心になるのは**リスクマネジメント**です。発生していない不確実な事象への対応を検討します。

</details>

<details markdown="1">
<summary>ケース4：関係者に進捗と変更内容を報告する</summary>

主に**コミュニケーションマネジメント**です。誰に何をいつ伝えるかを整理します。

</details>

## 科目Aでどう出る？

**「各管理分野の計画を調整し、全体として矛盾しないようにする」**とあれば統合マネジメントが候補です。

### 確認問題

新機能の追加要求があったため、プロジェクト責任者が費用・納期・品質・リスクへの影響を確認した上で、決められた承認手順に従って変更を判断する。この活動に最も関係するマネジメントはどれか。

- ア：統合マネジメント
- イ：調達マネジメント
- ウ：コミュニケーションマネジメント

<details markdown="1">
<summary>正解と理由を見る（タップして開く）</summary>

**正解：ア。** 複数の管理分野の影響を横断的に評価し、変更を統制するためです。

</details>

## どんな場面で使う？

システム開発、設備更新、製造ラインの改善など、複数の部署と管理分野が関わるプロジェクトで重要です。プロジェクトマネージャや関係者が、個別最適ではなく全体最適を考えるときに役立ちます。

## よくある誤解・混同

### 「統合マネジメントはすべての作業を一人で担当すること」？

違います。各専門分野の担当者と調整して、全体の整合性を保つことが目的です。

### 「変更要求があれば、すぐ計画を変更する」？

違います。影響を分析し、必要な承認を経てから反映します。

### 「PMBOKの10の知識エリアは現在の最新版でも同じ」？

違います。第6版の分類と第8版のパフォーマンス領域を区別しましょう。

## まとめ（試験直前用）

- **統合マネジメント**は各管理分野を横断し、全体を調整する。
- **変更要求 → 影響分析 → 承認判断 → 計画への反映**が基本の流れ。
- PMBOK第6版の**10の知識エリア**と、第8版の**7つのパフォーマンス領域**は別の分類。
- **プロセス群**は活動の種類、**知識エリア**は管理対象、**PDCA**は改善サイクル。
