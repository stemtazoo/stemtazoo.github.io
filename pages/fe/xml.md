## まず結論

**XML（Extensible Markup Language）とは、利用目的に合わせて名前を決めたタグを使い、データの構造や意味を記述するマークアップ言語**です。

科目Aでの判断基準は、**「独自タグを定義できる」「データを構造化する」「システム間で交換する」**の3つです。

XMLはWebページの表示をきれいにするためだけの言語ではありません。

## 直感的な説明

例えば、工場の温度センサが測定結果を別のシステムに送る場面を考えます。

~~~xml
<measurement id="T01">
  <sensor>Temperature</sensor>
  <value>65.2</value>
  <unit>degC</unit>
</measurement>
~~~

この例では、自分たちで決めたタグによって、次のように意味を伝えています。

| 記述 | 意味 |
|---|---|
| `measurement` | 測定データ全体 |
| `id="T01"` | 測定データの識別情報（属性） |
| `sensor` | センサの種類 |
| `value` | 測定値 |
| `unit` | 単位 |

`value` が単なる数字ではなく「測定値」を表すと読み取れるのがポイントです。

ただし、**XMLを使うだけで、異なるシステムが自動的に同じ意味で解釈するわけではありません**。タグ名やデータの取り決めを共有することで、交換しやすくなります。

## 定義・仕組み

### タグ・要素・属性

XMLでは、開始タグと終了タグで内容を囲みます。

~~~xml
<temperature unit="degC">65.2</temperature>
~~~

- `<temperature>`：開始タグ
- `65.2`：要素の内容
- `</temperature>`：終了タグ
- `unit="degC"`：属性

タグの名前は用途に応じて決められますが、**名前の付け方や文書全体の構文には規則**があります。何でも自由に書いてよいわけではありません。

### XML文書の基本ルール

代表的なルールを押さえましょう。

| ルール | 例 |
|---|---|
| 開始タグと終了タグを対応させる | `<a>値</a>` |
| 要素を正しく入れ子にする | `<a><b>値</b></a>` |
| ルート要素を1つにする | `<data>...</data>` |
| 要素名の大文字・小文字を区別する | `<A>` と `<a>` は別 |
| 属性値を引用符で囲む | `id="T01"` |

例えば、`<a><b>値</a></b>` は閉じる順序が逆なので、正しいXMLではありません。

### XML宣言とDTDは何が違う？

XML文書の先頭には、次のようなXML宣言を記述できます。

~~~xml
<?xml version="1.0" encoding="UTF-8"?>
~~~

これはXMLのバージョンや文字エンコーディングを示します。**XML宣言は必須ではありません**が、記述する場合には位置などのルールがあります。

一方、**DTD（Document Type Definition）**は、要素・属性・並び方など、文書の構造上のルールを定義する仕組みです。DTDやXML Schemaの詳しい違いは[DTDとは？](/fe/xml-dtd/)で説明しています。

### SGMLとの関係

W3CのXML 1.0仕様では、**XMLはSGMLを制限した形式**と説明されています。

HTMLの初期の規格もSGMLを基礎としていました。ただし、**現代のHTMLは独自の構文と解析規則を持つ**ため、現在のHTML文書をそのままSGML文書と考えないようにしましょう。

SGML自体の役割は[SGMLとは？](/fe/sgml/)で整理しています。

## 科目Aでどう出る？

試験では、文中の**目的・役割**を手掛かりに切り分けます。

| 判断の手掛かり | 選ぶ用語 |
|---|---|
| **独自タグを使ってデータの構造や意味を表す** | **XML** |
| Webページの文書構造を記述する | HTML |
| XMLなどの基礎となった汎用的な文書記述規格 | SGML |
| 色・余白などの表示スタイルを指定する | CSS |
| XMLの変換・整形に関する仕組み | XSL・XSLT |
| キーと値を中心とした軽量なデータ交換形式 | JSON |
| XMLに許される要素や属性などのルールを定義する | DTD |

### CSSとXSLのひっかけ

**「XMLにはCSSを使用できない」は誤り**です。

W3Cでは、**CSSはHTMLにもXMLにも利用できる**と説明しています。一方、XSLにはXMLの表示・変換に関する仕組みがあり、XSLTはXMLなどのデータを変換する技術です。

したがって「HTMLはCSS、XMLはXSLしか使えない」という覚え方は避けます。

## どんな場面で使う？

XMLは、設定ファイルやシステム間での構造化データの交換などに利用されます。

例えば、設備Aが温度測定値をXMLとして出力し、設備管理システムBがそれを読み取ることができます。

~~~text
設備A（測定）
    ↓ XML：測定値・単位・識別情報
設備管理システムB（保存・分析）
~~~

実際にはシステム間でタグや値の意味を取り決め、必要に応じてDTDやXML Schemaで形式を検証します。

Web APIではJSONもよく使われますが、**XMLとJSONはどちらもデータ交換に使える形式**です。両者の詳しい比較は[JSONとは？](/fe/json/)で確認できます。

## よくある誤解・混同

### XMLはHTMLの表示機能を高めるためのもの？

違います。XMLが重視するのは**データの構造や意味**です。画面表示の改善が主目的ではありません。

### XMLではどんなタグでも無条件に使える？

違います。用途に応じたタグ名は定義できますが、**構文規則**を満たす必要があります。また、相手システムとのデータ交換には共通の取り決めも必要です。

### XMLはCSSを使えない？

違います。**CSSはXMLにも使えます**。XSLが存在することは、XMLでCSSが使えないことを意味しません。

### XMLはSGMLと無関係？

違います。XMLは**SGMLを基礎とした制限された形式**です。

### XMLとDTDは同じ？

違います。XMLは実際のデータを記述する形式であり、DTDはXML文書の**構造のルールを定義する仕組み**です。

## まとめ（試験直前用）

- **独自タグ・構造化データ・システム間の交換** → XML
- **Webページの文書構造** → HTML
- **汎用的な文書記述規格（XMLの基礎）** → SGML
- **表示スタイル** → CSS（XMLにも利用可能）
- **XMLの変換** → XSLT、**XML文書の構造ルール** → DTD
