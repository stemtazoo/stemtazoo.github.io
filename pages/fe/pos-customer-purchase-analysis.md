## まず結論

**POS（販売時点情報管理）**は、商品が売れた時点の情報を記録・集計する仕組みです。

POSの販売記録にポイントカードなどの**顧客ID**を結び付けると、「誰が何を何回買ったか」を集計でき、**同じ商品の購入頻度**を確認できます。

ただし、購入履歴だけでは「なぜ買ったか」や「誰が実際に使ったか」は確定できません。

## 直感的な説明

コンビニで、同じ人が月曜日と金曜日に同じ飲料を買ったとします。

```text
月曜日：顧客A → 飲料Xを購入
金曜日：顧客A → 飲料Xを購入
           ↓
顧客Aは飲料Xを2回購入した
```

顧客IDがなければ「飲料Xが2本売れた」ことは分かっても、同じ人が買ったかどうかは通常分かりません。

## 定義・仕組み

POSデータには、販売日時、商品コード、数量、価格、店舗などが記録されます。顧客IDが結び付けば、顧客別の集計もできます。

| 顧客ID | 日付 | 商品 | 数量 |
|---|---|---|---:|
| A | 10/1 | 飲料X | 1 |
| B | 10/1 | 飲料X | 1 |
| A | 10/5 | 飲料X | 1 |
| A | 10/8 | 菓子Y | 2 |

この表から、顧客Aが飲料Xを購入した回数は2回と分かります。

**購入回数と購入数量は別物**です。菓子Yは1回の購入で2個買っています。

## 科目Aでどう出る？

問題文の「どの情報を収集したか」を確認します。

| 確認したいこと | POSと顧客IDだけで分かる？ |
|---|---|
| 同一商品の購入頻度 | ○：顧客別の購入記録から集計できる |
| 商品の最終的な使用者 | ×：購入者と使用者は同じとは限らない |
| 店舗までの流通経路 | ×：物流・仕入れの記録が別に必要 |
| 商品を購入した動機 | ×：アンケートなど別の情報が必要 |

**「顧客ID付きPOS」→「誰が・いつ・何を買ったか」**と読み替えると、選択肢を切りやすくなります。

## どんな場面で使う？

店舗では、リピート購入の傾向を調べて品ぞろえや販促を検討します。

例えばPythonの`pandas`でも、次のように集計できます。

```python
import pandas as pd

sales = pd.DataFrame({
    "customer": ["A", "B", "A", "A"],
    "product": ["飲料X", "飲料X", "飲料X", "菓子Y"],
    "quantity": [1, 1, 1, 2],
})

# 各行が1回の購入明細である例
frequency = (
    sales.groupby(["customer", "product"])
    .size()
    .reset_index(name="purchase_count")
)
print(frequency)
```

この例では、顧客Aの飲料Xは`purchase_count = 2`です。実際のデータで1回の会計が複数行に分かれる場合は、取引IDを使って購入回数を数えます。

顧客IDを扱う際は、個人情報の保護や適切な利用目的にも注意が必要です。

## よくある誤解・混同

- **販売数量＝購入頻度ではない**：一度に3個買っても、購入回数は1回です。
- **購入者＝使用者とは限らない**：家族への購入や贈り物もあります。
- **購入履歴＝購入動機ではない**：購入した事実は分かっても、理由は推定にとどまります。
- **POS＝物流追跡ではない**：店舗に届くまでの経路を調べるには別の情報が必要です。

## まとめ（試験直前用）

- POSは「いつ・どこで・何が・どれだけ売れたか」を記録する。
- 顧客IDを結び付けると、顧客ごとの同一商品購入頻度を調べられる。
- 購入数量と購入回数を混同しない。
- 購入動機、最終使用者、流通経路はPOSの購入記録だけでは確定できない。
