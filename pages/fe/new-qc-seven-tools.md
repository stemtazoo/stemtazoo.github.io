## まず結論

**新QC七つ道具は「何を整理したいか」で見分けます。** どれも問題解決に使うため、「改善に役立つ」という説明だけでは区別できません。

| 手法 | 何をする？ | 選択肢を切る言葉 |
|---|---|---|
| 親和図法 | 似た情報をまとめる | 類似・グループ化 |
| 連関図法 | 原因と結果の複雑なつながりを整理する | 因果関係・相互関係 |
| 系統図法 | 目的から手段を段階的に展開する | 目的・手段・階層 |
| マトリックス図法 | 二つ以上の項目群の対応を表にする | 行と列・対応関係 |
| アローダイアグラム法 | 作業の順序や所要時間を整理する | 先行作業・日程・クリティカルパス |
| PDPC法 | 途中で起こり得る問題と対策を考える | 予測・不測の事態・対応策 |
| マトリックスデータ解析法 | 数値データを統計的に分析し、特徴を整理する | 数値・多変量・主成分分析 |

> **似たものをまとめる／原因をつなぐ／手段を広げる／表で対応づける／順序を決める／先回りして備える／数値を分析する**、の7つで整理しましょう。

## 直感的な説明

同じ「システム開発が遅れている」という課題でも、知りたいことによって手法が変わります。

| 知りたいこと | 選ぶ手法 |
|---|---|
| 現場から集まった不満を種類別に整理したい | 親和図法 |
| 人手不足や仕様変更が、どのように遅延へつながったか知りたい | 連関図法 |
| 納期を守るための具体策を洗い出したい | 系統図法 |
| 各対策が品質・費用・納期のどれに関係するか比較したい | マトリックス図法 |
| 設計・実装・テストの実施順序と日程を決めたい | アローダイアグラム法 |
| テストが失敗した場合の代替策を事前に用意したい | PDPC法 |
| 多数の数値指標を少数の特徴にまとめて傾向をつかみたい | マトリックスデータ解析法 |

## 定義・仕組み

### 1. 親和図法：似た情報をまとめる

利用者の意見をカードに書き出し、内容が近いものをグループにします。**情報の意味の近さ**が判断基準です。

```text
「文字が小さい」「画面が見づらい」→ 表示の問題
「検索が遅い」「待ち時間が長い」→ 性能の問題
```

詳しくは[親和図法](/fe/affinity-diagram/)を参照してください。

### 2. 連関図法：原因同士のつながりを整理する

複数の原因が影響し合う問題について、**原因と結果を矢印で結びます**。

```text
人員不足 → テスト不足 ─┐
仕様変更 → 手戻り増加 ─┼→ 開発遅延
連絡不足 → 認識違い ─┘
```

「因果関係」が決め手です。単に似た項目を集める親和図法とは異なります。

### 3. 系統図法：目的から手段を展開する

大きな目標を達成するための手段を、階層的に具体化します。

```text
開発遅延を防ぐ
├─ 作業を効率化する
│  ├─ 自動テストを導入する
│  └─ 手順を標準化する
└─ 人員を確保する
   ├─ 応援を依頼する
   └─ 担当を見直す
```

**目的→手段**という方向で考えます。

### 4. マトリックス図法：項目同士の対応を表にする

行と列に異なる項目群を並べ、関連の強弱を整理します。

| 改善策 | 品質 | 納期 |
|---|---|---|
| 自動テスト | ◎ | ○ |
| 人員追加 | △ | ◎ |

「項目群の対応関係」が中心です。**数値データを統計的に要約するマトリックスデータ解析法とは別**です。

### 5. アローダイアグラム法：作業順序と日程を整理する

作業の前後関係と所要時間を表し、全体の所要日数や、遅れると全体に影響する**クリティカルパス**を把握します。

```text
設計（3日）→ 実装（5日）→ テスト（2日）
```

「作業の順序・日程・所要時間」が決め手です。図の要素は[アローダイアグラムの読み方](/fe/arrow-diagram/)、経路ごとの日数計算は[クリティカルパスの求め方](/fe/critical-path-1/)で確認できます。

### 6. PDPC法：途中の問題を予測して対策する

PDPCは **Process Decision Program Chart** の略で、日本語では**過程決定計画図**といいます。

| 英語 | 意味 |
|---|---|
| Process | 過程・進行 |
| Decision | 判断・意思決定 |
| Program | 計画・手順 |
| Chart | 図 |

計画を進める中で起こり得る問題を予測し、代替手順や対応策を用意します。

```text
テストを実施する
├─ 合格 → リリースへ
└─ 不合格 → 原因を調査 → 修正・再テスト
```

**アローダイアグラム法は作業の順序、PDPC法は途中の問題と対応策**に注目します。問題と代替経路を整理する具体例は、[PDPCの使い方](/fe/pdpc/)で確認できます。

### 7. マトリックスデータ解析法：数値を分析する

複数の評価項目について集めた**数値データ**を統計的に分析し、特徴や傾向をつかみます。代表的な考え方に主成分分析があります。

「行と列で関係を示す」マトリックス図法に対し、こちらは**数値データを分析して特徴を抽出する**ことが中心です。

## 科目Aでどう出る？

「連関図法を説明したものはどれか」という問題では、選択肢の中の動詞と対象に注目します。

| 選択肢の説明 | 判断 |
|---|---|
| 事態の進展に伴う問題を想定し、対応策を検討 | PDPC法 |
| 集めた情報を関連によってグループ化 | 親和図法 |
| 複雑な要因の絡み合う事象の因果関係を明らかにする | **連関図法** |
| 目的・目標に向けて手段を順次展開 | 系統図法 |

ここでのひっかけは「関連」という言葉です。**関連する情報をまとめる**なら親和図法、**因果関係をたどる**なら連関図法です。

7手法を見分けるときは、次の順番で考えます。

1. **数値の統計分析か？** → マトリックスデータ解析法
2. **作業順序・日程か？** → アローダイアグラム法
3. **不測の事態への備えか？** → PDPC法
4. **項目群を縦横に並べるか？** → マトリックス図法
5. **目的から手段へ分解するか？** → 系統図法
6. **原因と結果を結ぶか？** → 連関図法
7. **似た情報をまとめるか？** → 親和図法

## どんな場面で使う？

新QC七つ道具は、業務改善で集めた情報を整理し、原因や対策、作業計画を考えるときに役立ちます。

例えば、処理が遅い原因を考えるなら連関図法、改善策を具体化するなら系統図法、作業順序を整理するならアローダイアグラム法というように、**何を解決したいか**で選びます。

## よくある誤解・混同

### 親和図法と連関図法

- 親和図法：似ている意見を**同じグループにする**
- 連関図法：原因と結果を**矢印でつなぐ**

### 系統図法とPDPC法

- 系統図法：目標を達成するための**手段を細分化する**
- PDPC法：途中で起こる**問題と対策を予測する**

### アローダイアグラム法とPDPC法

- アローダイアグラム法：**作業の順序・所要時間**
- PDPC法：**不測の事態・代替策**

### マトリックス図法とマトリックスデータ解析法

- マトリックス図法：項目同士の**関係を表にする**
- マトリックスデータ解析法：**数値を統計的に分析する**

### 特性要因図は新QC七つ道具？

**特性要因図（魚の骨図）は、従来のQC七つ道具に含まれる手法**です。新QC七つ道具の連関図法と同じものではありません。

特性要因図は、ある結果に対する原因候補を大きな枝に整理します。連関図法は、複数の要因が相互に影響する関係まで表します。

## まとめ（試験直前用）

- **情報をまとめる**＝親和図法、**原因をつなぐ**＝連関図法、**手段を展開する**＝系統図法
- **対応を表にする**＝マトリックス図法、**数値を分析する**＝マトリックスデータ解析法
- **作業順序を決める**＝アローダイアグラム法、**途中の問題に備える**＝PDPC法

> **「何を整理するのか」を先に読むと、7手法を切り分けやすくなります。**
