## まず結論

**アサーションチェック（assertion check）**は、プログラムの途中に「この時点では必ず成立するはず」という論理条件を埋め込み、実行時にその条件が成り立つか確認する方法です。

科目Aでは **「実行中」「論理式を埋め込む」「条件の成立を確認」→ アサーションチェック** と判断します。

## 直感的な説明

例えば、商品の在庫数を更新する処理を考えます。出庫後の在庫数は、通常は0以上になる設計だとします。

~~~text
在庫数 10、出庫数 3
       ↓
残り = 10 - 3 = 7
       ↓
「残り >= 0」？ → 成立 → 続行

在庫数 10、出庫数 12
       ↓
残り = 10 - 12 = -2
       ↓
「残り >= 0」？ → 不成立 → 異常を発見
~~~

**結果を記録するだけでなく、期待する条件が成立しているかをその場で判定する**のが特徴です。

## 定義・仕組み

アサーション（assertion）は「表明・断言」という意味です。プログラムの特定箇所で成り立つはずの条件（不変条件など）を論理式で書き、条件が偽になれば問題を検出します。

Pythonでは `assert` 文で体験できます。

```python
stock = 10
shipped = 3
remaining = stock - shipped

assert remaining >= 0, "在庫がマイナスです"
print(remaining)  # 7
```

`shipped = 12` に変更すると、`remaining` は `-2` となり、`AssertionError` が発生します。

| 入力した出庫数 | 計算した残数 | `remaining >= 0` | 結果 |
|---:|---:|---|---|
| 3 | 7 | 真（True） | 続行 |
| 10 | 0 | 真（True） | 続行 |
| 12 | -2 | 偽（False） | エラーを検出 |

見るポイント：**同じ論理式でも、変数の値によって真・偽が変わる**ことです。これは例示用の簡単な計算であり、実際の在庫管理では出庫前の入力検証も必要です。

> 注意：Pythonの`assert`は開発中の前提条件の確認に向きます。最適化オプション（`-O`）で無効化されるため、ユーザー入力の検証やセキュリティ上必須のチェックには使いません。その場合は`if`文と例外処理などを使います。

## 科目Aでどう出る？

用語の違いは「**何を確認したいか**」で切り分けます。

| 手法 | 確認する対象 | 問題文の目印 |
|---|---|---|
| **アサーションチェック** | その時点で条件が成立するか | 論理式を埋め込む、条件の成立 |
| コード追跡（トレース） | 命令の実行順序や変数の変化 | 実行経路、順序を追う |
| スナップショットダンプ | ある時点のメモリやレジスタの状態 | 状態を出力・保存 |
| テストカバレージ分析 | テストで命令や分岐をどこまで通ったか | 網羅率、実行割合 |

「実行中」という言葉だけではアサーションとトレースを区別できません。**条件を判定するのか、経過を追うのか**まで読み取ります。

テスト支援ツール全体の分類は[テスト支援ツール](/fe/test-support-tools/)、網羅率の考え方は[ホワイトボックステストの網羅基準](/fe/white-box-test-coverage/)で確認できます。

## 科目Bでどう使う？

科目Bのプログラム読解では、途中の変数について「ここではどんな条件が成立するはずか」を意識すると、処理の誤りに気づきやすくなります。

例えば、配列の添字 `i` が `0` から `n - 1` の範囲に収まる必要があるなら、確認したい条件は `0 <= i < n` です。

~~~text
n = 5、i = 4 → 0 <= 4 < 5 → 真
n = 5、i = 5 → 0 <= 5 < 5 → 偽
~~~

**配列にアクセスする直前の添字の値**をトレースして、この条件が成立するか調べれば、範囲外アクセスにつながる誤りを発見する手がかりになります。これはアサーションの考え方を応用した読解であり、試験の疑似言語に `assert` 命令があるという意味ではありません。

## よくある誤解・混同

### アサーションチェックは値を表示するだけ？

違います。変数の値を表示することと、**期待する条件を真・偽で判定すること**は別です。

### アサーションが通ればプログラム全体が正しい？

いいえ。アサーションで検査した条件が、その実行時点で成立したと分かるだけです。未実行の経路や、書かれていない条件まで保証するものではありません。

### アサーションと入力チェックは同じ？

用途が違います。アサーションは主に「プログラム内部で成立するはずの前提」を確認するものです。外部から来る不正な入力は、通常の条件分岐と例外処理で扱います。

### テストカバレージが100%ならアサーションは不要？

いいえ。カバレージは**どこを通ったか**、アサーションは**そこで条件が成立したか**を見るため、確認する対象が異なります。

## まとめ（試験直前用）

- **論理式を埋め込み、実行時に成立を確認 → アサーションチェック**
- **実行の順序や値の変化を追う → コード追跡**
- **ある時点の内部状態を出力 → スナップショットダンプ**
- **テストの網羅度を測る → テストカバレージ分析**
- Pythonの`assert`は開発時の前提確認に使い、必須の入力検証には使わない。
