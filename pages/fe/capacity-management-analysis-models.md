## まず結論

キャパシティ管理では、将来必要になるシステム資源やサービス能力を考えるために、現在・過去のデータを分析したり、モデルを使って予測したりします。

基本情報技術者試験では、**何を材料にして予測・評価するのか**を見ると切り分けやすくなります。

| 手掛かり | 疑う方法 |
|---|---|
| 過去の利用実績・時系列・推移 | 傾向分析 |
| 待ち行列理論などの数学的手法 | 数値解析モデル |
| トランザクションなどを模擬的に発生 | シミュレーションモデル |
| 現在の性能を反映した比較の基準 | ベースラインモデル |

試験直前は、次の対応を思い出します。

```text
過去を見る → 傾向分析
数式で解く → 数値解析
模擬的に動かす → シミュレーション
現在を基準にする → ベースライン
```

## 直感的な説明

例えば、サーバのCPU使用率が毎月増えているとします。

```text
4月  50%
5月  55%
6月  61%
7月  67%
        ↓
このまま増えると？
```

このように、**時間とともにどう変化しているか**を見て将来を予測するのが傾向分析です。

一方、同じ将来予測でも方法は一つではありません。

```text
過去のグラフを延長する
→ 傾向分析

数式・理論で求める
→ 数値解析モデル

仮想的に処理を発生させる
→ シミュレーションモデル

現在の状態を再現して比較基準にする
→ ベースラインモデル
```

「将来を予測する」という目的だけを見るのではなく、**どうやって調べるか**を見ることがポイントです。

## 定義・仕組み

### 傾向分析

傾向分析（トレンド分析）は、資源の使用状況やサービスのパフォーマンスなどを継続して記録し、その推移から将来の変化を予測する考え方です。

```text
過去
↓
時系列データ
↓
増加・減少の傾向を確認
↓
将来を予測
```

「時系列」「推移」「利用実績の変化」という表現が強い手掛かりです。

### 数値解析モデル

数値解析モデルでは、待ち行列理論などの数学的なモデルを使って、応答時間やスループットなどを評価・予測します。

```text
入力条件
↓
数式・数学モデル
↓
応答時間・スループットなどを予測
```

試験では、**待ち行列理論・数学的技法**という表現が出たら、傾向分析ではなく数値解析モデルを疑います。

### シミュレーションモデル

シミュレーションモデルでは、実際のシステムをそのまま動かす代わりに、処理やトランザクションの発生を模擬して性能を調べます。

```text
仮想的に
トランザクションを発生
↓
システムの動きを再現
↓
応答時間・スループットなどを評価
```

「模擬的に発生」「動きを再現」という表現が判断材料です。

### ベースラインモデル

ベースラインは、現在のシステムやサービスの性能を把握し、今後の変更や予測結果を比較するための**基準**として使います。

```text
現在の状態
↓
性能を把握
↓
比較の基準
```

ここでは「将来へ伸ばす」より、**現在を基準として押さえる**イメージが重要です。

## 科目Aでどう出る？

問題文に「キャパシティ管理」「将来予測」と書かれていても、それだけで傾向分析とは決まりません。

次に、**予測・評価の方法**を確認します。

```text
利用状況を時系列で把握
→ 傾向分析

待ち行列理論を利用
→ 数値解析モデル

トランザクションを模擬的に発生
→ シミュレーションモデル

現在のパフォーマンスを反映
→ ベースラインモデル
```

特に「将来」という言葉だけで選ばず、その前後にある動詞を見ると判断しやすくなります。

| 問題文の動き | 判断 |
|---|---|
| 推移を分析する | 傾向分析 |
| 数学的に計算する | 数値解析 |
| 模擬する | シミュレーション |
| 現状を再現・基準化する | ベースライン |

## どんな場面で使う？

例えば、アクセス数が増えているWebサービスで、半年後に現在のサーバ能力で足りるかを検討するとします。

過去のCPU使用率やアクセス数の増加傾向から予測するなら、傾向分析が使えます。

より複雑な条件を数学モデルで評価するなら数値解析、実際に近い処理を模擬して挙動を見るならシミュレーションというように、目的や利用できる情報によって方法を使い分けます。

ベースラインは、変更前後を比較したりモデルの基準となる現在の性能を把握したりするときに役立ちます。

FEでは実際に高度なモデルを構築する方法まで覚えるより、**各方法が何を使って評価するのか**を判断できれば十分です。

## よくある誤解・混同

### 将来を予測するなら全部「傾向分析」？

違います。

傾向分析の決め手は、**過去の時系列データの推移**です。

```text
将来予測
＋
過去の推移
→ 傾向分析

将来予測
＋
数式
→ 数値解析

将来予測
＋
模擬実行
→ シミュレーション
```

### 待ち行列理論はシミュレーション？

試験では分けて考えます。

待ち行列理論などを使って数学的に評価する説明なら**数値解析モデル**です。

一方、トランザクションを仮想的に発生させ、動作を再現する説明なら**シミュレーションモデル**です。

### ベースラインは将来の傾向そのもの？

違います。

ベースラインは、比較の出発点となる現在の状態・性能を表す基準です。

```text
時間方向の変化を見る
→ 傾向

現在を基準として押さえる
→ ベースライン
```

この2つは特に混同しやすいので、「時間」と「基準」で切り分けます。

### キャパシティ管理はサーバ容量だけを見る？

容量だけではありません。

CPU、メモリ、ネットワーク、ストレージなどの資源だけでなく、サービスが必要な性能を満たせるかという視点も含めて考えます。

試験では「容量」という日本語だけに引っ張られず、**能力・性能・需要とのバランスを管理する**ものとして捉えます。

## まとめ（試験直前用）

- **過去の時系列・推移 → 傾向分析**
- **待ち行列理論・数学的技法 → 数値解析モデル**
- **模擬的にトランザクションを発生 → シミュレーションモデル**
- **現在の性能・比較の基準 → ベースラインモデル**
- 「将来予測」という言葉だけでは決めず、**何を使って予測するか**を見る
- 傾向とベースラインは、**時間方向を見るか、現在を基準にするか**で切り分ける

試験直前は、次の4語で思い出してください。

```text
推移 → 傾向
数式 → 数値解析
模擬 → シミュレーション
基準 → ベースライン
```
